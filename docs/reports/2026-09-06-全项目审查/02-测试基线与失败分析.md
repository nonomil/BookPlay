## 2. 五项失败的处理方式

### B01：Minecraft 合集数合同

`prj/tests/test_minecraft_collections.py:16` 预期 count=1，实际 count=5。**不能仅据此判定产品显示错误**，更可能是当前分辑扩展未同步测试。对照 catalog、collections 和当前 map/storybook-route 消费：每个已发布 book 恰好归属一个合集，顺序/解锁/链接有效；明确最终合同后改 fixture 与断言。不得直接把所有数量断言替换成“>0”。任务 T06。

### B02：Mikey & JJ 新题没有齐备音频索引

`prj/tests/test_storybook_quiz_audio.py:32` records 集合缺少 fill/listen 等新增 qid。需生成“题 ID→题型→英文题干→中文题干→选项→音频路径→存在/大小”的缺项清单，确认题型真正需要的声音，不要求无需口播的纯 UI 字段也生成语音。补索引/媒体或从 published 集合撤下尚未完成内容。飞行模式全量已发布题目不得依赖桌面在线 TTS。任务 T06。

### B03：固定题数滞后

`prj/tests/test_storybook_quiz_migration.py:45` 预期 5，实际 9；此测试中 validate_book 已通过，本次全 15 本112题的 evidence validator 也为零问题。将“每书固定 5 题”改为经确认的发布清单合同及 ID 唯一、答案合法、证据可定位、不重复题意等断言。题目教学质量仍需按新增/修改题抽样人工核对，不能用 schema 通过替代。任务 T06。

### B04：wala 体积超预算

`prj/tests/test_wala_modules.py:170` `<105000 B`，实际108773 B。保留守卫，优先提取实际职责；若确需调整预算，必须附新增能力、加载时间测量和替代预算，不能只放宽数字让测试变绿。T01 负责登记，T08 负责处理；其他修复可先用已知失败对照推进，但发布前必须关闭。

### B05：角色清单扩充

`prj/tools/test_pack_companion_datapack.py:80` 预期角色集合与生成 manifest 不一致，多 woodcutter、temple-student、heaven-captain、generic-monkey、gibbon。核对这些角色是否已被关卡/播放器引用；已发布角色必须有方向帧、正确画布和可打包路径；未发布项保留在生成工作区，不强行塞入 APK。任务 T06。

## 3. 三组快速复现

### Range

审查探针自行开临时 HTTP server，写100个字节。`bytes=-10` 应为206/90–99/10字节，实际206/0–10/11字节。优化后应转成正式 Python/Java 回归测试；审查探针只记录值，不承担门禁断言。

### 录音

真实 `dub-store.create({indexedDB:null})` → putClip → deleteClip → getClip。实际 delete 返回ok=true，remaining=1。修复后应 remaining=0、getClip=null、listKeys=[]，重复删除仍ok。

### 门禁

用 `gate_probe.cjs` 执行真实 `content-gate.js`，注入与生成器完整 starter 相同的 available 对象。西游记1未拦，2拦；MC1/Mikey1也拦。后续正式用例需要生成器实际输出作为 gate 输入，不只手写重复 fixture。

## 4. 不能从这些测试推出的结论

- 339 个 Node 通过不意味着339条用户端到端路径通过。
- 108本旧绘本校验不覆盖15本多系列的新题音频。
- SHA-256 在打包端存在不代表 Android 导入端已校验。
- 磁盘 public/engine 有39个测试文件不代表本次对最终 APK 做过解包统计。
- Android Template 测试存在不等于 Range/SAF/权限测过。
- 对历史报告的数值校正不抹去历史完成记录；以日期与适用范围区分。

## 5. 推荐后续测试分层

源码层应使用仓库内小 fixture、注入 I/O 和固定依赖；内容层依赖恢复好的明确版本素材；Web E2E 使用真实 HTTP/浏览器/隔离存档；Android 测原生服务与真机权限/数据源；发布层对成品解包、路径闭包与 sha256。每层输出单独状态；环境缺失标 BLOCKED/NOT_RUN，不能当 PASS。
