# 豆豆龙英语题型与口语评测方案

> 调研日期：2026-09-01  
> 范围：`prj/engine` 当前实现、`G:/StudyCode/blocklegend` 语音实现、公开官方文档。  
> 状态：方案与证据整理，未改运行时代码，未把语音评分作为解锁门槛。

## 结论先行

1. **可以让孩子发音并判断是否命中目标词/句子。** 这是 ASR（语音转文字）能力，适合做“跟读闯关”的第一版。
2. **ASR 命中不等于发音准确。** 只有带发音评测的声学模型，才会返回准确度、完整度、流利度，以及可选的音节/音素分数。第一版不应把“识别到文字”包装成“发音正确”。
3. **当前项目还没有麦克风链路。** 已有的是 Edge-TTS/浏览器 `speechSynthesis` 和音频播放；`lesson.html`、`drill.html` 没有 `SpeechRecognition`、`MediaRecorder` 或 `getUserMedia`。
4. **`blocklegend` 的降级思想值得复用，评分逻辑不应直接照搬。** 它有语音状态 HUD、网关 STT、无麦克风时四选一/打字回退；但核心仍是文本匹配，且存在别名/编辑距离导致的误命中风险。
5. **推荐路线：先做“可选跟读 + 可解释反馈”，再接真正的发音评测。** 跟读不能阻塞无麦克风用户，也不应在未做儿童样本校准前决定每辑是否解锁。

### 2.2 与本项目的页面节奏

坚持“一集看完后出现一次知识巩固页”，不要每个字幕后弹题。每集巩固建议：

- 一二年级：3–5 题，最多 1 个可选单词跟读；
- 三四年级：5–9 题，1 个单词跟读 + 1 个短句跟读；

- 语音题是练习卡中的一个可跳过模块，不打断故事播放；
- 只有在用户主动点“开始跟读”时申请麦克风权限。

## 3. ASR 与真正发音评测的边界

### 3.1 两种能力不是一回事

**ASR 文本命中**回答：“系统识别到的文字是否包含目标词/句子？”例如目标是 `tree`，识别文本是 `tree`，就可以给“听到了目标词”。它不能证明声学上的 /t/、/r/、/iː/ 都正确。

**Pronunciation Assessment**回答：“录音的声学特征与参考文本的读法有多接近？”它可以在有参考文本时输出词、音节或音素层面的结果。识别器可能把错误发音“猜”成正确单词，所以不能用一次 ASR 命中替代发音评分。

### 3.2 官方能力核实

- [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)：浏览器接口目前不是 Baseline；页面说明部分实现使用服务器识别，离线不可用；`processLocally`、`phrases` 等能力仍带实验性/实现差异。适合原型和可用时的加分路径，不适合作为 APK 唯一引擎。
- [MDN MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)：可从 `MediaStream` 录制音频，并用 `isTypeSupported()` 检查容器/MIME；适合在 WebView 采集短录音，但仍需处理权限、格式和编码。
- [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)：麦克风需要用户授权；不安全上下文、权限拒绝、无设备、设备占用等都会导致不同异常，页面必须提供可用回退。
- [Android SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer)：需要 `RECORD_AUDIO`；官方明确提示实现很可能把音频流到远端，且不适合持续识别；API 也提供 `isOnDeviceRecognitionAvailable()`/`createOnDeviceSpeechRecognizer()`，但是否可用取决于设备服务。它给的是识别结果和置信度，不是发音音素分数。
- [Azure Pronunciation Assessment](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment)：可按 `FullText`、`Word`、`Syllable`、`Phoneme` 粒度返回；支持 `AccuracyScore`、`FluencyScore`、`CompletenessScore`，`en-US` 还可选 `ProsodyScore`。需要参考文本；这是声学发音评测，不是单纯 ASR。
- [腾讯云口语评测（新版）](https://cloud.tencent.com/product/oen)：官方产品页声明覆盖儿童到成人，支持字词、句子、段落、自由说，以及准确度（GOP）、流利度、完整度等维度，并提供儿童差异化评测能力。页面的“专家拟合度 95%+”属于厂商宣传，应以本项目真实样本复核。
- [科大讯飞 ISE 产品页](https://www.xfyun.cn/services/ise) 与 [ISE API 文档](https://www.xfyun.cn/doc/Ise/IseAPI.html)：官方列出 `read_word`、`read_sentence`、`read_chapter`、`simple_expression`、`read_choice`、`topic`、`retell`、`picture_talk`、`oral_translation` 等模式；可返回准确、流利、完整、声韵/音素等结果，并有 `junior/middle/senior` 年级参数。API 文档还要求英语音频按 16 kHz、单声道等合同传输，WebM/Opus 不能未经转换直接假设兼容。
- [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)：官方仓库声明支持无网络的 ASR、Android、WebAssembly 等平台。它是离线识别路线，不等同于完整的发音评测；模型体积、内存和准确率需单独实测。

## 4. `blocklegend` 语音实现复盘

### 4.1 可复用的部分

对应文件：

- [game.js](G:/StudyCode/blocklegend/game.js)：按环境选择 Web Speech、Capacitor SpeechRecognition 或网关 STT；网关分支用 `getUserMedia` + `MediaRecorder` 录制约 2.5 秒；识别失败后仍可四选一/打字。
- [data/speech-hud.js](G:/StudyCode/blocklegend/data/speech-hud.js)：把 `idle/listening/processing/matched/not-matched/mic-blocked/unsupported` 变成儿童可理解的一行反馈；连续失败两次才建议拼写。
- [data/speech-input.js](G:/StudyCode/blocklegend/data/speech-input.js)：做文本归一化、英文分词、同义/识别别名、短词严格匹配和长词编辑距离匹配。
- [shared/speech-match.js](G:/StudyCode/blocklegend/shared/speech-match.js)：按词元、词形还原和 LCS 覆盖率给句子文本评分，并返回命中的文本片段，适合做“内容完整度”的展示层。
- [tools/buddy-proxy.mjs](G:/StudyCode/blocklegend/tools/buddy-proxy.mjs)：`POST /v1/stt` 将短音频交给本机 Whisper 类进程，只返回文本，临时处理，不把录音写入进度。

### 4.2 为什么它只能算“基础版”

1. `/v1/stt` 返回 `{text}`，没有准确度、流利度、完整度或音素结果，所以不能给“发音 85 分”。
2. `speech-input.js` 中有 `tree → three/tee/free` 等别名，适合提高“能过关”的容错，但会把真实发音混淆隐藏，不适合直接作为发音正确判定。
3. 长词编辑距离 1、句子内容词命中会让“识别到部分文本”较容易通过；对本项目的跟读句，应该区分“内容命中”和“完整朗读”。
4. 网关链路依赖网络/局域网，固定 2.5 秒录音，没有针对儿童停顿、噪声和回声的独立校准；WebM 音频格式也需要服务端明确转码合同。
5. 代码虽不持久化录音，但网关路径仍然会把音频从浏览器发送到服务端；“不保存”不等于“不上传”，儿童隐私提示必须写清楚。

可借鉴的是**状态机、降级和不阻塞主游戏**；不能直接复用的是**别名即正确、模糊命中即通过**的评分语义。

## 5. 推荐技术方案

### 5.1 供应商无关的 VoicePort

不要在 `lesson.js` 里直接写某一家 SDK，新增一个小的语音端口（名称可定为 `voice.js`）：

```js
VoicePort.capabilities() // { mic, asr, pronunciation, offline }
VoicePort.listen({ referenceText, mode, gradeBand, maxMs })
// -> { kind, transcript, accepted, scores?, words?, provider, latencyMs }
VoicePort.stop()
```

页面只消费统一结果；实现层可切换：

1. **开发/演示：** Web Speech 或 Android 系统识别，只有文本命中；
2. **国内试点：** Android/WebView 录音 → 本地/局域网网关 → 腾讯云 OEN 或讯飞 ISE；
3. **离线候选：** sherpa-onnx 只做 ASR 回退，不宣称音素评分；
4. **可选国际基准：** Azure Pronunciation Assessment 作为真正声学评测适配器。

所有云端密钥放网关环境变量，不能放 APK、HTML、Git 或 `localStorage`。

### 5.2 统一结果合同

```json
{
  "questionId": "ep001-read-word-001",
  "mode": "read_word",
  "referenceText": "monkey",
  "provider": "tencent_oen",
  "kind": "partial",
  "transcript": "monkey",
  "accepted": true,
  "scores": {
    "overall": 78,
    "accuracy": 76,
    "fluency": 82,
    "completeness": 100,
    "prosody": null
  },
  "words": [
    {"reference": "monkey", "heard": "monkey", "accuracy": 76, "error": null}
  ],
  "hints": ["开头音再清楚一点"],
  "latencyMs": 2100,
  "audioStored": false
}
```

`kind` 至少区分：`match`、`partial`、`mismatch`、`no-speech`、`permission-denied`、`unsupported`、`network-error`。没有真正的发音分数时，`scores` 必须为空，而不是伪造 0–100 分。

### 5.3 录音和格式合同

- 点击按钮后才申请麦克风；显示录音中动画和“停止”按钮；默认 2–5 秒，使用 VAD 或静音结束，不要无限录音。
- 录音结束立即停止 tracks；不写 `localStorage`，不上传分析日志中的原始音频。
- 网关接收 `webm/opus` 等浏览器格式后，统一转成供应商要求的 16 kHz、单声道 PCM/WAV；格式不兼容要返回明确错误并回退。
- 服务端收到 `questionId/referenceText/gradeBand`，把参考文本传给评测引擎；密钥只存在服务端。
- TV 版默认隐藏跟读入口或显示“需要带麦克风设备”，因为遥控器/电视通常没有可用麦克风；语音不是 TV 通关条件。

### 5.4 儿童反馈，不直接展示技术分数

| 结果 | 孩子看到的文案 | 操作 |
|---|---|---|
| `match` | “说得很清楚！🎉” | 下一题 / 再说一次 |
| `partial` | “听到了，试试把 **monkey** 说完整” | 听示范、慢速、再试 |
| `mismatch` | “我听到：xxx。先听一遍，再试试” | 播放示范、再试、跳过 |
| `no-speech` | “没有听到声音” | 检查麦克风、再试 |
| 权限/不支持 | “麦克风不可用，可以点选或打字完成” | 点选/打字 |
| 网络失败 | “语音服务暂时不可用” | 离线回退 |

技术分数放到家长/学习报告，儿童界面优先显示星级、命中词高亮和下一步动作。不要用“你发音错了”这类绝对表述。

## 6. 分阶段落地

### P0：验证与数据合同（先做）

- 新增语音题型合同：`read_word`、`read_sentence`；明确参考文本、语言、年级、是否可评分。
- 先做失败测试：无麦克风、权限拒绝、空结果、网络超时、回退后仍能完成巩固。
- 用 1 集、3 个词、2 个短句做人工录音矩阵，分别测试浏览器、Android、网关；记录误识别、首字母/短词混淆、延迟和音频格式。
- 验收门：没有麦克风也能完成 `lesson`/`drill`；语音结果不写原始录音；失败不改变解锁逻辑。

### MVP：文本命中型跟读（推荐第一版）

- `lesson.html` 每集最多 1 个单词跟读卡；三四年级以上标准/挑战档再加 1 个短句跟读卡。
- 复用现有 TTS、单词卡和“再学一次”入口；新增“听示范 / 说出来 / 再试一次 / 跳过”。
- Web Speech 只作为可用时的开发通道；正式 Android 优先走网关或原生桥接；结果仅显示“听到了目标词/句子”。
- 通过条件为 `accepted` 或用户选择回退，不以 ASR 命中率决定下一辑解锁。

### V2：接入真正口语评测

- 选择一家国内供应商做网关适配（腾讯云 OEN 或讯飞 ISE），保留第二适配器接口；Azure 作为技术对照，不在客户端直连。
- 单词题使用词级准确度；句子题使用准确度/完整度/流利度；音素错误只转成 1 个可操作提示，不把 IPA 堆给孩子。
- 按 `g1_2/g3_4/g5_6` 建立阈值配置，但先用真实儿童样本校准；建议初始只给反馈，不硬性卡通关。
- 家长报告显示趋势（本周开口次数、完整度带、待复习词），不保存原始音频。

### V3：离线和开放式输出

- sherpa-onnx Android/WASM 做无网 ASR 回退；先测模型大小、启动耗时、低端 Android 内存和中英混说误识别。
- 五六年级挑战档增加“看图说一说/复述”与段落跟读；开放式内容只做鼓励性反馈，不作为唯一正确答案。
- 只有在离线声学评测模型经过儿童样本验证后，才考虑离线发音质量分数。

## 7. 分级与数据改造建议

当前 5,975 张卡片全部覆盖三个年级且只有难度 1/2，建议逐批补充，不要一次自动改完：

```json
{
  "type": "read_sentence",
  "stage": "episode_complete",
  "difficulty": 3,
  "grade_bands": ["g3_4", "g5_6"],
  "skills": ["speaking", "fluency"],
  "prompt": {"en": "Read the sentence aloud.", "zh": "跟读这句话"},
  "payload": {
    "reference_text": "The monkey jumped.",
    "locale": "en-US",
    "audio": "assets/adv_audio/...",
    "provider_modes": ["read_sentence"]
  },
  "review_status": "needs_review"
}
```

分级规则建议：

- 一二年级：短词、图片/三选一、单词跟读；不要求拼写和长句；
- 三四年级：三四选一、句子补全/排序、短句跟读；
- 五六年级：听写、句子跟读、段落/看图表达；
- `light/standard/challenge` 优先调题量，再逐步调题型复杂度；
- 新卡片必须有来源、参考文本、音频、难度和人工/机器审核状态；
- 语音题不应把 `review_status=needs_review` 的内容带入正式评分池。

同时统一 `lesson-core.js` 与 `drill.js` 的设置来源：要么都读取 `bookplay_lesson_settings_v1`，要么明确区分“每集巩固强度”和“整辑学习量”，并在设置页写清楚两者不是同一开关。

## 8. 验收标准

### 功能

- 首次点跟读才申请麦克风；拒绝权限、无设备、无网络、浏览器不支持时都能点选/打字完成；
- 识别结果有 `transcript` 与状态；没有发音评测引擎时不显示虚构分数；
- 单词/句子跟读完成后，返回当前题目，不丢失题目索引、答题状态或“再学一次”回顾位置；
- 一集完成后只出现一次巩固页，跟读失败不会改变下一集/下一辑解锁状态。

### 质量

- 真实儿童样本按三个年级分别测：命中精确率、漏报率、误报率、平均/95 分位延迟；
- 至少覆盖安静环境、电视扬声器回声、多人说话、轻微口音、短词（`a/is/in`）和相似音；
- 供应商分数与人工抽样评价对照后再定阈值；厂商页面的拟合度宣传不直接当作项目验收证据。

### 隐私与发布

- 明确家长同意、录音用途、传输位置、保留时长；
- 默认只保留聚合结果，不保留原始儿童音频；服务端临时文件在响应后删除；
- API key 不进入 APK/HTML/Git/localStorage；HTTPS 或受控局域网；
- 语音链路未通过端到端测试前，不把它列为 APK 发布硬门槛，也不移除无麦克风回退。
