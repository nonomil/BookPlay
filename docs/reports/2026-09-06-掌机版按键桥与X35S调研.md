# 2026-09-06 掌机版（X35S）按键桥与多 flavor 打包

目标设备：泡机堂 X35S 掌机。本文记录设备调研结论、按键桥接入现状、已验证结果、
已知缺口和装机实测用的键码表。引擎源码层以 `prj/engine/` 为准。

## 一、设备结论

| 项目 | 结论 | 影响 |
| --- | --- | --- |
| 芯片 | RK3566（四核 A55 1.8GHz），1GB LPDDR4 | H5 + 音频够用；系统 WebView 版本需实机确认 |
| 屏幕 | 3.5" IPS 640×480（4:3），**无触摸** | 必须纯按键全流程可玩；小屏 UI 适配是主要工作量 |
| 按键 | 十字键、ABXY、L1/R1/L2/R2、左右摇杆、SELECT/START | 覆盖确认/返回/方向/游戏操作 |
| 系统 | 实机为安卓 11 | Capacitor 壳可用 |

按键收不到的机理：无 `.kl` 映射的扫描码在安卓层变成 `keyCode=UNKNOWN(0)` 的事件，
WebView（Chromium）直接丢弃未知键，H5 侧永远不触发 `keydown`。解法是 Activity
`dispatchKeyEvent` 原生拦截后用 `evaluateJavascript` 注入，**不 root、不改系统文件、
只在本 APK 内生效**。具体每个键的 keyCode/scanCode 只能装机实测，外部资料查不到。

## 二、接入现状（两条线合流）

**单包自适应按键桥（口袋 Z 并行会话产出）：**
- `NativeKeyBridge.java`：拦截所有物理键（keyCode + scanCode + action + repeat + source）
  与摇杆轴/HAT，`evaluateJavascript` 注入 `window.BookPlayNativeKey / BookPlayNativeAxis`；
  focus 变化时注入 `BookPlayDeviceProfile`（芯片/机型/屏幕）。
- `prj/engine/native-key.js`：JS 接收器。维护事件队列、`bookplay-native-key` CustomEvent、
  摇杆死区，`suggestHandheld()` 按「rk3566 且短边 ≤800」或「小屏且见过物理键」判定掌机模式。
- `prj/engine/handheld-keys.html`：按键探测页（显示 keyCode/scanCode/轴值/判定结果），
  首页副标题「掌机按键探测」入口。
- `pack_android.py` ENGINE_FILES 已登记两个新文件；`native-key.test.mjs` 7 例单测。

**多 flavor 构建链（本会话补齐）：**
- `android/app/build.gradle`：新增 `handheld` flavor（`applicationIdSuffix .handheld`），
  打开 `buildFeatures.buildConfig`。
- `android/app/src/handheld/AndroidManifest.xml`：固定横屏（640×480 横向）。
- `android/app/src/handheld/res/values/strings.xml`：应用名「豆豆龙英语 · 掌机」。
- `scripts/build-apks.mjs` / `打包APK.bat`：输出 `release/storyhall-handheld-debug.apk`
  （jttw 档 `storyhall-jttw-handheld-debug.apk`），与手机/TV 包共存互不覆盖。

按键桥对所有 flavor 通用（单包自适应路线），flavor 只承担形态差异（横屏、包名、命名），
两条路线叠加不冲突。

## 三、已验证

- `npm test` 344 例全绿（含 native-key 7 例）。
- `gradlew assembleHandheldDebug` 编译通过并产出 APK；APK 内
  `assets/public/engine/{native-key.js,handheld-keys.html,home.html}` 齐全（实际服务目录）。
- 合并 Manifest 确认 `screenOrientation="landscape"`、`package="com.nonomil.storyhall.handheld"`。

## 四、已知缺口（下一阶段）

1. `native-key.js` 的 `KEY_ROLES` 按标准 Android 键码猜测（19–22、96/97/99/100、108/109）。
   X35S 实际键码以下方实测表为准；若实测 keyCode=0（未映射），需用 scanCode 扩展映射。
2. 原生桥只派发 `bookplay-native-key` CustomEvent，页面现有键盘逻辑还听不到：
   `tv-remote.js` 焦点导航与 `game.js` 方向键/Enter/Escape 都监听标准 `keydown`。
   阶段 2 应在桥里合成标准 KeyboardEvent（`key/code` 齐全），并对「系统已认识的键」做
   去重（部分设备同一按键会同时产生 DOM keydown 与桥事件，双倍移动）。
3. `BookPlayDeviceProfile` 只在 Activity focus 变化时注入；页内导航后 JS 上下文重建即丢失，
   `suggestHandheld` 会退回「见过物理键」判定。阶段 2 建议页面 load 后重注入或 localStorage 持久化。
4. BACK 键转发后仍走系统返回；阶段 2 给页面 Escape 语义时避免与系统返回互相打架（被困/双退）。
5. 640×480 UI 适配是阶段 3 主要工作量：`tv.css` 的 TV 门槛 `min-width:1000px` 不会命中，
   建议由 `suggestHandheld` 置 `html[data-handheld]` 后走专用小屏样式（首页/书架/故事页/大地图优先）。
6. 打包卫生（既有问题，非本次引入）：`prepare-mobile.mjs` 整目录拷贝导致 41 个
   `*.test.mjs` 进入 APK assets，建议排除。

## 六、构建与安装

- 全量打包（含版本号自增）：`打包APK.bat`（或 `npm run android:build`），
  产出 `release/storyhall-handheld-debug.apk`。
- 只验证掌机包：`cd android && gradlew assembleHandheldDebug`，
  产物 `app/build/outputs/apk/handheld/debug/app-handheld-debug.apk`。
- 安装：`adb install -r app-handheld-debug.apk`；包名 `com.nonomil.storyhall.handheld`，
  可与手机版（`.mobile`）同机共存，便于对照触屏与按键表现。
