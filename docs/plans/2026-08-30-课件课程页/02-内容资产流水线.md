## 2. 分阶段产物

### A. 来源清单

记录 episode、源路径、SHA-256、页数、媒体数、文本层字符数、重复组和版本状态。

### B. 图片提取

主课件是一页一张扁平图，优先直接解包 `ppt/media` 并按 slide relationship 恢复顺序；只有关系不明确时才使用 LibreOffice 渲染。输出 WebP 保持 16:9，最长边建议 1600，禁止放大低清图。

### C. 文字提取

- 主课件：OCR；
- 培训课件：直接读取 `a:t` 文本和 notes；
- 动画截图：只 OCR 底部英文字幕，用于和 node 文本模糊匹配；
- 带标注精读 PDF：直接提取已有文本层，解析中英台词、侧边词汇、IPA、词性/释义和来源页；不得对已有文本层重复 OCR。
- 官方测试题 PDF：直接提取 108 集 540 道题，题面和选项保持原文。
- 课件 PDF：仅作视觉来源，不进入默认 OCR 队列。

OCR provider 必须写入收据。不得在任务中静默安装全局软件或联网上传课件；本地 provider 不可用时返回 blocker。

### D. 页面分类

按稳定标题/视觉结构分类：

```text
cover | journey | warmup | vocabulary | story
grammar | expression | sequencing | vocab_quiz
story_quiz | answer_key | homework | unknown
```

### E. Markdown

`lesson.md` 必须按原页顺序嵌入图片，并在每页下方记录：页型、OCR 文本、结构化候选、来源路径、审核状态。Markdown 是人工复核面，不是运行时消费者。

### F. JSON

只有 `machine_verified` 或 `human_reviewed` 页面可以生成默认运行时卡。课件题由 Answer Key 反向校验；官方测试题必须关联本集台词答案证据。

## 3. 去重

- 两套 108 集主课件 105 集完全重复，只保留一份逻辑来源；
- 第 42、61、97 集生成双版本对比报告，人工选择后写入 source manifest；
- 和现有 `official_words`、`official_quiz`、`puzzles` 做规范化与相似度去重；
- 去重不删除来源证据，只合并运行时展示。

## 4. Git 边界

进入 Git：提取代码、schema、测试、少量合成 fixture、计划文档。

不进入 Git：课件、提取图片、OCR 文本包、lesson JSON/MD、报告、发布数据包。
