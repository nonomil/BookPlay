# 任务 01 · 对时修复：字幕早一幕

## 目标
108 集的 `audio_start/audio_end` 与画面语音对齐。修复后：进入任一句，听到的就是这句、逐词高亮跟得上。

## 背景与证据
- 官方 SRT（data/03）第 i 条的**文字**实际在第 **i+1** 条的时间窗里说出（ep1 实测：cue1 "From the beginning…" 标 11.073–22.248，whisper 听写实际 21.8–26.4；cue1 的时间窗对应片头空镜/章节名）；
- 不能盲目全体 +10s：首条窗长与后续偏移不一致；不确定 108 集是否都有此缺陷 → **逐集判定**。

## 改动文件
- 新建 `demo/tools/fix_audio_shift.py`（只重写 ep*.json 的时间字段，**不得**动 vocab/gloss/quiz 等任何已导入数据；不要用 rebuild_from_official_srt.py 重跑，会把词汇测验全部冲掉）。

## 实施步骤
1. **whisper 缓存**：对每集 `demo/assets/video/epN.mp4` 跑 faster-whisper（`base`，`int8`，`clip_timestamps="0,150"` 只听前 150s；无 VAD），结果存 `demo/data/align/whisper_head/epN.json`（已存在则跳过，支持断点续跑）；
2. **移位判定**：解析该集官方 SRT（注意 UTF-8 BOM），取前 3 条文字，分别按 shift=0（用第 i 条时间窗）与 shift=1（用第 i+1 条时间窗）与 whisper 分段做 token 重叠打分（时间窗内重叠的分段合并后算词交集/并集），取分高者；两者接近（差 < 0.15）记 `ambiguous` 并默认 shift=0，输出到报告人工复核；
3. **重写时间**：shift=1 的集——
   - 对原始 cue 序列先做移位：`cue[i].time = cue[i+1].time`，最后一条的窗 = `[原末条 end, whisper 全文末段 end（若无则 +4s）]`；
   - 再按 `rebuild_from_official_srt.py` 里同样的 `merge_cues` 规则（句末标点/引号配对）分组合并时间窗——**文字与分组不变，只换时间**；
   - 合并后窗序列应与该集 ep*.json 的 narration 节点（跳过 puzzle/choice 节点）一一对应；数量不匹配则该集标 `FAIL` 跳过写入，进报告；
4. **写回**：只更新每个 narration 节点的 `audio_start/audio_end`；
5. **报告**：打印每集 `{ep, shift, score0, score1, nodes, status}` 汇总；`ambiguous/FAIL` 列表单独输出；
6. **抽帧验收**：对 ep 1/2/50/108，各取修复后前 3 句的 `audio_start+0.3s` 抽帧到 `demo/data/align/probe_after_fix/`，逐张人工看画面是否是该句剧情。

## 验收标准
- 108 集报告：shift 判定完成，FAIL=0（有则逐个排查）；
- ep1 浏览器验收：第 1 句进入时画面不再是空镜、语音同句；连续自动播 4 句无错位；
- ep50、ep108 各抽 2 句同验。

## 风险与回滚
- 写回前把 108 个 ep*.json 的 `(node_id, audio_start, audio_end)` 备份到 `demo/data/align/times_backup.json`，出问题一键还原；
- whisper 听写慢：只听前 150s、只为判定移位，全量约 108×(10~20s)，可接受；跑批时输出进度。
