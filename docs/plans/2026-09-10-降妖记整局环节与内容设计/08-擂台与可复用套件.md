# 08 擂台、星露谷/宝可梦映射、可复用套件

> 第一性原理：孩子要的是「在西游世界里逛，然后上台打一场」。  
> 长期复利：资产和算法按合同接入，不按游戏名重写。

## 这件事的意义

不是再做一个星露谷物语，也不是再做一个宝可梦。  
是把两件已经验证的乐趣拆成 **可替换的层**：

| 乐趣 | 星露谷 / 宝可梦里是什么 | 降妖记落在哪 | 为什么能复利 |
|---|---|---|---|
| 世界里走、捡、跟人说话 | 农场/镇子/NPC 日程 | `game.html` 大地图三站 | 换主题图和词，算法不动 |
| 上台、回合、血条、出招 | 宝可梦战斗画面 | `battle.html` 擂台 | 答题=出招；套件按 Boss id 复用 |
| 生图即用 | 手工像素 | Grok 2D 套件 → `sprites.json` / 擂台地板 | 一张 canonical，只 `image_edit` |
| 精细模型 | 3D 角色 | **旁路**，不挡 2D 交付 | 见下 |

禁止：为「更像星露谷」新开种田循环、背包经济、昼夜系统；为「更像宝可梦」上 6v6、属性克制表、换人。那些会把英语复习糖衣做成第二款游戏。

## 三层套件（长期只加皮，不加引擎）

```
1. 世界层  game-core.js     走、捡、扔、门控
2. 擂台层  battle-core.js   判定、连击、护体、套件出招
3. 资产层  sprites / kits / generated/<主题>
```

新玩法 = 新 **数据**（词、图、kit id），不是新 JS 页。

## Grok 游戏套件怎么用（本仓库）

来源：`G:\AI编程--项目模板\美术和游戏设计\游戏开发\`

| 要什么 | skill | 接入点 |
|---|---|---|
| 角色立绘/四向 | `game-character-consistency` | `content/game/sprites.json` 已有 gif 槽 |
| 出招/受击帧 | `game-animation-frames` | `boss-kits.json` 的 `fx` |
| 擂台地板/场景 | Imagine 场景图（可有地面） | `.battle-arena-floor` 背景 |
| 按钮/血条框 | `game-ui-icons`（无烧字） | CSS 先顶上，图后换皮 |
| 透明 PNG | `transparent-image-generator` | 精灵；背景用 JPEG 即可 |

合同（与 09-08 `08-美术` 一致）：

- 精灵：单色可抠底、无场景、无铸字
- 同角色只 `image_edit` 链，禁止整套重 `image_gen`
- 目录：`content/assets/generated/<主题>/` + 短 manifest
- **2D 先交付。** `img2threejs` 可把同一张 canonical 做成旁路 GLB，不进 `game.html`/`battle.html` 主循环，直到有独立 3D 页。

## 生图 / 现成模型怎么「直接接入」

1. 人物：已有悟空/Boss GIF **直接用**（本擂台就是这样）。  
2. 新立绘：透明 PNG/GIF → 填 `sprites.json` 的 id → 关卡 `cast` 引用同一 id。  
3. 擂台地板：一张 16:9 空场地 JPEG → CSS `url(...)`，人物 DOM 叠在椭圆上。  
4. 算法：`resolveBossKit(bossId)` 已按 id 取招；换皮不改判定。

缺特效 PNG 时：闪光 + 技能名，不报错、不挡打。

## 玩法多样（仍是一套状态机）

擂台上的多样性来自 **题型轮换** 和 **Boss 套件**，不是来自多种小游戏引擎：

- 点选中英 / 听音 / 跟打 / 官方题（P1）
- 每 Boss 攻/必杀/防名称不同
- 大地图仍负责「多样空间」：捡、走、NPC
