## 2. 精灵规格（与既有四向资产对齐）

- **每方向一张 8 格 4×2 图**，格子 384×512：第 1 行 = 走路 4 帧（contact / left-forward / passing / right-forward），第 2 行 = 持械/施法动作 4 帧；四方向 = south / west / east / north 四张。
- 用户要求（2026-09-05 更新）：也可以**一张 4 行 × 8 列**（行=方向，列=前 4 走路后 4 动作）出图再拆格；小角色体积小，4×8 在 1536×1024 下每格 192×256 可接受。**大角色沿用每方向 4×2 高清规格，小角色用 4×8 单张**。
- **生成时直接在提示词里指定透明背景（transparent background），不要绿色/纯色底**；若 provider 返回不透明图，再用 `transparent-image-generator` 的 chroma/背景去除后处理（不再用"绿幕 staging → chroma key"的老路径）。
- 质检：alpha 报告（非透明像素占比、边缘羽化）、格子完整性（每格非空）、按语义重命名（`<id>-south-walk-01.png` … `<id>-south-act-04.png`）。

## 4. 文件夹布局（按集数分类，用户要求）

```
assets/generated/jttw-game-sprites/
  c01/
    ep01/monkey-minor/{source/,2d/,transparent/,manifest.json}
    ep03/subodhi-disciple/…
    ep05/chaosdemon-minion/…
    ep06/dragonking-soldier/…
    ep07/underworld-clerk/…
    shared/imp/…            # 跨集兜底小妖放 shared
  manifest.json             # 章级汇总（角色→帧路径→sha256）

```

大角色不搬家（留在 `jttw-player-walkers/`），游戏运行时用一张**游戏精灵注册表** `content/game/sprites.json` 把 id → 帧路径（含大角色与小角色）统一映射，关卡 JSON 里只写 id。

## 5. 地图背景与道具图标

- **战斗背景 P0（零生成）**：`theme` → 该集 `adv_frames` 首帧放大模糊 + 底部压暗渐变；命中不了就 `collections/normalized/c01.jpg`。
- **战斗背景 P1（T5 内一起生成，6-8 张主题）**：花果山 / 水帘洞 / 三星洞 / 水脏洞 / 龙宫 / 幽冥界（1536×1024，横版，中景留空给战斗 UI，同一卡通渲染风格）。生成后压 1280×720 JPG 进数据包。
- **道具图标（P1）**：3×3 sheet 一张——蟠桃 / 芭蕉扇 / 紫金葫芦 / 袈裟护盾 / 金箍棒 / 星星 / 金币 / 木鱼 / 妖怪卡框，拆格后进 `jttw-game-sprites/shared/items/`。

## 6. 并发生成与批次（子代理可并行）

- 批次 A：6 个小角色 × 1 张 4×8 = 6 次生成（可 3 个子代理并行，每个负责 2 角色）。
- 批次 B：6 张主题背景（并行 2-3 代理）。
- 批次 C：1 张道具 3×3 sheet。
- 每个子代理的提示词 = `prompts/04-资产生成-c01小角色.md` + 分派的角色 id 列表；要求子代理遵守 gpt-image-pipeline 的目录/manifest/质检合同，**禁止**把 API key 写进任何文件。
- 失败重试：单格缺失/合并不拆——按 skill 规则改小批量或单图重试，不猜格。

## 7. 验收

- `assets/generated/jttw-game-sprites/manifest.json` 列全 6 小角色 + 帧 sha256；`review.md` 记录 alpha 报告结论。
- 抽查每角色四方向各 1 帧贴到深色/浅色两底色上无白边绿边。
- `content/game/sprites.json` 注册表能解析全部 id（T2 core 测试覆盖注册表加载）。
