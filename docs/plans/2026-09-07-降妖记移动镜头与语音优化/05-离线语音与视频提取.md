# 离线语音与视频提取

## 1. 来源策略

按内容选择来源，而不是把所有声音重新生成一次。

| 声音用途 | 优先来源 | 不足时如何处理 |
|---|---|---|
| 小怪英文词、正确命中朗读 | 现有分集词音频 / en_index | 检查其它已发布静态词音频，再为确实缺的词预生成 |
| 中文词球、简短释义 | 现有 zh_index | 新 shortZh 与旧解释不一致时补静态中文音频 |
| NPC 引用本集原文 | 已审核的原视频 / 原音轨句片段 | 未完成原声审核前使用现有同文本静态句音频 |
| 新编操作引导、NPC 接话、Boss 嘲讽 | 预生成中英配音 | 不在原视频中的话不能声称是视频提取 |
| 战斗 / 拾取 / 奖励音效 | 现有 BookPlayAudio 音效 | 调音量与触发时机，和语音区分 |

原视频通常含背景音乐和音效。切出音轨不会自动得到“干净人声”。P0 使用听得清的整句原音片段；暂不做耗时的人声分离。单词连读难以干净切分时继续使用现有独立词读音。

## 3. 原声提取流程

1. **列需求**：从最终关卡与对白收集每个需要朗读的 stable ID、文本、语言、speaker、用途。先定文案再生成，避免音频和题目不同步。
2. **映射原文节点**：优先使用 sourceNodeId，与 `dialogue_stories` 中节点逐项对应；文本全文相同只是候选，不能仅凭关键词近似命中。
3. **记录确切来源**：原视频或整集 MP3 的路径、SHA256、时长、音轨编号、时间基准。MP4 与 MP3 时间线可能有片头差异，禁止混用时间戳。
4. **审定时间窗**：现有 audio_start / audio_end 作为候选；每句听开头、末尾和说话者，必要时修订。ASR / forced alignment 只能辅助，不以均分时长伪造边界。
5. **提取**：用锁定的 ffmpeg 从正确来源切出独立句音频，保留约 60–120ms 安全余量作为调校起点；旁边说话 / 片头音乐不能硬塞进去。
6. **解码和试听**：ffprobe 检查时长，ffmpeg 解码检查损坏；逐条人工或可回放证据听辨文本、截断、相邻句、音量。原声候选未通过就保留 pending 状态。
7. **发布**：只将 approved 项写入运行时索引。源视频保持原样，所有切片可按 manifest 重现。

FFmpeg 命令形状（拟新增构建脚本负责传 argv；下面不是本轮已执行记录）：

```powershell
& $ffmpeg -nostdin -n -i $source -ss $startSeconds -t $durationSeconds -vn -map 0:a:0 -ac 1 -ar 44100 -c:a libmp3lame -q:a 3 $clip
& $ffprobe -v error -show_entries format=duration -of json $clip
& $ffmpeg -v error -i $clip -f null -
```

变量来自已审核 manifest，duration=end-start。`$ffmpeg` / `$ffprobe` 先从本机工具配置定位并记录版本；不能把不存在的路径写成环境事实。输出以源 hash + 时段 + 编码参数寻址，已存在文件校验后复用，避免无条件覆盖。

若需要中间整音轨，将其放 `assets/generated/jttw-game-audio/source-audio/`，不放最终 clips，不写入原素材目录。实际可直接从 MP4 切句时无需先导出整条 MP3。

## 4. 证据清单和运行时清单分开

构建证据拟放 `assets/generated/jttw-game-audio/epN/source-manifest.json`，每项包含：

```json
{
  "id": "ep1:n001:en",
  "sourceNodeId": "n001",
  "kind": "source-clip",
  "sourcePath": "content/assets/video/ep1.mp4",
  "sourceSha256": "构建时计算",
  "timebase": "该文件的音轨秒数",
  "startSec": null,
  "endSec": null,
  "text": "从原节点读取全文",
  "speaker": "narrator",
  "reviewStatus": "pending",
  "reviewNotes": "待核对视频与原有audio时间线"
}
```

null 表示尚未审定，不是可发布时间戳。稳定逻辑 ID 与带 hash 的物理文件名分开；文本变化导致 digest 不匹配时重审。

运行时 `content/game/audio/epN.json` 仅携带已发布项：id、text、lang、kind、src、sourceNodeId（如有）。src 始终为 `assets/...` 相对路径；绝对本机路径不进入 APK。引用已有 MP3 时直接用原路径，不复制一份同内容。

## 5. 统一游戏语音适配器

拟新增 `prj/engine/game-audio.js`，供 game 和 battle 共用，复用 BookPlayAudio。

建议 API：`create({episode, audioIndex, media, onState})`，返回 `play(ref)`、`replay()`、`stop(reason)`、`dispose()`。media 在创建时接入 `watchMedia`，内部以 generation token 拒绝旧加载 / play promise 回调。

查找顺序：明确 audioRef 的已发布 src → 本集静态索引 → 通用静态索引 → 可用 /api/tts 或系统后备。样板验收中关键操作 / 单词 / NPC / Boss 必须在断网且不依赖系统语言包时可播，fallback 不能掩盖未打包文件。

声音状态：idle → loading → playing → ended；错误时 unavailable。产品上提示“这句暂时没声音，可点重听”，保留字幕和继续；开发记录 status / ref / URL / error，不把技术路径放到儿童画面上。

## 6. 播放时机与优先级

| 事件 | 默认声音 | 世界是否暂停 |
|---|---|---|
| 第一次捡球 | 中文 shortZh 一次 | 不暂停，但教学可暂缓追击 |
| 空手点小怪 / 点重听 | 英文一次 | 按当前状态 |
| 正确投掷命中 | 英文词一次 | 不暂停；同词短时间去重 |
| 错误匹配反馈 | 正确英文 + 中文提示 | 给予短安全窗口，避免边听边连续挨打 |
| NPC 台词 / 题干 | 原声或静态配音 | 世界暂停，读完仍由孩子推进 |
| Boss 题目 / 出招 | 题干、正确词或角色回应 | 按回合状态推进 |
| 暂停 / 隐藏 / 离开页面 | stop 当前语音 | 暂停 |

NPC 当前句 > 当前答题反馈 > 主动点读 > 自动拾取提示。相同优先级后一次替换前一次，自动低优先级不得打断 NPC。不要把高频碰撞提示都变成语音。

BookPlayAudio 已有 foreground / sfx 互斥：命中音效可先短播，再读词；读词时 BGM 降低。不为游戏新建持久化“语音开关”键，复用适用的既有设置或只维护本页内存偏好。

## 7. 发布阈值

- 每个实际朗读事件的已发布引用存在且可解码；关键项覆盖 100%。
- c01 所有新增剧情句逐条试听，原声与文本 / speaker 相符。
- 快速下一句、连续点读、暂停、切页、后台恢复无旧语音串入。
- 飞行模式 + 系统没有对应 TTS 语言包时，已打包主流程仍可用。
- c01 额外音频体积先设预算 10MB 内（已有文件复用不重复计入），超过时列明每类时长与码率后再调整；不牺牲清晰度凑数。

本方案借鉴 storybook-audio-splitting 的源文件保留、逐句证据和解码验收方法；西游记保持自己的 ep/node ID，不能直接调用 Mikey & JJ 的批处理写入另一套书籍目录。
