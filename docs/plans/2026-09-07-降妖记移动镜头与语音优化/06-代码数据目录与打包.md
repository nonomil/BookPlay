## 2. 地图与关卡契约

建议在 maps.json 增加 `schemaVersion:2`（保持旧结构可适配），每个主题增加 world 配置、区域、明确坐标和 camera 参数：

```json
{
  "world": {"cols": 4, "rows": 4, "tileWidth": 960, "tileHeight": 540},
  "camera": {"mode": "edge-follow", "deadZone": {"left": 0.25, "right": 0.75, "top": 0.25, "bottom": 0.70}},
  "heroSpawn": {"region": 5, "x": 0.5, "y": 0.58},
  "waveRegions": [1, 10],
  "npcSpots": [{"id": "intro", "role": "intro", "region": 5, "x": 0.32, "y": 0.62}],
  "bossSpot": {"region": 11, "x": 0.5, "y": 0.5}
}
```

这是局部字段示意，不是完整可运行关卡，quiz NPC、waveSpawns、可行走范围还需按主题补齐。所有 x/y 在这里是格内归一值，运行时 normalize 后只保留世界单位。不要把旧单图坐标默默当作整个4×4世界百分比。

`levels/epN.json` 继续提供 cast / intro / previewWords / waves / boss / map；新增 dialogueUrl / audioIndexUrl / wordId / shortZh / sourceNodeId / audioRef 都应可选。buildLevel 与 buildNpcLines 必须透传，下游有 round-trip 行为校验。

若旧关卡没有新字段，用当前主题的确定性默认值；未知主题 / 关键点缺失时给出明确数据诊断，不把所有错误显示成“未解锁”。

## 3. 音频目录契约

运行时音频索引推荐：

```json
{
  "version": 1,
  "episode": 1,
  "entries": {
    "word:mountain:en": {
      "text": "mountain", "lang": "en-US", "kind": "static-existing",
      "src": "assets/adv_audio/ep1/mountain.mp3"
    }
  }
}
```

真实 ID 由需求清单生成，本示例不表示 mountain 是当前 12 个游戏词之一。对白通过明确 audioRef 关联；原文来源通过 sourceNodeId 保留。manifest 中 sourcePath / sourceSha256 等证据只留构建区。

同文本不同语言、不同声源可有不同引用；文件物理去重按 hash，不把别的音色静默当作当前角色。只对已审核的 src 进行发布。

## 4. 三白名单与真实 APK 入口

| 通道 | 必查内容 | 具体动作 |
|---|---|---|
| 阶段 zip | `pack_datapack.py COMMON_FILES` | 对固定路径加载的 dialogues/epN.json、audio/epN.json 逐文件登记；扫描这两个 JSON 的运行时资源引用 |
| APK 内置 data | `pack_android.py pack_builtin → _build_stage_pack` | 验证 jttw-only 第1集所需新音频和 JSON 真正在内置树；COMMON_FILES 是共享项，不能假定自动按 episode 精简 |
| APK 引擎 | `pack_android.py ENGINE_FILES` | game-input.js、game-audio.js 及 HTML 引用依赖都登记 |

新增 MP3 必须有明确携带机制：优先从已登记音频索引展开引用闭包并验证所有 src；若当前收集器不展开这些 JSON，则本轮补该收集逻辑或将新增 MP3 逐条登记。只登记索引而不收集文件不算完成。

另有实际启动链：`prepare-mobile → dist/engine → cap sync → assets/public/engine`；Android 本地服务器的 /engine/ 正是读 public/engine。保留三白名单检查，同时比较 `assets/public/engine` 与 `assets/engine` 的本任务文件及源码 hash，不新增所谓“第四份手工白名单”。

外部已导入数据可能覆盖内置同名数据。安装新版 APK 后还要验证带旧 c01 数据包的升级路径，并在运行诊断中记录实际数据来源 / manifest 版本，不能只测试全新安装。

## 5. 发布与目录保护

- 修改真实源 `prj/engine`、`content/game` 和打包工具；Android assets / dist 由现有构建生成，避免手动只改一份副本。
- 不删除 `content/`、junction 或原素材；不要递归清理共有输出目录。
- 新手写 dialogues、地图数据等受 content gitignore 影响，提交时逐文件 `git add -f`；源内容与生成音频应按项目已有策略逐项登记。
- 游戏新的 run 字段只写两条既有游戏键；音频缓存使用浏览器/文件缓存，不自建游戏第三条存档。
- 本轮不重新生角色，不批量改其它系列音频，不部署外网。
