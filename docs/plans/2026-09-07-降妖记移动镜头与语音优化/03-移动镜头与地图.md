# 移动、镜头与地图

## 1. 坐标先统一

保留 DOM 渲染和现有两个游戏页面。世界逻辑使用同一套长度单位，屏幕只用一个 scale；角色、怪物、词球、弹道、碰撞、镜头、点击反算都遵守同一变换。

建议逻辑地图每格 960×540，4×4 共 3840×2160。格子是地图设计单位，**不再等于任意设备的一整屏**。

```text
screenX = playRect.left + (worldX - cameraX) × scale
screenY = playRect.top  + (worldY - cameraY) × scale
worldX  = cameraX + (pointerX - playRect.left) / scale
worldY  = cameraY + (pointerY - playRect.top) / scale
```

横屏短边对应约 540 逻辑单位；竖屏按可用宽设置同一 scale，再计算实际可见世界宽高。所有测量来自 game-scene 的实际 rect；不能用 window.innerWidth / height 代替含安全区和工具栏后的场景尺寸。

旧 map.x/y 是局部 0–1 坐标，转换时 x 乘格宽、y 乘格高。旧数据由 normalizeMap 一次性适配；不要让新旧坐标混入主循环。

## 2. 速度与摇杆

母本 `MOVE_SPEED=0.04` 即 40 逻辑单位/秒，参考可见宽 280、高 157.5。在 16:9 同比例展示下，可换算新 960 宽的起始速度约 **137 逻辑单位/秒**。这是对齐起点，最终按同尺寸录屏比较人物体长/秒和跨区时间，而不是只比较常量。

先等比例换算移动、追击、拾取、击退、投射距离；保留原参考的各机制比例，再做低龄真机微调。禁止只修改 HERO_SPEED，留下更快的小怪和过小的投掷范围。

摇杆目标模型：

```text
r = min(1, hypot(rawX, rawY))
r <= 0.15 → input = (0, 0)
否则 strength = (r - 0.15) / 0.85
velocity = normalize(raw) × strength × heroSpeed
```

键盘用单位方向向量，斜向归一；摇杆保留 strength，不再在 moveStep 中丢弃它。0.15 是初始调校值。

必须处理：pointerdown 当帧计算方向；记录唯一 activePointerId；其它手指不覆盖摇杆；pointerup / pointercancel / lostpointercapture / blur / hidden / 打开弹层都清零。

点词球自动走近时，单帧步长不超过剩余距离；手动输入立即取消自动目标。停下时用现有角色可用的静止帧或冻结帧，不能只有坐标停止而 GIF 一直走；优先复用已有资产。

## 3. 用户已确认的边缘跟随

镜头有一块中央静止区：主角在区内走，camera 不动；越过软边界才平滑跟随。HUD、对话和摇杆固定在屏幕层。

建议初始参数（均待样板调校）：

| 参数 | 起始值 | 用途 |
|---|---|---|
| 水平中央静止区 | 25%–75% 可用场景宽 | 允许角色先在屏幕内走 |
| 垂直中央静止区 | 25%–70% 可用场景高 | 留出下方手指操控区 |
| 硬安全边界 | 10%–90% | 跟随不能慢到人物离屏 |
| 平滑时间常量 | 100–160 ms | 启动柔和，快速追上 |
| 残差吸附阈值 | 0.5 屏幕像素 | 停止后消除微抖 |

算法顺序：计算当前 heroScreen → 越软边界时推导目标 camera → `alpha = 1 - exp(-dt / tau)` 做时间无关插值 → 硬安全边界校正 → 世界边缘 clamp。x/y 共用同一世界单位。

人物停止后允许很短的镜头收尾，目标 250ms 内停止；对话 / 暂停立即固定镜头。横竖屏切换重新算 viewport，保持主角世界坐标和当前任务不变。世界边缘只限制镜头，人物仍可在屏幕内走到边界。

`prefers-reduced-motion` 下保留必要的边缘跟随，关闭震屏、弹性过冲、无关浮动；不能以禁用所有镜头移动导致地图走不到。

## 4. 地图应有路线，不只是重复壁纸

先修正背景重复周期与4×4格子一致；后续允许同主题不同装饰层，但不新画全部角色。

样板路线推荐：出生/教程区 5 → 第一波区 1 → NPC 过渡区 6 → 第二波区 10 → Boss 区 11。仍保留完整 4×4 世界；实际点位根据背景可用地面审定后写到数据，不把本推荐常量写死在引擎。

- 每个目标区域有明显地标、入口和当前任务箭头。
- `heroSpawn` / `waveSpawns` / `npcSpots` / `bossSpot` 由地图 JSON 驱动。
- 第一阶段支持简单可行走矩形，落实已有 walkable 字段；画面中装饰树石先不增加复杂碰撞。
- 若美术明显画出不可走的水 / 峭壁，第二阶段增加少量阻挡矩形及轴向滑动；没有安全路径时生成器报错。
- 词球和怪物出生点必须可达且不重叠。镜头移动不能改变它们的世界坐标；禁止 resize 后重新生成位置。
- 人物按脚底 y 做前后遮挡，词牌置顶但不得把对话层压住。

## 5. 输入所有权与主循环

| 状态 | 方向键 | OK / Enter | 指针 | 世界更新 |
|---|---|---|---|---|
| explore | 移动角色 | 对话范围内交互，否则向选中怪投掷 | 左摇杆移动，右手选目标 / 投掷 | 开启 |
| dialogue / boss-confirm | 移动当前弹层焦点 | 当前按钮 | 当前弹层 | 冻结 |
| pause / result | 菜单焦点 | 当前按钮 | 当前菜单 | 冻结 |
| hidden | 清零 | 忽略 | 清零 | 冻结 |

给 tv-remote 增加页面级输入所有权钩子；探索时跳过它的焦点漫游，弹层时只处理该层。保留其它学习页原有 TV 行为。

运动 / buff / 伤害用有效游戏时间，音频加载和 UI 超时用真实时间。保留 320ms 看门狗和 debug.step，但所有入口进同一 tick；测试不可产生负 dt 或双推进。若 15–20fps 实测仍明显变慢，再采用有上限的固定步长补步（如 16.67ms，每帧最多 5 步），隐藏恢复清空累积时间。

## 6. 本部分完成条件

同一地图、同一屏幕比例下，上下左右实际速度误差 ≤5%，斜向总速度误差 ≤5%；轻推比满推慢，松手 100ms 内停止。中央区 camera 位移 ≤1px，边缘跟随连续，停下后 ≤250ms 稳定。旋屏、切后台、双指投掷和遥控弹层后均无卡键或自动漂移。
