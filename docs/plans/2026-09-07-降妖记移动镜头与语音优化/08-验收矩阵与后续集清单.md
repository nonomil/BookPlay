## 2. 自动化与手动证据边界

- 纯逻辑测试：坐标变换、死区/速度、镜头边界、状态机、奖励幂等、词池、音频选择与取消。
- 内容/打包测试：引用完整性、时间窗、源hash、音频解码、APK两个引擎副本与实际加载路径。
- 浏览器E2E：使用独立临时浏览器上下文、测试夹具和真实键鼠/触屏事件；不污染用户现有进度。可用debug准备状态，但完整流程另有不跳阶段用例。
- 真机：手感、双指、返回键、音量/输出通道、WebView音频与后台恢复。没有设备的结果不得由桌面截图替代。

未来E2E脚本 `prj/tests/game-loop.e2e.mjs` 需在T08创建，不能将其命令提前报告为执行成功。

本地服务使用已有入口：

```powershell
python -X utf8 prj/tools/serve.py --port 8810
```

打开 `http://127.0.0.1:8810/engine/game.html?ep=1`，ep5同理。该服务明确映射engine/data/assets；不要用仓库根静态服务造成404，再误以为关卡缺失。

## 3. 证据目录与结果格式

```text
docs/reports/降妖记优化验收/
  environment.json            git/脏文件摘要、node、Python、FFmpeg、设备与WebView
  artifact-hashes.json        源码、APK、内容包、public/engine的hash
  results.json                V01–V28逐项状态/实测值/证据路径
  现状复现.md                  改造前问题复现
  结论与残留问题.md             已通过/失败/待验和原因
  recordings/                 输入、镜头、整局、语音及后台测试
  screenshots/                节点/关卡/错误反馈
```

每条结果记录至少含 `caseId / status(pass|fail|pending) / episode / device / appVersion / contentVersion / expected / actual / evidence / timestamp`。

同一测试在代码改变后用新证据覆盖状态，旧录屏可保留版本标识；没有重跑的相关项退回pending。源码测试通过不自动勾选真机项。

## 4. 后续集逐项清单

新开ep8+时，先确认c01样板已按新流程验收，再执行：

- [ ] 本集故事节点、词库和可用来源媒体齐全；明确哪些是原文，哪些是新增游戏台词。
- [ ] cast / theme / sprites引用有效；复用已有角色/背景，不复制一份引擎。
- [ ] maps.json使用正确坐标版本，出生、两波、NPC、Boss可达；镜头保持edge-follow。
- [ ] 正式词条有稳定wordId、短中文shortZh，英文词牌与判题用同一个词条。
- [ ] dialogues/epN.json的剧情、题目、带读、继续路径完整；sourceNodeId/audioRef能解析。
- [ ] 生成levels/epN.json并检查buildLevel透传新增字段；内容修改真的被运行时使用。
- [ ] 音频需求清单与最终文案一致；已有静态音频复用，新原声有来源/时段/审核，新编话有配音。
- [ ] audio/epN.json所有src存在并解码通过；未审核原声不进入发布索引。
- [ ] COMMON_FILES逐项登记固定JSON；相关MP3从闭包实际进入zip，缺失能使构建失败。
- [ ] 若新增了通用脚本，ENGINE_FILES和public/engine同步检查；通常扩集无需新增JS。
- [ ] APK默认仍按其开箱档案提供内容；扩集通过数据包进入，不仅凭所有关卡JSON都在包内判断“已解锁”。
- [ ] 完成巩固后自动邀请本集游戏；进入与跳过都正常；入口不指向旧battle页。
- [ ] 本集至少一次完整移动/词球/道具/NPC/Boss/返回，且一次断网语音验证。
- [ ] 当前完整npm测试数量不下降、无失败；记录真实设备未覆盖项。
- [ ] 更新旧手册五文件中的范围和具体包版本，以本次证据为依据。
