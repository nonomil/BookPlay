# T10-S03 验收签收与计划归档

所属：[T10 文档收口与发布验收](../TASK.md)。状态统一写[state.json](../../state.json)。

## 输入与目标

将30个子任务逐项附证据与复核人，核对任务依赖；STATUS生成无漂移；填写最终报告与剩余P3；下一轮只从未完成收益项立项。

文件范围以父任务为准；先读取相关函数与现有测试，再定位本子任务所需最小变更。前置：T10-S02 验收完成。

## 执行步骤

1. 记录当前revision与相关dirty diff，确认输入/素材版本；把本条触发条件做成最小fixture或检查记录。
2. 编写会暴露当前缺口的行为断言/验收脚本，运行一次保存预期失败；文档或纯治理步骤改为先检查现有差异，不写无意义单测。
3. 按上文方案修改最小文件集合；保持既有业务语义，每次只处理一个边界。
4. 运行父任务的定向命令和相关验收用例；比较修复前后结果，发现新失败先定位，不直接扩大断言容差。
5. 保存证据并自查diff；写明回滚点。若有提交记录附提交号；没有提交就附文件hash和diff路径，禁止编造。
6. 更新state.json为review，填写证据；复核达标后才改done。发现依赖/环境缺口写blocked与最小解除动作。

## 必须达到的结果

每个done都有可读证据；回滚包/迁移备份路径明确；未验收项仍标blocked/review；本轮用户可直接复查交付和收益。

## 证据交付

建议文件：`../evidence/S03-验收.md`。填写：环境与输入、命令及退出码、断言/操作步骤、实际结果、相关日志/截图/trace路径、复核人、已知限制。只写“测试通过”不合格。

## 回滚与退出

历史文档保留原日期；回退发布指针到上一个已验收版本，不清学习数据；用户升级兼容问题须走存档备份恢复方案。 达不到本条结果就保留review/blocked，不能依靠父任务其他测试全绿关闭。
