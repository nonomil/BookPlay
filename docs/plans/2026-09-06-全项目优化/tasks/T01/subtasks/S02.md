# T01-S02 隔离源码测试与本地素材测试

所属：[T01 测试基线与环境分层](../TASK.md)。状态统一写[state.json](../../state.json)。

## 输入与目标

用 pytest marker 区分 unit/content/local_integration；将修改真实 manifest 的测试改用 tmp_path 与注入 ROOT；个人技能合同仅进入显式 local_integration。盘点实际 import 和本机版本，固定最小测试依赖。

文件范围以父任务为准；先读取相关函数与现有测试，再定位本子任务所需最小变更。前置：T01-S01 验收完成。

## 执行步骤

1. 记录当前revision与相关dirty diff，确认输入/素材版本；把本条触发条件做成最小fixture或检查记录。
2. 编写会暴露当前缺口的行为断言/验收脚本，运行一次保存预期失败；文档或纯治理步骤改为先检查现有差异，不写无意义单测。
3. 按上文方案修改最小文件集合；保持既有业务语义，每次只处理一个边界。
4. 运行父任务的定向命令和相关验收用例；比较修复前后结果，发现新失败先定位，不直接扩大断言容差。
5. 保存证据并自查diff；写明回滚点。若有提交记录附提交号；没有提交就附文件hash和diff路径，禁止编造。
6. 更新state.json为review，填写证据；复核达标后才改done。发现依赖/环境缺口写blocked与最小解除动作。

## 必须达到的结果

从不带媒体的临时检出可运行源码层；内容缺失明确提示恢复流程；中断测试不会修改 content；每个 marker 能列出被选/排除用例。

## 证据交付

建议文件：`../evidence/S02-验收.md`。填写：环境与输入、命令及退出码、断言/操作步骤、实际结果、相关日志/截图/trace路径、复核人、已知限制。只写“测试通过”不合格。

## 回滚与退出

只回退测试组织与依赖配置；保留原始失败日志，不重写内容。 达不到本条结果就保留review/blocked，不能依靠父任务其他测试全绿关闭。
