# 西游记勋章墙与小白龙伙伴：整体优化分析

设计复盘日期：2026-09-01  
适用版本：当前已落地的 P1 MVP   
相关实现：`prj/engine/map.*`、`prj/engine/companion.*`、`prj/engine/companion-core.js`、`content/achievements/jttw.json`、`content/companions/white-dragon.json`

## 1. 结论先行

当前方向是对的：**路线图负责“下一步做什么”，勋章负责“我已经做到什么”，小白龙负责“谁在陪我走”，SP 负责“这一题即时反馈”**。不建议再把系统扩展成完整宠物积分游戏。

下一轮优化的重点不是再增加奖励数量，而是让这四层分工在同一条学习路径里更清楚：

1. 打开西游记后，5 秒内能找到唯一的主动作「继续学习」；驿站是次级入口，不抢学习主线。
2. 学完一集、通过一辑巩固后，只出现一次合并反馈，并明确告诉孩子“获得了什么、下一步去哪”。
3. 勋章墙默认只突出最近获得、下一目标和已拥有内容；19 枚完整收藏仍可查看，但不让孩子面对一整面同等重要的灰锁。
4. 小白龙保持单伙伴、免费照料、不会生病和掉级；玩具架和房间装饰作为验证需求后的第二阶段。
5. 先修正学习日记录、移动端布局、无障碍和错误状态，再考虑更多纪念物。

产品停止线仍然有效：不做多宠物、抽卡、排行榜、倒计时、商城、生存衰减和战斗属性。

## 2. 当前状态审计

| 领域 | 当前状态 | 判断 |
| --- | --- | --- |
| 学习主路径 | 首页 → 闪屏 → 13 辑路线图 → 单集 → 巩固 | 基础链路成立，但缺少全局“继续学习”按钮 |
| 伙伴入口 | 地图顶栏、封面闪屏、独立驿站页 | 可发现性好，入口数量略多 |
| 勋章体系 | 19 枚，条件来自现有进度，幂等补发 | 规则可靠；信息密度和分组还可优化 |
| 伙伴成长 | 7 阶段，由剧情进度派生；4 个免费互动 | 轻量合适，重复互动的长期回访理由不足 |
| 同行日 | 学习日 + 当天首次照料盖印，漏天不清零 | 设计正确；单集 `progress` 当前没有写入 `day`，存在行为缺口 |
| 视觉资产 | 7 张 PNG，SVG 回退，已做透明质量检查 | 质量门成立；移动端体积仍偏大 |
| 离线与 Android | 数据包清单、移动端页面和测试已接入 | 需要增加运行时错误和返回路径验证 |
| 无障碍 | 焦点、`reduced-motion`、语义按钮已有 | 地图仍有持续 `map-bob`，对话框焦点和状态描述可加强 |

### 2.1 已确认的实现缺口

`prj/engine/companion.js` 的 `inferTodayLearning()` 依赖 `bookplay_adv_progress` 项中的 `day` 字段，但当前 `prj/engine/adventure.js` 的 `saveProgress()` 只写入 `node`、`total`、`done`。因此：

- 只读完并推进单集、当天进入驿站，可能不会被识别为“今天已经学习”；
- 完成巩固时因为 `drill.js` 会写 `day`，又可以正常识别；
- 这会让“看故事就能和伙伴同行”的产品承诺在两条路径上表现不一致。

这是 P0 逻辑修复，不是新玩法。建议只在真实推进（翻过至少一页或完成一集）时写入当天日期，不能把单纯打开页面算成学习。

## 3. 端到端体验问题与优化方向

### 3.1 入口：从“有很多入口”改为“一个主动作、两个次动作”

当前地图顶栏同时放了首页、当前辑、伙伴、SP、列表，闪屏又放了一个伙伴入口。信息都存在，但孩子第一眼仍需要自己判断“现在应该点哪里”。

建议的层级：

```text
继续学习（当前未完成集）
  ├─ 看西游地图（查看路线、换辑）
  └─ 去白龙马驿站（伙伴、勋章、同行日）
      · SP 只做小型状态显示
      · 列表收进“更多”或保留给家长/熟悉用户
```

落地建议：

- 地图当前辑页头增加高识别的「继续第 N 集」按钮，链接到第一个未完成节点；
- 已完成当前辑、待巩固时，主按钮改为「去完成本辑巩固」；
- 全部完成时，主按钮改为「回看最后一辑」或「去驿站看收藏」，不要显示失效的“继续”；
- 闪屏继续 1.25 秒自动消失，伙伴卡只做可点击的次级入口，不能延长固定等待；
- 手机竖屏把顶栏压缩为“返回 / 当前辑 / 伙伴”，SP 和列表改为次级区域，避免横向挤压。

### 3.2 学习到奖励：建立一个短而稳定的反馈闭环

推荐固定为：

```text
完成单集 → “已学会这一集” + 下一集
通过巩固 → “本辑勋章收入墙” + 小白龙变化 + 下一辑
进入驿站 → 查看收藏 / 做一次免费互动
```

同一事件最多一个庆祝层。若一次同时触发篇章章、旅程章和伙伴阶段变化，合并为一张卡：

- 主标题：小白龙阶段变化或篇章完成；
- 次信息：获得的勋章数量和名称；
- 主按钮：继续下一辑；
- 次按钮：去驿站查看。

这样可以避免连续弹出 SP、勋章、升级、纪念物四个打断层。

### 3.3 勋章墙：从“19 枚网格”改为“收藏展柜”

现有多形状 CSS 视觉已经足够有识别度，下一步应优化信息架构，而不是继续增加形状。

建议首屏顺序：

1. 顶部显示 `已获得 X/19`、最近获得（最多 3 枚）；
2. 单独突出一张「下一目标」卡，显示可理解进度，例如“第 1 辑巩固：7/7 集，下一步完成巩固”；
3. 「我的篇章印」13 枚按辑分组；
4. 「旅程里程碑」6 枚单独分组；
5. 远期目标折叠到“查看全部”，不让所有未获得章同时抢注意力。

推荐增加的低成本交互：

- “全部 / 篇章 / 旅程”三个筛选按钮；
- “最近获得”排序或横向小条；
- 每张卡增加 `aria-label`，把获得状态和进度读完整；
- 下一目标同时提供「回到对应辑」按钮。

不建议：按稀有度、颜色或排行榜排序；这些会把阅读成就变成比较和竞争。

### 3.4 小白龙：增加“回访理由”，不增加生存压力

现有四个动作已经构成轻互动，但动作结果主要是文字回应和一次弹跳。首版可以保持不变，先补三点：

- 每种动作有一个 1–2 秒不同的视觉反馈（吃果、玩水、云球、休息），仍支持 `prefers-reduced-motion`；
- 互动后显示明确状态：“今天已盖同行印”或“今天学习后再互动”；
- 驿站增加一个固定的“最近获得”小架位，为后续纪念物留位置，但暂不开放自由装修。

孩子明确表现出“想收集玩具、想装饰房间”后，再进入 P2：13 件故事纪念物、一个固定玩具架、每件一种轻互动。暂不做家具槽、购买、库存和主题切换。

### P1：验证 MVP 后完成

| 项目 | 价值 | 控制范围 |
| --- | --- | --- |
| 勋章分组、最近获得、下一目标卡 | 降低理解成本 | 只增加信息架构，不增加勋章数量 |
| 最近一次互动与最近一次学习提示 | 增强伙伴回应 | 只保留本机状态，不做账号和社交 |

### P2：只有出现需求信号才做

- 13 件篇章纪念物和固定玩具架；
- 两到三个驿站主题背景；
- 少量 SP 兑换非必要外观；
- 更丰富但仍可跳过的互动动画。

进入 P2 的信号应是：孩子主动打开驿站、能说出下一枚勋章如何获得、获得篇章章后主动询问“能不能放到房间里”。只被一次性庆祝弹窗带入，不算真实需求。

## 5. 无障碍、性能与离线检查清单

### 5.1 无障碍

- 正常文字与背景保持至少 4.5:1 对比度；勋章的颜色、形状、文字三者共同表达状态；
- 地图 `.node-tip` 的持续 `map-bob` 在 `prefers-reduced-motion: reduce` 下关闭，地图滚动改为即时；
- 进入 `dialog` 后把焦点放到关闭按钮，关闭后还原到原勋章卡；
- 伙伴、勋章、照料动作均有可读的中文 `aria-label`，不依赖 emoji 才能理解；
- 触控目标至少约 44px，横屏和电视遥控焦点都能看见；
- 重要状态不能只用灰度或颜色表示，保留“已获得 / 下一目标 / 未获得”等文本。

### 5.2 性能

当前 7 张阶段 PNG 合计约 12.79 MB，单张约 1.55–2.34 MB。桌面端可接受，但低端 Android 设备会在切换阶段时承担解码和内存峰值。

优化顺序：

1. 先测实际设备上的首屏时间和内存，不凭文件大小直接改格式；
2. 生成 512–768px 的 WebP/AVIF 运行资产，保留 PNG/SVG 回退；
3. 仅加载当前阶段，切换阶段时取消旧请求；
4. manifest 继续记录尺寸、字节数、SHA-256、alpha 检查和绿边比例；
5. 生图 API 只在离线生产流程中运行，密钥不进入仓库、APK、网页或数据包。

### 5.3 离线与存档

- `content/achievements/`、`content/companions/`、阶段素材和页面清单必须由同一条 Android prepare 流程打包；
- JSON 损坏、旧存档、空存档时回退到龙蛋和空勋章墙，不阻塞地图；
- 勋章收据继续采用永久、幂等、带 `rule_version` 的写入；
- 同行日只保存日期集合和必要的最近动作，不引入时间衰减、服务器时间或账号同步；
- 从驿站返回地图后，使用 `pageshow` 复核进度、SP、勋章和伙伴阶段；
- 未来新增书系时，勋章 ID 必须带书系前缀，不能和《西游记》串章。

## 6. 验收指标

下一轮优化不以“增加了多少玩法”为成功标准，而以真实路径是否更清楚为准：

1. 首次进入地图，孩子在 5 秒内能找到「继续学习」；
2. 从地图到当前学习内容最多一次主点击；
3. 完成一辑后，孩子能说出获得的勋章和下一辑位置；
4. 驿站打开、照料、返回地图不丢失当前辑和当前节点；
5. 同一天重复照料只盖一次同行印，漏一天不扣除任何东西；
6. 空进度、历史进度、坏 JSON、缺失 PNG、Android 数据包都能安全降级；
7. 减弱动效和键盘/遥控操作不影响完成学习；
8. 全量 `npm test` 中与本任务无关的 Mikey & JJ 内容问题继续单独记录，不在本轮混改。

## 7. 推荐实施顺序

### 第一步：修闭环（P0）

修正 `day`、加入“继续学习”主 CTA、统一巩固完成反馈，补四种主状态的浏览器冒烟测试。

### 第二步：降认知负担（P0/P1）

勋章墙分组和下一目标卡，收敛移动端顶栏，补 dialog 焦点、`aria-label`、减弱动效和失败重试。

### 第三步：降资源成本（P1）

在目标 Android 设备上测 PNG 解码，再决定 WebP/AVIF 尺寸；把生图提示词、角色圣经、manifest 和质量报告作为唯一生产入口。

### 第四步：用真实行为决定 P2

只要孩子会主动回驿站、查看收藏并询问玩具/房间，就做固定玩具架和纪念物；如果只是领取弹窗后立刻回地图，就不扩张养成系统。

## 8. 最终判断

小白龙伙伴已经足够回应孩子“喜欢养宠物、积分奖励和打卡”的偏好。现在最有价值的优化是把学习路径、成就路径和情感路径接得更顺，而不是把系统做重。

**当前建议：先做 P0 闭环与可读性修复，再观察驿站主动回访；P2 玩具与房间装饰延后，完整宠物积分系统继续不做。**
