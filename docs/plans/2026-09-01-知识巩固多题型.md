# 知识巩固多题型实施计划

> **给 Claude:** 必需子技能：使用 superpowers:executing-plans 来逐任务实施此计划。

**目标：** 将每集知识巩固改成可理解、可朗读的多题型练习：英文选中文、中文选英文、句子排序、句子补全，并提供可点击发音的单词知识回顾。

**架构：** `lesson-core.js` 负责从课程卡片和对应故事数据生成稳定的题型模型；`lesson.js` 负责统一的 Edge-TTS 播放、题型交互和反馈；`lesson.css` 提供清晰的大按钮与回顾卡样式。故事 JSON 中已有 `official_words`、`nodes` 和 `puzzles`，只在运行时读取，不复制或改写 108 集数据。

**技术栈：** 原生 JavaScript、Node 内置测试、pytest 契约测试、现有 `/api/tts` Edge-TTS 服务。

---

### 任务 1：锁定题型数据契约

**文件：**
- 修改：`prj/tests/test_episode_lesson_runtime.py`
- 参考：`content/dialogue_stories/ep1.json`

**步骤 1：编写失败测试**

覆盖 `word_en_to_zh`、`word_zh_to_en`、`sentence_order`、`sentence_fill`、`word_review` 的字段、答案和发音文本。

**步骤 2：运行测试确认失败**

运行 `pytest -q prj/tests/test_episode_lesson_runtime.py`，预期新断言因 API 尚不存在而失败。

### 任务 2：扩展核心题目生成

**文件：**
- 修改：`prj/engine/lesson-core.js`

**步骤 1：实现最小生成器**

从词卡生成两个方向的选择题；从故事 `puzzles` 生成排序题；从带例句词汇或故事节点生成补全题；保留词条的音标、词性、中文释义和例句供回顾与朗读。

**步骤 2：运行核心契约测试**

运行 `pytest -q prj/tests/test_episode_lesson_runtime.py`，预期题型字段测试通过。

### 任务 3：接入页面交互和 Edge-TTS

**文件：**
- 修改：`prj/engine/lesson.js`
- 修改：`prj/engine/lesson.html`

**步骤 1：加载对应故事数据**

并行读取 `lesson.json` 与 `/data/dialogue_stories/epN.json`，生成稳定题目顺序。

**步骤 2：实现渲染器**

选择题显示双语选项；排序题支持点击组句、撤回和确定；补全题支持选择缺词；回顾卡显示单词、音标、词性和释义，点击单词或扬声器朗读。

**步骤 3：统一朗读**

所有英文题目、单词、句子和选项优先请求 `/api/tts?voice=en&text=...`，中文释义用 `voice=zh`，失败才使用浏览器回退。

### 任务 4：样式和回归验证

**文件：**
- 修改：`prj/engine/lesson.css`

增加题型标签、排序词块、补全选项、回顾卡和清晰的点击/焦点状态，保证 320px/390px 不横向溢出。

