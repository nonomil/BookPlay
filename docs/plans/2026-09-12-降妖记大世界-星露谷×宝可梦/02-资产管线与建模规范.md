# 02 资产管线与建模规范

> 原则：**人物/场景不二次建模，直接复用既有四向精灵与生图产物**；新需求走已验证的生图 SOP 一次生成、注册表接入、引擎零改动。

## 1. 人物模型：复用优先，规范生成兜底

### 直接复用（已有，零成本）
| 用途 | 资产 | 说明 |
|---|---|---|
| 大地图行走/对战立绘 | `content/assets/generated/jttw-player-walkers/<id>/directions/` 四向 walk+action GIF（4 主角）+ `content/assets/game-sprites/`（6 小怪） | 4×8 分镜：每行一方向，前 4 格走路后 4 格持械动作 |
| NPC 站桩 | 任一角色 walk 第 1 帧 + `assets/walker-gifs/` 24 角色兜底 | 星露谷 NPC 站桩对话直接用 |
| 图鉴卡/妖怪卡 | 透明帧任选一帧 + 卡框（P1 生图） | 不需要新画 |

### 新生成的建模规范（与既有 4×8 对齐，勿另立标准）
- **规格**：一张 4 行 × 8 列（行=南/西/东/北），列 1-4 走路循环、列 5-8 持械/施法动作；格子内容源自 provider 实际尺寸等比归一，最终帧 192×256。
- **背景**：角色类必须透明；提示词写 "transparent background" 会产出假棋盘格 → 用 `transparent-image-generator` 的 checkerboard 模式移除；场景图写实心（full-bleed）。
- **进化形态**：同角色同一提示词改"进化后外形段"再生成一张 4×8（造型连续性靠提示词锁定发型/武器/主色）；图鉴显示用 act-04（胜利姿态）帧。
- **图鉴卡图**（P1）：3×3 sheet 一次 9 张（每辑 9 只妖怪），拆格后 `<dex-id>-card.png`。
- **Tileset**（P2 词田）：3×3 可拼接地块（土/水/苗/成熟/荒），1536×1024 一张，拆 3×3，命名 `tile-<name>.png`。
- **NPC 头像**（对话用）：单帧半身像，2×2 sheet 一次 4 个。

### 落盘与注册（引擎零改动接入）
```
assets/generated/jttw-game-sprites/<辑>/<集或shared>/<asset-id>/
  ├─ source/prompt.txt  ├─ 2d/(原图+响应JSON)  ├─ 2d/split/  ├─ transparent/(+alpha报告)  └─ manifest.json
→ 运行时帧/GIF 拷 content/assets/game-sprites|game-backgrounds/
→ 登记 content/game/sprites.json（行走）与 content/game/dex.json（图鉴）
→ 三白名单同步（pack_datapack COMMON_FILES / pack_android DATA_DIRS+闭包 / ENGINE_FILES 不涉资产）
```

## 2. 内容建模：所有游戏对象的数据契约

### 妖怪（dex.json 条目，P1-1 产出 schema）
```jsonc
{
  "id": "chaosdemon", "nameZh": "混世魔王", "tier": 1,
  "words": ["chaos", "furious"],            // 绑定词：图鉴解锁条件 = 这几个词进入 mastered
  "element": "water",                        // 属性：克制矩阵见 04
  "sprite": "chaosdemon",                    // 指向 sprites.json
  "cardFrame": "assets/game-sprites/cards/chaosdemon-card.png",
  "evolution": { "to": "chaosdemon-lv2", "requireWords": 8, "requireStars": 6 },
  "habitat": ["water-dirty-cave"],           // 出现主题（= 星露谷"栖息地"）
  "catchQuiz": { "kind": "meaning-choice", "count": 3 }   // 捕捉=答对 N 题
}
```

### 词田作物（P2）
```jsonc
{ "id": "word-plot", "seedCost": 5, "growDays": 1, "waterWord": true,
  "harvest": { "wordCard": 1, "gold": 2 } }   // 种=预学新词，浇水=答 1 题复习，收获=词卡
```

### 商店/物价（P2）
`content/game/economy.json`：`{ "items": { "peach": {buy:8, sell:3}, ... } }`——数值平衡只改 JSON。

## 3. grok-build 并行执行（有界实现任务）

- 适用：纯函数模块 + 测试（combat 克制矩阵、schedule 日结算、economy 定价校验）、批量资产后处理脚本。
- 不适用：需要跨文件设计决策、涉及存储键合同、UI 手感的任务（主会话自己做）。
- 委派合同模板（单行化后经 `<bridge> create --cwd G:\Game\BookPlay书戏 --owner "<会话标题>" --prompt "<合同>" [--always-approve]`）：
  `目标：<模块>；写集：prj/engine/<模块>.js/.test.mjs + content/game/<数据>.json；禁区：不改其他文件/存储键/打包脚本；验收：node --test <文件> 全绿 + npm test 不低于现场基线；产出：测试清单+模块 API 说明。`
- 端口纪律：预览服务器一律 `--port 0` 取 OS 分配端口，不杀他人监听。

## 4. 质检合同（沿用并强化）

manifest（sha256/provider/尺寸）+ alpha 报告 + 拆格 QC（每格非空）+ 深/浅底抽查无色边 + **新增**：接入自检脚本 `prj/tools/check_game_assets.py`（校验 sprites.json/dex.json 引用的每个路径存在、三白名单覆盖完整——缺一即 fail，杜绝静默缺资产）。
