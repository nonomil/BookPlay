# 01 第一原理与内容分析

## 1. 终局意义：这个游戏到底为什么存在

降妖记不是"游戏"，是**间隔重复调度器 + 提取练习发生器**的糖衣。教育科学里两条最硬的结论：

1. **提取练习（retrieval practice）**：主动回忆比重读有效数倍——宝可梦式对战（必须从记忆里取出"这个词对应哪只怪/哪个招"）就是标准提取练习。
2. **间隔重复（spaced repetition）**：遗忘曲线靠"隔天再考"打败——星露谷的"一天"循环（今天体力有限 → 选择花在谁身上）就是天然的复习调度器。

**因此每一个玩法决策的评判标准**：它是否同时 (a) 创造一次提取练习，(b) 服从间隔调度。纯装饰玩法（无单词提取）一律降级为奖励演出。

## 2. 星露谷 × 宝可梦的组合为什么是对的

| 层 | 星露谷提供 | 宝可梦提供 | 学习映射 |
|---|---|---|---|
| 时间结构 | "一天"循环、体力、季节日程 | 无 | 一天 = 一个复习单元；体力 = 今日复习预算（由 review-queue 的到期词数决定） |
| 长期动力 | 经营复利（田/牲畜/关系逐日成长） | 图鉴收集 completionism | 词田收获 = 词卡入图鉴；图鉴完成度 = 词汇量可视化 |
| 局内动力 | 探索/采集/手工 | 对战/捕捉/进化 | 找词打怪 = 辨认提取；对战选招 = 分类提取；捕捉新怪 = 学新词 |
| 情感 | NPC 好感、四季变化 | 妖怪伙伴成长 | 好感 = 连续坚持天数；妖怪升级 = 掌握度升级（孩子对"自己的怪"有感情=对词有感情） |

## 3. 现有复利资产盘点（截至 2026-09-12）

### A 资产层（直接可用，零重画）
- 四主角 + 6 小怪**四方向 walk+action 分镜**（4×8 规格，32 帧/角色 + GIF）；24 角色单向走路 GIF

### B 算法层（纯逻辑 + node:test，可直接长出新玩法）
- `battle-core.js`：出题/词球组卷/判定/连击/错词/结算（11+ 用例）
- `game-core.js`：移动/朝向/六道具/增益/背包/NPC 门控/Boss 血条（14 用例）
- `game-input.js`：模拟量输入适配（死区/pointer 归属/弹层分权）

- 镜头系统（edgeCameraStep，TDD 达标）；既有题型库 `lesson-core`（听音识图/看图选词/句型…）

### C 数据层

### D 管道层
- 生图 SOP（提示词模板/checkerboard 去背/拆格/GIF/manifest）
- 打包三白名单接线；E2E 泵帧钩子（BookPlayGameDebug.step）；测试基线 446

### 缺口（要新建的）
1. **图鉴数据模型**：怪↔词↔属性↔经验↔进化的绑定（现在怪只是"词的皮"）
2. **回合制战斗引擎 v2**：现在是"答题制"单回合；缺招式/属性克制/经验结算/捕捉
3. **日循环/体力/经济**：完全没有
4. **妖怪卡图鉴图/进化形态/Tileset**：资产生成批次
5. **整局状态闭环**（005 T03-T05 未修：NPC 门控/跨页快照/幂等奖励）

## 4. 设计原则（写代码前先背下来）

1. **数据驱动优先**：克制矩阵、物价、进化阈值、招式表全部 JSON——调平衡不改代码。
2. **一次生成多处复用**：同一只怪的 4×8 分镜，同时服务大地图游荡/对战立绘/图鉴卡/词田劳作。
3. **学习事件 = 游戏事件**：答对=攻击命中/捕捉成功；错词=妖怪逃跑/作物枯萎——不做与学习无关的数值系统。
4. **存档向后兼容**：新系统写新键（`bookplay_dex_v1`/`bookplay_farm_v1`），旧的 `bookplay_battle_*` 只读迁移。
5. **每任务过复利检查**（00-总览 §2）。
