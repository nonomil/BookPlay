## 并行执行（grok-build）

1. 主会话拆出**有界实现任务**（典型：P1-2 combat-core、P2-2 economy-core——纯函数+测试，写集明确）。
2. `grok-build` 的 `<bridge> hooks install`（首次）→ `create --cwd G:\Game\BookPlay书戏 --owner "<标题>" --prompt "<单行合同>"`。
3. 合同必须含：写集白名单、`npm test` 不低于现场基线、禁止改存储键/打包脚本、产出物清单。
4. 主会话验收：跑测试 + 抽查 diff + 复利检查，不合格打回同一 session 修正。

## 风险与红线

- **范围膨胀**：星露谷系统只做"服务复习调度"的最小子集（体力/词田/商店），不做天气/季节/婚姻。
- **数值失控**：一切平衡进 JSON；每阶段跑 `validate` 校验。
- **并行冲突**：map.js/lesson.js/battle.js 并行会话在改——P0 动手前 git status 复核，改动尽量新文件化（core 库天然隔离）。
- **性能**：大世界实体+粒子在低端 TV WebView 的帧率，P1 回归时用 BookPlayGameDebug 泵帧 + 实机验证。
