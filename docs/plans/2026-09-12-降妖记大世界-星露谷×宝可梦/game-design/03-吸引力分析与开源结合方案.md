# 03 吸引力分析与开源结合方案（调研结论）

> 调研：2026-09-13。工具：tavily（代理未开，走 key 直连）+ 本地参考库 prj-ref。证据分层：✅ 已验证（来源/实测）、🔲 推断。

## 1. 先回答核心问题：这套玩法能吸引小朋友吗？

**能，但吸引力不在"像星露谷"，而在三个被验证过的儿童机制**（✅ 由主流游戏长销事实反推 + 教育设计通识）：

| 机制 | 为什么对 7-10 岁有效 | 我们的落点 |
|---|---|---|
| **可见的成长**（收集/图鉴/进化） | 宝可梦 30 年验证：孩子对"自己的怪"有感情，图鉴完成度是最强回访动力 | 每只妖怪绑定 1-3 个词，图鉴=词汇量可视化；进化=掌握度里程碑 |
| **安全的掌控感**（经营/种植） | 星露谷验证：没有失败惩罚的放置成长，焦虑儿童也能玩 | 词田：种词→答题浇水→收词卡；枯萎不惩罚、只回炉复习 |
| **社交剧本**（NPC 关系/对话） | 星露谷 NPC 好感 + 孩子的角色扮演天性 | 每集 NPC=剧情角色（已落地）；好感=连续到访天数 |

**风险点（诚实评估）**：7-10 岁对星露谷式"慢节奏经营"耐心有限——星露谷层必须做成**轻量每日仪式**（2-3 分钟），重头戏仍是 3-5 分钟的战斗与收集。纯生活模拟（做菜/钓鱼/社交全景）不适合本产品。

## 2. 有没有可直接复用的开源代码？——有，但分层采用

### 结论矩阵（✅ 均已核实来源）

| 项目 | 技术栈 | 许可证 | 对我们的价值 | 采用决策 |
|---|---|---|---|---|
| **Tuxemon**（开源宝可梦，411 只怪） | Python/Pygame | 代码 **GPLv3** / 素材 **CC-BY-SA + CC0 双许可** | **只抄数据 schema 设计，不抄代码/素材**（GPL 传染 + 素材 BY-SA 需署名同授，商用儿童 App 有合规成本） | 🟡 schema 参考 |
| **OpenMon MCE**（怪物捕捉引擎） | Unity 6 / UE5 | 自述 production-grade framework | 引擎不适用（Unity/UE），但其**数据驱动设计理念**（species/technique/economy 分文件）印证我们的 dex/moves/elements JSON 方向 | 🟢 理念印证 |
| **harvest-moon-phaser3-game**（mimikim） | **Phaser 3 / JS** | GitHub 页未标 license（默认保留版权） | **同技术栈的农场参考**：种植/能量/日循环的实现读法；只学思路不复制代码（无许可证不可商用） | 🟡 读码学习 |
| **camping-trip**（本地 prj-ref） | LÖVE 2D / Lua | MIT | **最贴近我们气质的参考**：415 行 camp_world（小世界/日夜/氛围）、cook_brew/fish 等微玩法拆分、上下屏=主玩法+工具。每个玩法都是独立 lua 文件——与我们"每系统一 core 文件"同构 | 🟢 架构参考（MIT 可借鉴代码结构） |
| word-memory-map（已在用） | JS | 本地参考 | 词球捡投已移植 | ✅ 已落地 |

**总策略**：不引入任何游戏引擎/代码库依赖（保持零依赖原生 JS），**采 Tuxemon 的数据 schema 思想 + camping-trip 的微玩法拆分 + Phaser3 农场的交互模式**，全部用我们自己的实现——这与"资产和算法长期可复用"的第一原理一致。

## 3. Tuxemon schema → 我们的 dex.json（关键差距对照）

Tuxemon 每只怪一个 YAML（411 只），字段：`slug/species/types[]/moveset[{level_learned, technique}]/evolutions[{at_level, monster_slug}]/terrains/catch_rate/lower_upper_catch_resistance/shape/sounds`；每个招式一个 YAML（`power/accuracy/potency/recharge/types/effects`）。

我们的 dex.json 已有：`id/words[]/element/sprite/habitat/catchQuiz/evolution{to,requireWords,requireStars}`。**差距与升级**（P1-2 combat-core 落地时对齐）：

| Tuxemon 概念 | 我们的映射 |
|---|---|
| `types`（元素） | `element`（已有，五属性） |
| `moveset`（等级解锁招式） | 招式=复习题型；解锁按**图鉴星级**而非等级 |
| `catch_rate` + `catch_resistance` 区间 | `catchChance(hpRatio, mastery)` 已实现（0.05-0.95 钳制）；补"每怪个性 resist 修饰"字段 |
| `evolutions[at_level]` | 已有 `requireWords/requireStars`（学习版进化，比等级更有教育意义——保持） |
| `terrains`（栖息地） | 已有 `habitat` |
| `sounds.combat_call` | 词的静态发音（已有 audio 索引） |

## 5. 与现有系统的接法（不推倒重来）

所有新玩法**挂进既有循环**，不改核心引擎：
1. 剧情数据（G1 产出）→ `game.js` 大地图按 acts 渲染三站（站=既有玩法）——**数据接法**，非新引擎；
2. 对战数值 → combat-core 的元素克制/捕捉，在 battle.js 结算处调用（battle.js 现由并行会话迭代，改动收敛到"结算插桩"一处）；
3. 词田 → 已上线的浮层加 tileset 背景与收获演出；
4. 进化 → 图鉴页仪式（已落地）→ 进化形态立绘走 P3 生图批次。
