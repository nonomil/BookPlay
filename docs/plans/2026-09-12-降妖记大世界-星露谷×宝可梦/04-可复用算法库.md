# 04 可复用算法库设计（B 层）

> 铁律：纯逻辑 / 无 DOM / 无存储 / 数据驱动 / `node:test` 全覆盖 / IIFE 双暴露。命名 `BookPlay<Name>Core`。每个库独立可被 grok-build 委派实现。

## 1. combat-core v2（回合制对战引擎）

```js
BookPlayCombat = {
  createBattle({ player, enemy, elements, moves, rng })   // → battle{id,turn,log[]}
  availableMoves(battle, side)                             // 招式=题型注册表过滤（冷却/体力）
  resolveTurn(battle, moveId, answer)                      // 玩家招→命中判定(答案对错×克制)→事件入 log
  enemyTurn(battle)                                        // 效用 AI：血量/克制/冷却评分选招
  applyEvents(battle, events, ui)                          // UI 只消费 log 增量（pet-battle 模式）
  result(battle)                                           // {win, expGain, catchable, events}
}
```
- **事件日志是唯一表现数据源**：`{actor, side, move, hit, mult, dmg, hp, faint, catch}`——UI diff 增量动画，逻辑/表现解耦（这是 pet-battle-template 侦察出的核心模式）。
- **克制矩阵** = `content/game/elements.json`：`{"water":{"strong":"fire","weak":"forest"}, ...}`，系数 1.3/0.75——调平衡改 JSON。
- **招式表** = `content/game/moves.json`：`{id, label, quizKind, power, cooldown, energyCost}`，quizKind 引用 lesson-core 题型注册。
- **AI**：效用 = 预期伤害×克制 + 击杀奖励 + 冷却惩罚，取最高分（20 行以内，可测试）。
- **答案正确性即命中**：`hit = answerCorrect`；mult = 招式威力 × 克制 ×（连击加成）。

## 2. schedule-core（日循环/体力）

```js
BookPlaySchedule = {
  today(saved)                       // 日切判定（本地日期）→ {newDay, carry}
  energyMax(queueCount)              // min(10, queue+4)：体力=复习预算
  spend(state, cost)                 // 扣体力，<0 拒绝
  settleDay(state, {harvests, visits}) // 日结算：作物生长/好感/连续天数
  streak(state, today)               // 连续坚持天数（好感档位输入）
}
```

## 3. economy-core（经济）

```js
BookPlayEconomy = {
  price(economyJson, itemId, "buy"|"sell")
  canAfford / pay / earn             // 纯账本，金币状态由调用方持有
  validate(economyJson)              // 物价自检（卖价<买价等），--check 用
}
```

## 4. collection-core（图鉴/进化）

```js
BookPlayCollection = {
  unlockable(dexJson, mastery)       // 哪些怪"可捕捉"（绑定词已 mastered）
  register(dexState, dexId, {stars}) // 捕捉入图鉴（幂等）
  evolutionReady(dexJson, dexState)  // 进化阈值判定 → {to, missing}
  completion(dexJson, dexState)      // 图鉴完成度（图鉴页/勋章联动）
}
```

## 5. 复用关系图

```
lesson-core(题型) ─┐
review-queue(错词) ─┼→ combat-core(v2 对战) ←─ elements/moves.json
battle-core(判定) ─┘
schedule-core ← 本地日期；→ economy-core ← economy.json
collection-core ← dex.json；→ review-queue(捕捉前置=词掌握)
```

## 6. 测试基线纪律

每个库 ≤200 行/库先写测试后实现（TDD 红→绿）；新库测试并入 `npm test` 基线只增不减；grok-build 委派时验收命令必须含 `npm test` 全量。
