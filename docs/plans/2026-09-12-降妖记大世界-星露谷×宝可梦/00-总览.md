# 降妖记·大世界（星露谷 × 宝可梦）· 总览

> 2026-09-12 立项。把降妖记从"单词跑酷"升级为**星露谷式生活循环 × 宝可梦式收集对战**的长线游戏，服务一个终局目标：**孩子每天主动回来，间隔重复由游戏循环天然承载**。
> 上游：`docs/plans/2026-09-06-西游记降妖记-大地图探索版/`（v2 大地图已落地）、`docs/handoff/005_…`（T03–T11 未完成项全部吸收进本计划 P0）。
> 用户要求：第一原理思维、长期主义复利；资产与算法长期可复用；人物模型直接复用既有四向精灵或按规范生图接入；可调用 grok-build 套件做并行实现。

## 0. 一句话架构

**四层复利栈**：D 管道（生图SOP/打包/E2E钩子）→ C 数据（关卡/图鉴/词库，派生零代码）→ B 算法（combat/schedule/economy/collection 纯逻辑库）→ A 玩法（星露谷日循环 × 宝可梦对战）。**新增一集的成本 = 数据条目 + 资产生成，零引擎代码。**

## 2. 工程约定（继承 + 强化）

- 继承 005 全部禁区：测试只增不减（当前基线 446）、两条游戏存储键向后兼容、content/game 手写源保护、三白名单同步、不覆盖并行未提交改动。
- **新增算法库铁律**：纯逻辑（无 DOM/无存储）+ `node:test` + IIFE 双暴露（`module.exports` + `window.BookPlayXxx`）+ 数据驱动（克制矩阵/物价/进化阈值全部 JSON，不改代码可调）。
- **资产接入铁律**：新资产 = `assets/generated/jttw-game-sprites/` 按规范生图（03 文档 §管线）→ 注册表 `sprites.json`/`dex.json` 登记 → 三白名单 → 引擎零改动。
- **复利检查**（每个任务完成前自问）：本次产出是否同时进入 A 资产/B 算法/C 数据/D 管道 四层之一？只服务一次性效果的实现要说明为什么值得。
- grok-build 套件：有界实现任务（如"写 combat-core 的克制矩阵模块+测试"）可用 `<bridge> create` 委派 Grok 并行执行（委派合同=目标/写集/验收/禁区，见 05 文档 §并行执行）。
