# 00 产品定位与为什么

> 先理解 BookPlay，再谈降妖记。降妖记不是仓库里的第二个产品。

## 产品是什么

BookPlay 要把书戏品牌那种「英文原著剧本 + 扮演推进」做成可玩的故事。落地后的**当前产品**是：

**离线优先的《西游记》英语学习播放器** + 内容流水线。  
旗舰路径是逐句视频/绘本，不是传统动作游戏引擎。

```
绘本/视频（书）
  → 知识巩固（测刚学的词）
    → 降妖记（用刚学的词去玩）
```

早期 PRD 把形态落在「带数值与收集的视觉小说」，并写过「不做实时移动」。那是 2026-08-29 草案。后续产品已经在巩固之后叠了俯视大地图；**实时移动是复习环节，不是主课。**

## 给谁用、在什么设备上

| 项 | 口径 |
|---|---|
| 用户 | 约 7 岁英语学习者 + 家长；无账号、无云同步 |
| 场景 | 课后一集：看/听 → 巩固  → 可选游戏 3–5 分钟 |
| 设备 | 同一套 HTML/JS：桌面浏览器、Android **mobile / tv / handheld** |
| TV | 十英尺横屏、D-pad、OK；新页必须接 `tv.css` + `tv-remote.js` |
| 离线 | 手机不在线合成 TTS；音频预生成入库；漏打包 = 真机静默无声 |

## 「书」和「戏」为什么这样接

书戏素材本质是对话剧本。差异化不在「再做一个 AI 绘本」，而在：

1. 学的词 = 考的词 = 玩的词（同源，不另开词表）  
2. 巩固已经完成认和测；游戏是**第三次把词用掉**  
3. 游戏可跳过，失败不改学习 `passed` / `done`  
4. 挂在**本集节点**上，不是 App 里另开小游戏中心

所以入口有三条，落到同一个 `game.html?ep=N`：

- 巩固结束：「进入降妖记 / 暂时跳过」（`from=lesson`）  
- 绘本地图节点「⚔️ 打怪」  
- Boss 结算返回（`from=battle`）

## 为什么一套引擎、七集共用、开箱只带第 1 集

- 玩法相同，只换主题图、角色皮、词库。复制 `game-ep8.js` 会把诊断噪声放大。  
- c01 = 石猴出世到拜师学艺，第 1–7 集；6 张主题俯视图（3、4 集共用三星洞）。  
- APK 精简档单文件 <100MB，开箱只内置 ep1 当首发体验；ep2–7 靠导入 c01 数据包。  
- 先 ep1（花果山）和 ep5（混世魔王，手感主测）闭环，再铺其余集。

## 为什么学习发生在匹配里

大地图再弹快卡 = 第二张巩固页，和 lesson 重复，也破坏 word-memory-map 的「走、捡、扔」。  
三遍学习：中文球对英文怪 → NPC 听一句选意思 → Boss 选英文词打血条。

## 版权与内容红线

- 个人使用优先；`data/` 西游记 PDF/MP3/视频可用  
- 不复制书戏门店剧本原文  
- 公开分发另议，不挡当前开发  
- 未成年人内容边界：无过度暴力表现；打击感应保持卡通
