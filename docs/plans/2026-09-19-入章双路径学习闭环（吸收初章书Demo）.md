## 1. 第一性原理：孩子为什么卡在入章

Demo 作者的用户研究给了四条卡点（这是免费的真实市场调研，比任何竞品分析都值钱）：

| # | 卡点 | 第一性归因 |
| --- | --- | --- |
| 1 | 听得懂，但自己读不下来 | 儿童听力理解天然**领先**解码能力，听力是更低的入章台阶 |
| 2 | 单词认识，但一长就读得很慢 | 解码是逐词的，工作内存被解码吃光，没有余量做理解 |
| 3 | 逐词翻译，读完一段不知道什么意思 | 句子被拆散成词→中文的映射，丢失了**意群**和**主线** |
| 4 | 家长不知道该讲多少、怎么带 | 家长是真正的运营者，没有诊断就没有下一步，没有下一步就弃用 |

**推导出的产品根本任务**：不是更多单词、更多题型、更多奖励——是让孩子获得
「**抓住故事主线并用自己的话输出**」的能力，并且让家长**看得见**孩子卡在哪、下一步练什么。
词汇和测验只是这条主线的副作用。

**BookPlay 资产盘点**（探索结论，证据见 §8）：

| Demo 的环节 | BookPlay 现状 | 差量 |
| --- | --- | --- |
| Watching Path 看故事 | `wala.html` 剧情/精学两遍制、卡拉OK逐词高亮 | ✅ 已有且更强 |
| Listening Path 听力入章 | `listen-mode.js` 磨耳朵（循环/纯音频/休息卡） | ✅ 引擎已有，**但没有作为「路径」组织** |
| 任务前置（Who/Where/What） | ❌ 无 | 缺一张前置任务卡 |
| GUIDE 学方法（抓主线/意群阅读） | ❌ study 模式插词卡和题，但**从不教方法** | 缺「方法卡」资产类型 |
| PRACTICE 练一练 | `lesson-words.html`、降妖记 | ✅ 已有且更强 |
| CHECK 理解挑战 | `lesson.html` 每集测验、随堂题 | ✅ 已有；缺「首答」口径 |
| OUTPUT 说出故事 | `dub.html` 逐句跟读配音 | 半个：跟读是复读，**缺复述（生成）** |
| 双路径分流 | 听力/阅读是并列入口，全靠家长手调设置 | 缺分流引导 |
| 家长诊断「卡在哪/下一步」 | 词级对错、测验 answers、弱词表**都存了**，但无聚合报表、无建议 | 数据有、显性化无 |

**结论**：BookPlay 已拥有实现这个 Demo 所需的约九成底层资产。真正的差量不是新引擎、新内容，
而是两件「显性化」：**教学法的显性化**（任务→方法→输出，让孩子看见路径）和
**诊断的显性化**（让家长看见卡点）。这恰好是 Demo 比我们强的地方，也是我们比 Demo 强的地方
（108 集内容管线、游戏闭环、数据底座）的反面。两边互补，吸收成本很低。

## 2. 吸收清单：七件值得偷的，两件不偷的

| # | 吸收点 | Demo 做法 | BookPlay 落法 | 复利性质 |
| --- | --- | --- | --- | --- |
| A | **同一故事双路径** | CHOOSE YOUR PATH：听力入章 vs 阅读入章，同一本书两种学法 | map 详情卡升级为双路径卡：听力卡→`wala?mode=listen`，阅读卡→`wala` 精学；显示「已到第 N 步/继续上次学习」 | **框架复利**：以后 Minecraft/Mikey&JJ 系列直接复用 |
| B | **任务前置** | A LITTLE MISSION：看之前给三个问题 Who? Where? What happened? | wala 开播前插一张任务卡（听力/阅读文案不同），看完轻轻回扣 | **资产复利**：任务卡进 schema，管线派生 108 集 |
| C | **GUIDE 学方法** | 「别追每个单词，先抓人物地点动作」「意群=谁/做了什么/和谁」 | 方法卡库（先手写 5–10 张通用策略卡），study-plan 按集编排插入 | **资产复利**：一次写，全书用 |
| D | **OUTPUT 复述** | 四图排序→看图说故事（听）；句子配图→连读（读） | dub 加 `mode=retell`：图片序列排序 + 录音 + 放映厅；复用 `dub-recorder` | **能力复利**：输出是理解唯一的显影剂 |
| E | **降焦虑文案体系** | 「不暂停、不查单词、不必听懂每一句」「答错也可以继续探索」「A LITTLE EVERY DAY」 | 直接借鉴话术，统一到任务卡/测验页/等待页；符合 7 岁口径 | 品牌资产，零成本 |
| F | **首答口径** | 「记录首次作答·答错也可以继续探索」 | 测验/随堂题记录 first-attempt 对错，重试不改写；诊断才有干净的信号 | **数据复利**的前提 |
| G | **家长四问诊断** | ①哪条路径 ②卡在哪 ③怎么学 ④下一步练什么 | 家长报告页：聚合已有 localStorage 数据，输出本周轨迹+卡点+下一步建议 | **数据复利**：每多学一集，诊断越准 |
| ✗ | 不偷：再做视频播放器 | Demo 的 WATCH 只是普通播放器 | 我们的字幕卡片流已领先两代 | — |
| ✗ | 不偷：一天一课的「课」结构 | Demo 按单本书组织 | 我们按 108 集连续剧+合辑组织，密度更高；只吸收它的 session 长度提示（15–20min） | — |

## 3. 复利判断：什么越用越值钱

**复利资产（优先做）**：
1. **学习事件数据 + 诊断**——每节课都在让「下一步建议」更准。这是产品的时间护城河。
2. **内容 schema 与派生管线**——任务卡/方法卡/复述提示加进 schema 后，
   由 `prj/tools/build_*.py` 派生到 108 集，一次建管线全库受益
   （和 `build_game_levels.py` 同一哲学：手写一份，派生一百零八份）。
3. **多系列复用框架**——双路径/任务/方法/复述一旦在 jttw 跑通，
   Minecraft、Mikey&JJ 换内容不换引擎，边际成本趋零。
4. **家长信任**——家长四问被回答的那天，续用率的问题就解决了大半。

**消耗品（明确不做，见 §6）**——皮肤、勋章、题型数量、游戏动词，都是一次性支出，
不随使用变值钱。降妖记玩法已冻结合同，本方案不碰。

## 4. 实施计划：四个切片 + 一个开关

每个切片独立可发布、独立可验证；顺序即优先级（测量先行，没有 P0，后面全是猜）。

### P0 学习事件日志 + 家长报告（最小诊断闭环）★最高优先
> **实施记录（2026-09-19）**：已落地。`prj/engine/step-log-core.js`（纯逻辑：normalize/append/summarize/suggest）+
> `step-log.js`（静默落盘 `bookplay_step_log_v1`，环形 400 条）；wala（watch enter/finish/quit，听力/阅读路径区分）、
> lesson（practice/check enter/finish/quit）、dub（output enter/finish）、drill（drill enter/finish）全量埋点；
> 新页 `parent-report.html`（入口：地图设置菜单），建议规则 5 条先写死；已入 `pack_android.py` 白名单。
> 全仓 550 测试通过 + 无头渲染冒烟通过。待真机验证。
- **意义**：Demo 作者宁可停下来找真实测试者，也不闷头加功能——因为「哪一步最容易卡」
  没有答案之前，一切功能都是赌。BookPlay 数据都有，就差一本账。
- **改哪里**：
  - `prj/engine/storage.js`：新增 `bookplay_step_log_v1`（环形，保留最近 N 天）：
    `{ts, ep, path: listen|read, step: watch|guide|practice|check|output, event: enter|finish|quit|first_answer, payload}`；
  - `wala.js / lesson.js / lesson-words.js / dub.js / drill.js`：各埋 3–5 个关键事件；
  - 新页 `parent-report.html`（或扩展 `parent.html` 加 tab）：本周看了哪些集、每步完成/放弃点、
    错词 Top5、一句话建议（规则引擎先写死 5 条）。
- **验收**：模拟一次「听力路径看到第 3 步退出」，家长页能准确指出停在哪一步。
- **注意**：新页面要同步 `prj/tools/pack_android.py` 的 `ENGINE_FILES` 白名单，否则 APK 里没有。

### P1 双路径入口 + 任务前置（吸收 A、B、E）

> ② wala 开播前任务前置卡（三问 Who/Where/What happened + 路径差异化降焦虑规则 + 点击才开始不自动播，
> 回顾模式跳过）；听力完成卡与剧情遍完成卡各加三问回扣（「小挑战：用自己的话说说发生了什么」）；
> ③ **修复一个回归**：content-gate 全局点击拦截（capture）抢在地图卡片监听器之前导航，
> 详情弹层完全打不开——`data-detail` 锚点现跳过内容门，详情层内部链接仍受保护（含测试）。
> 浏览器端到端验证：地图→详情卡→听力入章→任务卡→磨耳朵第 1/2 遍；步日志正确记录
> `read/watch/quit`（中途退出）与 `listen/watch/enter`。全仓 559 测试通过。
- **意义**：承认孩子差异；同一集内容两种用法，是把内容资产翻倍的最便宜方式。
- **改哪里**：
  - `map.js` 详情卡（现「学习/磨耳朵/地图/配音/本辑巩固」五按钮）：重组为两张路径大卡
    「👂 听力入章 / 📖 阅读入章」+ 小按钮行；卡上显示进度（`bookplay_adv_progress` 已有数据）；
  - `wala.js`：开播前插任务卡（听：不暂停不查词，只想 Who/Where/What；读：不逐词翻译，找主线）；
    结束页按路径回扣三问；
  - `listen-mode.js`：任务卡文案接入；路径标识写进 step log。
- **验收**：从地图进听力路径全程不需要碰设置面板；中途退出再进，能「继续上次学习」。

### P2 方法卡 GUIDE + 首答口径（吸收 C、F）
> **实施记录（2026-09-19）**：已落地。
> ① 全局策略卡库 `content/strategy_cards.json`（8 张通用卡：抓主线/意群阅读/看图猜词/出声跟读/找证据/听大意/
> 故事排序/大胆复述），一条内容进三处打包白名单（datapack INCLUDE_DIRS + COMMON_FILES、APK DATA_DIRS）——
> 手写一份、全系列复用；② `study-plan.buildGuidePlan`：确定性选位（避开随堂题节点、首卡靠前、
> lite 1/标准 2/加强 3 张、按库顺序轮转）；③ wala 精学模式新 guide act：方法卡排在词卡之前
> （先学方法再练习），一集内每张卡只出一次，「知道了，继续故事」收卡自动续播（与内嵌小测同款
> inlineQueued 契约）；④ 首答口径：lesson 会话新增 `firstAttempt`（重置测验时归档上一轮，只归档一次
> 不改写），`lesson-core.normalizeStudySession` 透传。浏览器验证：精学模式方法卡正常弹出/收卡/续播，
> 顺带修复策略卡在浅色字幕容器上的对比度问题 + strategyPack 未声明的启动阻断 bug。
> 全仓 567 测试通过。
- **意义**：从「插题」到「教方法」——孩子背下来的不是答案，是可以带走的阅读策略。
- **改哪里**：
  - `prj/engine/study-plan.js`：新增 `guide` 卡类型，从策略库按集特征挑选；
  - 策略库先手写 5–10 张通用卡（抓主线三问、意群阅读、看图猜词、回读找证据），
    放 `content/strategy_cards.json`（全局，不逐集复制——复利原则）；
  - `wala.js` 渲染方法卡（同词卡轮播位）；`lesson-core.js` answers 数组加 `attempt: first|retry`。
- **验收**：精学模式中每集至少出现 1 张方法卡；测验重做不改写首答记录。

### P3 复述输出 OUTPUT（吸收 D）
- **意义**：配音是复读机，复述是生成——入章能力的试金石是「合上书讲出来」。
- **改哪里**：
  - `dub.html` 加 `mode=retell`：取本集 4 个关键场景图（`content/assets` 现有插画）→
    排序（复用 `dialogue_stories` puzzles 的排序交互）→ 逐图录音 → 放映厅连播；
  - 录音复用 `dub-recorder` + IndexedDB，奖励幂等复用 dub 奖励机制；
  - `content/dialogue_stories/epN.json` schema 加 `retell_scenes[]`（管线派生）。
- **验收**：ep1 能完成排序+录音+回放全流程；产物在家长报告可见。

### P4 诊断路由「下一步练什么」（吸收 G 的后半）
- **意义**：回答 Demo 四问的最后一问；也是 P0 数据开始产生复利回报的时刻。
- **改哪里**：规则引擎（纯逻辑，进 `lesson-core.js` 或新 `coach-core.js` + `.test.mjs`）：
  输入 step log + 首答数据 → 输出「推荐路径 + 薄弱环节 + 下一动作」；
  家长报告页与 map 详情卡消费同一份建议。
- **验收**：三条典型画像（听力强/解码强/双弱）产出不同且合理的建议。

### 精益验证关卡（开发流程本身的改变，借 Demo 作者的流程）
- 每个切片做完 → **真机验证 + 真实孩子验证**，再进下一片；
- 验证问题固定四条（借 Demo）：孩子愿不愿意学完？哪一步最容易卡？两条路径有没有实际差异？
  家长用完是否更清楚孩子的问题？
- **P0 完成后先停一次**：拿真数据回答「哪一步最容易卡」，用数据决定 P1–P4 的顺序是否调整。
  这条是本方案从 Demo 学到的最重要的一件事：功能为验证服务，不为进度服务。
