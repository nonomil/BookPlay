# 05 · 技术支撑：recorder-core 兼容回退 与 Demucs 伴奏轨

> 本文件是两个独立技术项，均服务于趣配音。5a 可单独执行；5b 是 P3 数据包项目，需真实素材加工，不在纯前端会话内完成。

## 5a · 录音兼容回退（vendor recorder-core）

### 背景

`dub-recorder.js` 用原生 MediaRecorder，输出 webm/opus。老安卓 X5 内核与部分 WebView 不支持 webm 播放或 MediaRecorder 缺失。[recorder-core（xiangyuecn/Recorder）](https://github.com/xiangyuecn/Recorder) 单文件、零依赖、输出 mp3（播放兼容性最好），明确支持 Android WebView/X5。

### 设计

- vendor 引入：`prj/engine/vendor/recorder-core.mp3.min.js`（从 npm `recorder-core` dist 拷贝，记录版本号与来源到 `vendor/README.md`；许可证为 MIT，允许再分发，保留其头注释）。
- `dub-recorder.js` 改造（保持合同不变）：
  - `capabilities()` 增加 `engine: "media-recorder" | "recorder-core" | "none"`；
  - 选 engine 顺序：MediaRecorder 可用且 `isTypeSupported` 命中 webm;opus/webm → media-recorder；否则全局存在 `Recorder`（vendor 加载后）→ recorder-core（mp3）；都无 → none；
  - recorder-core 分支：`Recorder({ type:"mp3", bitRate:64, sampleRate:16000 })`，`start/stop` 回调包装成既有 `{ok, blob, mime, sec}` 合同；`stop` 后 `destroy()` 释放；
  - `dub.js` 页面按 `capabilities().engine === "none"` 决定隐藏录音（现状不变），无需大改。
- 加载策略：`dub.html` 增加 `<script src="vendor/recorder-core.mp3.min.js" defer>`？——否：直接普通引入（文件约 100KB，仅配音页加载）。vendor 文件**不引入 node 测试**，测试用注入假构造器覆盖分支。
- 测试：`dub-recorder.test.mjs` 增加 engine 协商用例（假 `env.Recorder` 存在且 MediaRecorder 缺 mp4/webm 时选 recorder-core；recorder-core 分支 start/stop/destroy 调用时序；错误映射 not-allowed/no-mic）。

### 验收

- [ ] `npm test` 全绿；`node --check` 通过。
- [ ] `android:prepare` 后 `dist/engine/vendor/` 存在且 dub.html 引用路径正确。
- [ ] 真机（老安卓/X5 若有）：录音产出 mp3 且能回放（列入验收报告"真机待验"）。

## 5b · Demucs 伴奏轨（P3，"背景音乐不变、旁白换成孩子"）

### 背景

放映厅目前是"压原声 0.15"的卡拉OK混音。用 [Demucs](https://github.com/facebookresearch/demucs)（[UVR 同源](https://github.com/ultimate-vocal-remover)）离线分离整集音轨 → 伴奏轨 `assets/dub_bgm/ep{N}.mp3`，放映厅切"纯伴奏模式"：video 静音 + 伴奏轨 + 孩子人声，实现背景不变、旁白全换成孩子。

### 设计要点（执行时展开为正式任务）

1. 离线批处理脚本 `scripts/build_dub_bgm.py`：`python -m demucs -n htdemucs --two-stems=vocals -o out_dir assets/lf_ep*/audio_ep*.mp3`，取 `no_vocals` 轨转码 mp3（ffmpeg），落到 `assets/dub_bgm/ep{N}.mp3`；带 `--ep 1-10` 分段参数与断点续跑。CPU 约 5-15 分钟/首量级，先跑 3 集抽检人耳验收（旁白残留、BGM 损伤），合格再批量。
2. 运行时：`dub.js` 放映厅检测 `assets/dub_bgm/ep{N}.mp3` 存在（HEAD fetch）→ 显示"🎵 纯伴奏"开关；开启后视频 muted + audio 元素播伴奏 + 配音轨并行（三轨对齐以 `audio_start` 为基准，不追求采样级同步）。
3. 数据包：`prepare-mobile.mjs` 目前不拷 `assets/`（数据包脚本负责）；需确认 `打包数据包.bat` 对应脚本把 `assets/dub_bgm` 纳入清单并**跳过未生成的集**。
4. 存储/合同无变化；开关记忆 `bookplay_dub_bgm_v1`（可选）。

### 风险与边界

- 口语旁白非音乐人声，分离质量需抽检（模型以音乐训练为主）；不合格的集不启用伴奏模式（按集白名单 `assets/dub_bgm/index.json`）。
- 体积：每集约 6 分钟 mp3 ≈ 3-6MB × 108 集 ≈ 400-600MB，**只纳入 APK 外置数据包或按需下载**，不进 engine 目录。

### 验收

- [ ] 批处理脚本可断点续跑，抽检 3 集人耳合格并记录到报告。
- [ ] 放映厅伴奏模式在已生成的集可用，未生成的集不显示开关。
- [ ] 数据包体积增量记录在报告，未超预算。
