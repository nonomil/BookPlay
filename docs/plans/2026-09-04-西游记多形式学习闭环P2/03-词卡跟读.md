# 03 · 词卡跟读（把"单词跟读"挂进播放器词卡）

## 目标

现在跟读只在巩固页（lesson/drill 的可选跟读卡）。本特性把跟读入口挂到 wala 播放器的"新词·学习"词卡上：点词卡上的 🎤，听示范→开口跟读→听到判定反馈。不需要跟读也完全不影响原流程（沉默期友好）。

## 现状与数据基础

- `wala.html` 目前**未引入** `voice-core.js/voice.js`（`lesson.html:64-70` 才有）。`wala.js` 词卡：`renderCard(card)`（`wala.js:741` 附近）分 learn/test/review 三种，已有 `.vspk`（播放示范）按钮与 `playSeq(termItems(...))`。
- `voice.js` 的 `WalaVoice.create({ env, endpoint })` 提供 `capabilities()/listen(referenceText)` 类链路；`voice-core.js` 的 `matchReference/feedbackFor` 输出 match/partial/mismatch 与中文反馈文案。`lesson.js:64-65` 是现成装配范例。
- 电视版无麦克风：`capabilities().mic` 为 false → 整个入口隐藏。

## 产品设计

- 仅在 **learn（新词·学习）** 卡上加一个 🎤 按钮（test/review 卡不加，避免测试环节被打断）。
- 点击流程：播放词示范音（现有 `termItems`）→ 按钮变"听你说…"→ Web Speech 收音 → `feedbackFor` 文案显示在词卡底部一行（`aria-live`）："听到了，跟读成功！" / "再说完整一点" / "没有听到声音，再试一次"。
- 最多连点 3 次后按钮休息（防止孩子反复挫败），2 秒后恢复。**不落盘、不发 SP、不记错题**——跟读是热身不是考试。
- 失败全部静默降级：不支持/拒权/网络错误 → 按钮隐藏或提示"这台设备不能跟读，听老师读也很好"。

## 技术设计

| 文件 | 改动 |
|---|---|
| `wala.html` | `<head>` 引入 `voice-core.js?v=1`、`voice.js?v=1`（在 wala.js 之前）；`wala.js?v=72` |
| `wala.js` | 顶部装配单例 `voicePort = WalaVoice.create({ endpoint: voiceSttQuery })`（同 lesson.js）；`renderCard` 的 learn 分支：`micReady` 时插入 `.vread` 按钮；点击 → 播示范 → 收音 → 反馈行；状态机与清理（连续次数、未返回前禁点） |
| 新 `wala-word-read.test.mjs` | 静态合同：wala.html 引入顺序（voice-core → voice → wala.js）；wala.js 含 capabilities 探测守卫（无麦克风不插入按钮）、反馈走 `WalaVoiceCore.feedbackFor`、无 localStorage 新键、无 eval |
| `wala.css` | `.vread` 按钮与反馈行样式（复用 .vspk 尺寸） |

**明确不做**：不打分、不保存录音、不写任何存储键、不改词卡学习/测试/复习的既有逻辑与配额。

## 验收清单

- [ ] `npm test` 全绿；node --check 通过。
- [ ] 浏览器（Chrome 桌面，允许麦克风）：learn 卡出现 🎤，跟读命中显示成功文案；test/review 卡无此按钮。
- [ ] 拒权场景：按钮消失或降级提示，词卡其余功能不受影响。
- [ ] 剧情/精学两遍制、磨耳朵模式下按钮不出现或不可点（跟读仅在词卡展示时）。
