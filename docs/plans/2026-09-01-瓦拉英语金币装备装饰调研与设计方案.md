# 瓦拉英语：学习币、装备、伙伴与房间装饰设计方案

状态：备选经济方案（已降级）；当前 MVP 以 `docs/调研/2026-09-01-儿童学习奖励与房间装饰-分析报告与方案.md` 为准，不等于业务代码已上线。

日期：2026-09-01（中国标准时间）

相关证据：`output/research/2026-09-01-gamification/report.md`、`sources.json`、`claims.json`。

## 1. 先给结论

> **MVP 口径覆盖：** 评审已确认当前不做云朵币/票券商店。本文第 4、5 节的货币、商店和装备闭环保留为 P2 备选实验，不能在 P0/P1 接入学习路径。当前实现应采用“首次巩固达标 → 3 选 1 → 角色房间”的直接掉落方案。

瓦拉英语值得加入“学习 → 获得 → 看见 → 选择 → 回到学习”的轻量闭环，但不值得现在搬入完整宠物积分系统。

首版采用四个明确边界：

1. **备选一种货币（暂不实施）**：儿童文案叫“云朵币”（内部键建议 `bookplay_wala_coin`），可用于后续外观和场景装饰实验；现有 `bookplay_sp` 继续是答题即时反馈，不与云朵币混账。
2. **一个伙伴入口**：通用瓦拉英语显示豆豆龙的“小屋”；进入西游记系列时复用同一壳层，伙伴换成小白龙/白龙马的“驿站”，但伙伴状态和物品按 `series` 隔离。
3. **固定槽位**：首版 12–20 件物品，MVP 通过巩固达标后的 3 选 1 直接获得；房间先用 5 个固定槽位，不做自由拖拽和复杂家具碰撞。商店购买属于 P2 备选。
4. **学习优先**：奖励只在完成有效学习里程碑后结算，短庆祝、不打断、不惩罚；装备纯外观，不改变正确率、题目难度、课程解锁或伙伴基本照料。

一句话体验（当前 MVP）：孩子完成一集巩固后，从 3 件剧情相关物品中选 1 件，立刻放进伙伴房间，然后自然回到下一关。云朵币购买链路留作后续实验。

## 3. 现有瓦拉入口与接入边界

### 3.1 当前真实消费者路径

`wala.html` 目前有四个 screen：

- `#wala-map`：冒险地图，顶部显示现有 SP、知识一览、磨耳朵和绘本馆；
- `#wala-player`：一句一拍播放器，剧情/精学模式、字幕、词卡、小测和 SP；
- `#wala-review`：单词/句型/错题回顾；
- `#wala-end`：章末小测和进入知识巩固。

`wala.js` 通过 `WalaStorage` 读写 `bookplay_adv_progress`、`bookplay_adv_vocab_stat` 和 `bookplay_sp`；答对题目在多个入口用 `+10 SP`。因此：

- 云朵币不能复用 SP 的数值，否则答题、勋章和购买会互相放大；
- 章末、完成一组有效学习或首次完成活动是更适合结算云朵币的边界；
- 入口应从地图顶部和章末卡片可达，不能只放在播放器内。

### 3.2 系列与伙伴命名

| 场景 | 伙伴 | 空间名 | 说明 |
|---|---|---|---|
| 通用瓦拉英语 | 豆豆龙 | 豆豆龙云朵小屋 | 沿用现有品牌角色，承担老师/伙伴双重入口；不把老师变成“可购买的宠物” |
| 西游记系列 | 小白龙 → 白龙马 | 白龙马驿站 | 伙伴就是《西游记》中的小白龙，后来化作白龙马；龙蛋/幼龙属于儿童向成长想象，需标注“想象阶段” |

共享的是账本协议和 UI 壳层，不共享主题物品、阶段解锁和房间摆设。孩子不会因为在西游记买了云宫旗帜，就在通用瓦拉小屋看到不相干物品。

## 4. 云朵币经济设计（P2 备选，暂不实施）

### 4.1 货币原则

- 只存在一种可消费货币：云朵币；不设置付费币、兑换比例、负余额或每日衰减。
- 所有奖励必须有 `grantKey` 幂等键；重复打开章末页、刷新页面、重复答同一题不能重复结算。
- 云朵币只买外观/玩具/背景；伙伴成长主线和课程解锁不花币。
- 余额、来源和最近流水可在家长视图查看，孩子端只显示易懂的图标和整数。

### 4.2 建议奖励表

| 行为 | 云朵币 | 结算边界 | 幂等键示例 |
|---|---:|---|---|
| 完成一个新的有效活动（句型卡、单词卡、小游戏） | 1 | 活动完成事件 | `activity:{series}:{activityId}:done` |
| 完成本集剧情播放 | 3 | `saveEpisodeProgress(..., done=true)` 首次转为 done | `episode:{series}:{ep}:complete` |
| 完成本集知识巩固 | 5 | 通过门槛写入巩固完成状态 | `review:{series}:{ep}:pass` |
| 完成一个篇章（建议 6 集一组） | 8 | 篇章完成庆祝卡 | `chapter:{series}:{chapterId}:complete` |
| 连续 3 个不同学习日 | 2 | 第 3 个有效学习日，不追求无限连签 | `streak:{series}:{yyyy-mm-dd}:3` |

建议每日自然上限 30 云朵币；达到上限后仍可继续学习、获得勋章和伙伴同行日，只是不再刷货币。漏学不会扣币、不掉级、不让伙伴生病。

### 4.3 SP 与云朵币的分工

- SP：保留当前“答对即刻 +10 SP”反馈，服务即时成就和现有兼容性；
- 云朵币：只在上述里程碑发放，服务装备和房间；
- 勋章：证明长期成就，不重复发币；
- 小白龙阶段：由剧情/学习进度派生，不以余额作为门槛。

## 5. 商店、库存和装备（P2 备选，暂不实施）

### 5.1 商店信息架构

首版只显示三个标签：

1. **伙伴外观**：围巾、云纹护额、行囊、铃铛；
2. **小屋装饰**：云窗、莲花灯、书架、星河地毯；
3. **故事玩具**：云球、桃子、金铃、取经小旗。

每张物品卡包含：预览图、名称、价格、来源（“完成第 2 章解锁”或“云朵币 8”）、已拥有/已装备状态和一句 12 字以内的互动文案。没有稀有度、抽卡、倒计时或“错过就没有”。

### 5.2 数据合同（建议）

```js
// localStorage: bookplay_wala_coin_v1
{
  balance: 24,
  lifetimeEarned: 47,
  ledger: [
    { id: "episode:jttw:2:complete", amount: 3, reason: "episode_complete", at: 1788270000000 }
  ],
  owned: ["toy-cloud-ball", "outfit-west-sea-scarf"],
  equipped: {
    companion: "outfit-west-sea-scarf",
    room: { sky: "sky-night", wall: "wall-cloud", floor: "floor-river", toyRack: "toy-cloud-ball" }
  },
  seenRewardIds: []
}
```

物品目录（静态 JSON）建议字段：

```json
{
  "id": "outfit-west-sea-scarf",
  "series": "jttw",
  "slot": "companion",
  "name_zh": "西海小围巾",
  "price": 8,
  "unlock": {"type": "chapter", "id": "chap-01"},
    "asset": "prj/assets/generated/wala-gamification/clean/gear-parts/gear01_541x573.png",
  "interaction": "小白龙甩甩围巾，准备出发！"
}
```

### 5.3 消费规则

- 购买前显示“还差 X 云朵币”而不是灰掉整个按钮；
- 点击购买先预览，再二次确认；余额不足不扣币；
- 购买成功写入 `owned` 与一条 ledger，刷新后仍保持；
- 装备/卸下是免费且可撤销；
- 主题物品按 `series` 过滤，避免跨故事混乱；
- 未来如果要开放更多物品，只追加目录，不改变已购物品 ID 和价格。

## 6. 伙伴与房间玩法

### 6.1 房间固定五槽位

```text
┌────────────── 云朵小屋 / 白龙马驿站 ──────────────┐
│ sky（天空）       wall（墙面）                    │
│                                                  │
│             companion（伙伴外观）                │
│                                                  │
│ floor（地面）      toyRack（玩具架）              │
└──────────────────────────────────────────────────┘
```

固定槽位的好处是手机端容易理解、资产可复用、不会陷入拖拽坐标和碰撞调试。孩子想“摆房间”时，先提供五个大按钮；等真实使用数据证明需求，再开放拖拽。

### 6.2 轻互动

每个装备/玩具只绑定一个 1–2 秒的轻互动：

- 云球：小白龙/豆豆龙顶球一次；
- 金铃：铃响两下，出现一个英文词卡 `ring`；
- 书架：翻开一本已学绘本；
- 云窗：切换昼/夜背景；
- 行囊：展示本章已获得的勋章缩略图。

互动不是新的体力/饥饿系统，不设置失败、扣币或每日维护。

### 6.3 伙伴成长

通用豆豆龙：云朵小屋的装饰数量和已完成活动数只改变表情、动作和小台词。

西游记小白龙：继续沿用已有 7 阶段派生规则（神秘龙蛋 → 西海小龙 → … → 白龙马/腾云白龙/八部天龙）；云朵币只能购买外观，不能替代剧情解锁。阶段变化与勋章在章末合并成一次庆祝卡。

## 7. 页面落点与用户流程

### 7.1 地图入口

在 `#wala-map` 顶栏现有 SP 旁增加一个小型入口：

`🐉 伙伴 · 🪙 24`

移动端折叠为“伙伴”按钮，SP 仍保留在二级状态区。点击后进入 `companion.html?series=wala` 或 `companion.html?series=jttw` 的共享壳层。

### 7.2 章末入口

现有 `#wala-end` 的“本章完成”卡片增加一行：

`本章奖励：+8 云朵币 · 新玩具已放入玩具架`

按钮顺序：`继续知识巩固`（主）→ `去小屋看看`（次）→ `回选集`。默认不自动跳房间。

### 7.3 商店流程

```text
完成学习 → 1.5 秒奖励 toast → 可继续下一句
       ↘ 章末奖励卡 → 预览新物品 → 购买/稍后
地图/伙伴入口 → 小屋 → 商店 → 预览 → 装备 → 返回学习
```

同一时刻只允许一个奖励层；不要连续弹 SP、勋章、升级、掉落四个窗口。

## 8. 视觉资产计划（概念资产；当前 MVP 不接商店）

资产统一使用“西游水墨 + 儿童玩具质感 + 金色点缀”方向，避免照搬瓦拉品牌紫色皮肤。UI 文本由 HTML/CSS 渲染，生图只负责无文字插画/物件。云朵币、宝箱和商店概念稿仅保留作 P2 对照实验；P1 直接掉落使用伙伴、房间装饰和 3 选 1 选物卡。

| 资产 | 用途 | 尺寸/背景 | 文件名 |
|---|---|---|---|
| 云朵币图标 | 顶栏、奖励 toast、商店价格 | 透明 PNG（1254×1254，运行时缩放） | `prj/assets/generated/wala-gamification/cloud-coin-v1-alpha-v2.png` |
| 奖励宝箱 | 章末奖励卡 | 透明 PNG（1254×1254，运行时缩放） | `prj/assets/generated/wala-gamification/reward-chest-v1-alpha-v2.png` |

## 9. 分期与验收

### P0（本轮）

- 完成调研证据包和本设计合同；
- 生成首批视觉资产；
- 不改 `wala.html/js/css`，不改变现有 SP 和播放行为。

### P1（下一次实现）

- 新增 `episode-reward.js` 纯逻辑模块和 `episode-reward.test.mjs`；
- `episode_001` 首次巩固达标后打开 3 选 1，写入 `inventory.owned` 和花果山固定槽位；
- 在地图/章末增加“去房间看看”入口，默认焦点仍为“下一集”；
- 验收：重看/重做不重复掉落；刷新后物品仍在；旧存档无新键也能正常播放；房间能朗读物品英文名。

### P2（真实需求确认后）

- 若 P1 留存证明孩子会主动回房间，再评估固定五槽位小屋、12–20 件物品、伙伴轻互动；
- 若确有“想自己挑更多外观”的需求，再以实验开关启用 `bookplay_wala_coin_v1` 和商店闭环；
- 记录 7 天主动回访、装备率、奖励跳过率和错误率护栏；
- 只有孩子主动进入小屋、查看收藏、询问“还能买什么/能不能摆房间”时才扩充玩具架和主题。

### 明确不做

多宠物、抽卡、稀有度、排行榜、金币衰减、付费货币、战斗属性、宠物饥饿/清洁/死亡、强制连签、跨系列混装、在学习中频繁弹商城。

## 10. 指标与停止线

正向指标：完成学习后 5 秒内能找到奖励；奖励后继续学习率；章末“去小屋看看”点击率；选物后摆放率；7 日主动回访率。

护栏指标：答题正确率不下降；学习中途退出率不升高；奖励关闭/跳过率不过高；家长关闭音效/动效后不再强制播放；重复活动刷物次数为 0。

若 P1 只带来一次性弹窗点击、没有主动回访，停止 P2，不继续增加家具、商城和宠物状态。孩子喜欢养宠物是做“有陪伴的一个伙伴”的充分理由，不是把完整宠物积分系统搬进来的充分理由。
