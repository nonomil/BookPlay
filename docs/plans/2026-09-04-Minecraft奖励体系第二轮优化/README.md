# Minecraft 奖励体系第二轮优化实施计划

> **给执行者：** 必需子技能：使用执行计划技能逐任务实施此计划。

**目标：** 把《我的世界》前两本绘本的奖励闭环从“可用”收敛到适合 7 岁儿童的“看得懂、想继续、离线也可靠”。

**架构：** 保留现有“完成巩固 → 1 张故事贴纸 + 3 选 1 故事纪念物 → Byte 成长 → 小屋摆放”的核心，不引入金币、票券、商店、饥饿或死亡。第一轮先修正路线文案、页面层级和资源合同；第二轮补齐透明物件、Byte 反馈和奖励仪式；最后验证 Android 数据包与跨系列状态隔离。

**技术栈：** 原生 HTML/CSS/JavaScript、JSON 内容目录、Node 内置测试、Python 打包测试、Chromium 浏览器抽样。

---

## 设计决策

1. 两本绘本首屏保持两张大卡片；详情页可滚动，但图片优先。
2. 每本只发 1 张故事贴纸和 1 件三选一纪念物；逐页只给短暂动画/表扬，不发永久物品。
3. 勋章页只保留 3 枚 Minecraft 勋章的清晰墙面；不让“下一目标”和“最近获得”重复占首屏。
4. 探险日记暂不承诺不可见的项圈、床、夜灯；没有真实资产接入前隐藏或降级为无奖励的轻互动。
5. 故事场景图用于“故事证据”，透明 PNG 用于贴纸/房间收藏物，两者不混用。
6. `content` 是打包源，`prj/data` 是本地运行副本；任何新增资产必须两端同步并被 Android/数据包测试覆盖。

## 任务顺序与验收门

| 任务 | 责任范围 | 依赖 | 验收门 |
|---|---|---|---|
| T01 | Minecraft 文案、勋章墙信息架构、儿童化措辞 | 无 | 页面不出现错误单位；勋章首屏无重复大块 |
| T02 | 奖励资产字段、透明物件、房间呈现 | T01 | 物件图与故事图分离；房间摆放不被场景图撑爆 |
| T03 | Byte 成长、照料反馈、奖励仪式 | T01/T02 | 三阶段有明显差异；选择后有去小屋/下一本路径 |
| T04 | Android/数据包资源闭包、跨系列状态、回归测试 | T01–T03 | Node/Python 测试通过；离线资源完整 |

## 停止条件

- 奖励无法在指定绘本页或句子中找到来源；
- 生成图混入无关角色、攻击性武器、恐怖/血腥或文字水印；
- Minecraft 与西游存档互相覆盖；
- 页面视觉改动导致 320px 横向溢出或动效无法遵守 `prefers-reduced-motion`；
- Android 包仍缺少运行时引用的资产时，不宣称可发布。
