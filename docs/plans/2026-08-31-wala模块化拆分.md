# `wala.js` 模块化拆分实施计划

**目标：** 在不改变播放器行为、localStorage 契约、媒体路径和测验门禁的前提下，把 `wala.js` 中的存储、媒体、学习计划和测验核心逻辑拆成独立脚本。

**现状：** `prj/engine/wala.js` 为 74.6 KB、2011 行；它同时承担 DOM 编排、持久化容错、音视频状态机、词卡计划和测验归位。任一小改动都需要理解整文件，且纯逻辑无法独立测试。

## 模块边界

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| `storage.js` | 所有 `bookplay_*` 键、损坏 JSON 回退、设置归一化、进度/词频/SP 写入 | DOM 渲染 |
| `media.js` | 文本/音频索引归一化、TTS URL、视频地址与音视频序列控制 | 题目和学习计划 |
| `study-plan.js` | 分级学习量、首次出现词计划、词袋收集、掌握度判断 | 卡片 DOM |
| `quiz.js` | 题面 token、剧情题归位、复习题选项构造 | 题目 DOM 与得分动画 |
| `wala.js` | 页面状态、DOM 编排、模块协作 | 重复实现上述核心规则 |

## 实施顺序

1. 先增加四模块合同测试：默认值、损坏存档、媒体索引、三级学习计划、测验归位。
2. 创建 UMD 脚本，使浏览器通过 `window.Wala*` 使用、Node 测试通过 `require()` 使用。
3. `wala.html` 按 `storage → media → study-plan → quiz → wala` 加载，避免运行时竞态。
4. `wala.js` 改为调用模块；保持所有 `bookplay_*` key、进度结构、题目 `_asked` 语义和现有 DOM 不变。
5. 每个阶段运行 Node 语法检查、模块合同测试和全量 pytest；浏览器仍沿现有冒烟路径验证 EP1/EP108。

## 验收标准

- 四个模块可在 Node 中独立加载，无 DOM 依赖错误。
- 损坏 JSON 回退到默认值；旧进度结构读取/写入不变。
- `lite/std/max` 学习计划行为与拆分前一致。
- 剧情题只在题面和正确答案信息已经出现后安排。
- `wala.js` 不再定义四类已迁移的核心函数。
- 全量测试不低于当前基线 137 passed，所有前端脚本通过 `node --check`。
- 不提交或暂存图片、视频、音频、PDF、ZIP、APK。
