# 语音跟读 MVP 实施计划

> **给 Claude:** 必需子技能：使用 superpowers:executing-plans 来逐任务实施此计划。

**目标：** 在每集知识巩固页增加可选的单词/短句跟读，先判断语音识别文本是否命中目标，并在无麦克风、无权限、无网络或浏览器不支持时保持点选/打字通关。

**架构：** 新增无 DOM 的 `voice-core.js` 负责文本归一化、目标命中和统一结果合同；新增浏览器端 `voice.js` 负责 Web Speech/MediaRecorder 网关能力探测、录音生命周期和失败回退。`lesson.js` 只装配一个可选跟读卡，不直接依赖某一家供应商；真正发音评分留给后续 `/v1/speech/evaluate` 适配器。

**技术栈：** 原生 JavaScript IIFE、Node 内置测试、现有 Edge-TTS、Web Speech API、MediaRecorder、Capacitor WebView 兼容路径。

### 任务 2：实现浏览器端 VoicePort

**文件：**
- 创建：`prj/engine/voice.js`
- 创建：`prj/engine/voice.test.mjs`

**步骤 1：编写失败的测试**

覆盖能力探测和注入式假实现：

- 没有 SpeechRecognition、MediaRecorder 或端点时返回 `unsupported`；
- Web Speech 返回候选文本并交给 `voice-core` 判定；
- `no-speech`、`not-allowed`、`network` 映射到稳定错误类型；
- 网关分支只在显式配置端点且存在录音能力时启用；
- 录音停止后释放所有 MediaStream tracks。

**步骤 2：运行测试以验证它失败**

运行：`node --test prj/engine/voice.test.mjs`

预期：因 `voice.js` 尚不存在而失败。

**步骤 3：编写最小实施**

实现 `WalaVoice.create({ env, endpoint })`：

1. 优先使用 Web Speech（开发/桌面可用）；
2. 显式配置 `voiceStt` 查询参数时，使用 `getUserMedia + MediaRecorder` POST 短音频到网关；
3. 失败返回稳定状态，不抛出未处理异常；
4. 仅保存本次内存结果，不写 `localStorage`，不保存原始音频。

**步骤 4：运行测试以验证它通过**

运行：`node --test prj/engine/voice.test.mjs`

预期：注入式 Web Speech、错误和资源释放测试通过。
