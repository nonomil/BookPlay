# T11：贴纸故事锚点与提示词治理

## 目标

解决“贴纸画面好看但和本集故事无关”的问题。贴纸卡片必须先展示本集真实绘本场景，再展示可选的 GPT 透明小物件；任何生成图都不能覆盖故事事实。

## 已落地

- `content/rewards/jttw.json` 增加 `story_image_template`，并为 13 个篇章补齐 `cover_asset` / `detail_asset` 与故事范围说明。
- 从每集 `assets/lf_epN/pages/p03.png` 裁切上半部插画，生成 108 张无正文缩略图：`assets/generated/jttw-story-scenes-v1/epNNN.jpg`。
- `episode-reward.js` 在每个贴纸条目输出 `story_image`；卡片与大图弹窗优先使用该场景图，失败才回退到透明物件或 glyph。
- 贴纸页额外读取 `storybooks/catalog.json`，将第 2–13 篇的卡片标题替换为本集真实故事名（EP1 的精确物件标题与出处不变）。
- `companion.css` 增加 `story-scene-image` 样式，保证小尺寸仍能看到角色和动作，不把整页正文塞进卡片。
- 数据包与 Android 打包脚本按 episode 收录缩略图，避免离线环境出现 404。

## GPT 提示词规则（后续重生图必须遵守）

1. 每次只描述一个可收集元素，并写明 `episode / storybook_pages / scene_ids / trigger_terms`。
2. 先从本集绘本页提取“谁 + 在哪里 + 正在做什么”，再决定物件；不能因为“西游风格”自行添加雷电、宝剑、盔甲等泛化符号。
3. 角色、动作和关键道具要与页面一致；恐怖、尖锐、攻击性元素改成圆润的纪念物，不改变剧情事实。
4. PNG 不放标题、英文段落、数字和 UI；故事文字由 HTML/CSS 叠加。
5. 生成图必须经过 alpha、四角透明、绿边质量门；不合格时保留故事缩略图，不将半成品接入运行时。

## 验收

- 108 张贴纸均可定位到 `epNNN` 的故事场景图。
- 13 篇地图卡和详情页均显示真实绘本图，不再出现空白场景。
- 点击未解锁卡片仍能看到故事大图、出处和解锁条件。
- `npm test`、`npm run test:content`、数据包测试全部通过。
