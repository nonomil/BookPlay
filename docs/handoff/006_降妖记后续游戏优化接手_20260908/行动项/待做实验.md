# 待做实验

## 实验 1：慢速与边缘镜头设备轨迹

- **假设**：当前 `0.018/0.0012/0.0024` 参数在真实 CSS 像素中仍可观察；中央死区不滚图，越边缘才平滑滚图。
- **验证方法**：浏览器和精确 APK 各做 1 秒轻推、1 秒满推、横/竖/斜向，再做中央区和边缘区各一次；记录英雄位置、camera、world transform 和帧率。
- **成功判断标准**：轻推小于满推；横竖/斜向屏幕速度差不超过设计阈值 5%；中央 camera 偏移不超过 1px；边缘相机无跳变；松手 100ms 内停止。
- **失败后动作**：先确认包路径、WebView/CSS 像素、pointer 事件和设备刷新率，再决定调参或修适配器；不得直接恢复硬跟随。

## 实验 2：双指移动与投掷

- **假设**：一指摇杆持续移动时，第二指点击目标/投掷不会劫持活动 pointer，也不会留下移动。
- **验证方法**：触屏连续做 pointerdown/move/up/cancel/lostpointercapture 组合；同时记录 `game-input` 意图、投掷事件和关闭弹层后的意图。
- **成功判断标准**：活动 pointer 唯一；第二指不能改变摇杆；释放/失焦/后台后 100ms 内意图为零；投掷只发生一次。
- **失败后动作**：保留最小事件日志，修 `game-input.js` 或弹层输入分权，并补行为测试；不改存储键。

## 实验 3：整局状态与返回幂等

- **假设**：正常顺序完成 ep1/ep5 后，Boss 返回地图不重播 intro、不重刷已死小怪、不丢 NPC 和道具状态。
- **验证方法**：清空仅游戏两条键的测试数据；按正常顺序完成一局；在 NPC 选择、Boss 动画、浏览器返回和重复点击按钮的边界各记录一次；检查 progress/collection JSON。
- **成功判断标准**：阶段严格 `wave1 → npc → wave2 → boss → complete`；一次奖励只消费一次；`from=battle` 恢复与离开前快照一致；学习结果键不被清理。
- **失败后动作**：以最小复现断点补 `game-core`/`battle-core` 测试，再修页面；禁止用 debug.step 跳过断点。

## 实验 4：NPC 多次答题与对话关闭

- **假设**：正确、错误重试、直接关闭、重听后关闭都不会重复奖励或留下音频/输入。
- **验证方法**：打开 intro 与 quiz；错误一次再正确、错误两次、正确后点关闭、重听后立即关闭；触发迟到 `ended/error` 事件替身。
- **成功判断标准**：`dlg=null`、面板隐藏、锁释放、意图清零；NPC 奖励字段幂等；pending wave 只生成一次；无迟到语音。
- **失败后动作**：优先检查 `closeDialogue`、`game-audio.js` generation token 和 `completeQuizNpc` 的幂等保护。

## 实验 5：断网静态语音

- **假设**：ep1/ep5 的词、NPC、Boss 关键语音均从 APK/阶段包静态文件播放，断网时不依赖 TTS。
- **验证方法**：断网安装准确包；逐条操作词球、提示、NPC 普通句/题干/带读、Boss 关键句；记录 `game-audio` state、实际 URL、媒体 error 和系统音量。
- **成功判断标准**：索引引用文件存在且能解码；重听/取消/切页无串音；BGM 不盖人声；缺失项显示可见错误而非静默假成功。
- **失败后动作**：逐项区分索引、白名单、实际加载路径、解码和音量问题；未试听原声不得标 approved。

## 实验 6：巩固完成后的两路线入口

- **假设**：真实完成巩固后自动显示进入/跳过层，跳过不改变学习通过。
- **验证方法**：分别对 ep1、未通过结果、未发布集和最后一集完成/退出巩固；记录 DOM/路由/学习存储和游戏存储变化。
- **成功判断标准**：入口焦点可见；进入到本集 game route；跳过回结果/复习；不存在 ep109 或错误集跳转；学习结果保留。
- **失败后动作**：先复现 `lesson.js` 的 finishLesson/游戏可用性分支，再补 E2E，不把字符串存在当通过。
