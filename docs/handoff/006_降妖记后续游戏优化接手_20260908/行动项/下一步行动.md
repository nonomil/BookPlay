# 下一步行动

> P0 先把真实消费者和整局断点证据补齐，再处理扩集与装饰；不要用新增玩法掩盖未验证链路。

## P0

### P0-1：确认现场包与设备（T00/T10 前置）

- **前置依赖**：用户确认接手者复述方向；目标 Android/TV 可用。
- **具体操作**：记录 `git status --short`、当前 APK 路径/版本/hash、`adb devices -l`；有设备安装 `release/storyhall-jttw-mobile-debug.apk` 并核对 1.0.14/versionCode 19/SHA-256。
- **预期产出**：更新设备记录、安装日志和准确包证据；无设备则明确写“待验”，不阻塞浏览器样板。
- **为什么是 P0**：当前所有真机体验和完整链路都被“ADB 无设备”直接阻塞。

### P0-2：正常顺序跑 ep1/ep5 整局（T03–T05）

- **前置依赖**：P0-1 或可用本地浏览器运行时；保留已有存档键和用户进度。
- **具体操作**：从起点移动，捡中文词球，向头顶对应英文小怪投掷；故意触发一次撞击；清第一波后找 NPC，完成一次正确和一次错误重试；清第二波，靠近 Boss，完成回合并返回地图。
- **预期产出**：每一步的通过/失败/未执行、截图或日志、`from=battle` 返回后的 `mapStage/killed/npcDone/items` 快照。
- **为什么是 P0**：源码已有契约但没有端到端证据，用户明确反馈“游戏设计乱、之前没做完”。

### P0-3：修复地图数据真实消费与状态幂等（T03–T05）

- **前置依赖**：P0-2 记录的最小断点。
- **具体操作**：点位从 `maps.json`/关卡 JSON 读取；NPC 门控遵守 `wave1 → npc → wave2 → boss-ready`；Boss 回合使用 `roundId`/输入锁；奖励只写 `bookplay_battle_progress_v1` / `bookplay_battle_collection_v1`，返回不重播、不重刷。
- **预期产出**：新增/更新契约测试和浏览器/设备复现，测试总数保持至少 408。
- **为什么是 P0**：当前报告只证明契约和样板，整局状态是最大未闭环风险。

### P0-4：断网语音闭环（T06–T07）

- **前置依赖**：P0-2 的实际台词和页面顺序稳定。
- **具体操作**：清点 ep1/ep5 文本；已有词句直接复用；原声候选逐句登记来源/时间/说话人/试听；接入共享播放器的重听、取消、后台停止；断网验证地图词、NPC 题干/带读、Boss 关键句。
- **预期产出**：`audio/ep1.json`、`ep5.json` 和 source-manifest/review 记录；缺失项 0，未审原声保持 pending。
- **为什么是 P0**：语音索引虽然 validate 通过，但没有设备解码/断网证据，且用户要求语音接入。

### P0-5：巩固后自动进入/跳过（T08）

- **前置依赖**：P0-3 的 game route 和关卡可用性。
- **具体操作**：用真实题目完成巩固，不直接调用 finishLesson 字符串检查；确认自动显示两选项，进入带 `from=lesson`，跳过保留学习结果；覆盖 ep1、未通过结果、未发布集、最后一集。
- **预期产出**：页面行为测试/E2E 或明确未执行原因；不新增存储键。
- **为什么是 P0**：这是用户最初指出“知识巩固后的游戏环节没生效”的主入口问题。

### P0-6：三白名单与准确 APK（T09–T10）

- **前置依赖**：P0-3 至 P0-5 的文件和数据稳定。
- **具体操作**：逐文件检查阶段包 `COMMON_FILES`、APK 内置依赖闭包、APK 引擎 `ENGINE_FILES`；核对 `assets/public/engine` 真实加载副本；构建、解包、记录版本/hash/缺失引用。
- **预期产出**：可追溯包报告；新装和旧包升级各一条设备证据。
- **为什么是 P0**：清单漏登记会静默缺失，当前包 hash 只说明已有包，不说明后续修改已进入设备。

## P1

- 改善低端 WebView 的帧率、音量层级和后台恢复；每次改动都保留移动速度对照轨迹。
- 真实设备通过后，按同一契约扩 ep2–4、ep6–7，并同步 `docs/playbooks/降妖记整局玩法/` 五份手册。

## P2

## 完成定义

只有当适用的 V01–V28 项有设备或可复现浏览器证据、包 hash 可追溯、关键音频逐条可播、整局返回不丢状态时，才能把阶段写成“通过”。Node 测试通过、方案文档完成或单张截图都不能单独满足完成定义。
