# 决策记录

## 决策列表

### 决策 1：镜头改为边缘平滑跟随

- **选择**：人物先在屏幕内移动，接近视口内边缘后地图才平滑滚动。
- **原因**：这是用户明确确认的体验基准；旧的立即居中会让地图一直动、人物难以观察。
- **实现锚点**：`prj/engine/game-core.js` 的 `edgeCameraStep`；`prj/engine/game.js` 的 `updateCamera`。
- **被否决的替代方案**：恢复母本立即居中镜头；它与用户确认的镜头决定冲突。

### 决策 2：走路和攻击动作完全分离

- **选择**：主角和小怪分别使用四向 `idle / walk / attack`；攻击时停止移动，攻击结束回到 idle/走路状态。
- **原因**：用户反馈挥舞兵器和走路混在一起，看不清动作意图；状态分离也便于后续受击和战斗锁。
- **实现锚点**：`setHeroPose`、`setMonsterPose`、`monsterAttack`、`moveHeroBy`。
- **被否决的替代方案**：在走路 GIF 中叠加武器挥舞，或让攻击期间继续移动。

### 决策 3：速度先降到可观察档

- **选择**：`hero=0.018`、`monsterWander=0.0012`、`monsterChase=0.0024`（视口比例/秒，运行时再乘 `1 / WORLD`）。
- **原因**：旧主角约 1177 px/s 的理论视觉速度过快；当前参数让 8 帧×150ms 的 GIF 有机会被看清。
- **边界**：这是浏览器起始参数，不是设备最终手感；T10 允许基于轨迹证据微调，但不能跳过基线记录。

### 决策 4：保留词球、六道具和整局主线

- **选择**：`词球捡投 → NPC 剧情答题 → 第二波 → Boss → 返回`；保留六道具和头顶英文小怪。
- **原因**：这是用户指定的参考玩法与已形成的数据/测试契约。
- **被否决的替代方案**：把大地图改成点击式快卡或把 pet-battle 的完整选队/PvP体系直接搬入。

### 决策 5：语音静态索引优先，原声逐句审定

- **选择**：先复用已有词句音频；原视频只按来源、时间段、speaker、试听记录提取；新编台词单独配音。
- **原因**：离线可控且证据可追溯，避免把字幕或均分切片误写成原声。
- **被否决的替代方案**：动态 TTS 作为唯一发布声音，或整段视频按句数平均切片。

### 决策 6：先 ep1/ep5 样板，再推广

- **选择**：先让 ep1、ep5 通过移动、整局、语音和设备检查，再按同一引擎扩 c01/ep8+。
- **原因**：两集覆盖不同主题和点位，可暴露数据消费问题；能减少一次性扩集造成的诊断噪声。
- **被否决的替代方案**：在未闭合真机链路前批量生成更多集或复制新引擎。

### 决策 7：交接时不继续改代码

- **选择**：本轮只写 006 文档和索引，后续执行由新 AI 在用户确认后开始。
- **原因**：当前工作区已有 70 处未提交改动，继续叠加会模糊变更归属；交接包把证据等级和下一步分开。
- **被否决的替代方案**：在没有用户确认的情况下自动派发 ZCode、重建 APK 或扩玩法。
