# 根因分析

> 发布拆分不是技术事故，是体积与门控：ep1 视频+音频已经把 APK 顶到 121 MB；1–54 游戏图再进内置会继续涨，且与 `episodes:[1]` 门控打架。

## 根因

APK 内置树走阶段包闭包 + `jttw-only` 修剪；游戏页却按 `game/levels/epN.json` 与 `sprites.json` 绝对路径取图。后面关的图必须在**导入的 data 根**里，不能指望 builtin。

## 结论等级

- **已验证**：builtin manifest 只有 ep1；heaven-soldier 不在 builtin 目录；`COMMON_DIRS` 现已包含 `game` 与 `assets/game-*` 整树。
- **推测**：导入数据包后选关 8+ 能直接进地图（未在设备上点过导入）。
- **反证**：若把 2–54 打进 APK，会违反用户「只维护一份大文件」和既有 prune。

## 分析过程

1. 用户问 APK 是否含各关图片 → 查 `available_for_profile("jttw-only")` 与 builtin 树。
2. 用户要求一份大数据包 → 阶段包原先 `COMMON_FILES` 只点名 ep1–13 关卡 JSON，后面关会漏登记。
3. 把 `game/`、`assets/game-sprites|fx|backgrounds|pickups` 放进 `COMMON_DIRS`，按 c01–c07 打一份 ZIP。

## 证据

- `prj/tools/pack_android.py` `available_for_profile` / `_prune_jttw_only`
- `prj/tools/pack_datapack.py` `COMMON_DIRS`
- 本会话：builtin 无 `heaven-soldier`

## 最小反证实验

- **实验名**：把数据包导入后打开 ep8（天兵）地图，看是否加载 `heaven-soldier-south-walk.gif`
- **若失败意味着**：ZIP 闭包仍漏文件，或 App 导入后 data 根不是 `content/` 同构
