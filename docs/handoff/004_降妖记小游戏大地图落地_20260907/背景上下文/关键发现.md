## 2. 打包三白名单规则 ✅（本项目最大陷阱，三次踩坑后确立）

阶段数据包（`--collections`）与 APK 内置树都走 `_build_stage_pack` 的**引用闭包 + COMMON_FILES**，**不吃** `INCLUDE_DIRS`（那只管全量包）；APK 引擎文件走 `ENGINE_FILES` 白名单。后果：引用闭包扫不到"按固定路径 fetch 的 JSON"。

| 打包模式 | 需要登记的位置 | 文件 |
|------|--------------|------|
| 阶段数据包（--collections） | `COMMON_FILES` 逐文件（game JSON×4 + levels×7 + GIF×24 + 背景×6） | `prj/tools/pack_datapack.py` |
| APK 内置数据（--builtin） | 经 `_build_stage_pack` 自动带 COMMON_FILES；另有 `DATA_DIRS`（仅非 builtin 的 pack_data 模式用） | `prj/tools/pack_android.py` |
| APK 引擎页面 | `ENGINE_FILES` 白名单（battle*/game*/tv*/episode-vocab-quiz 已加） | `prj/tools/pack_android.py` |

验证：0.2.1 zip 解包 game 11 文件 + 背景 6 + GIF 24 全在；APK 内置 `assets/data/game/`、`assets/data/assets/game-backgrounds/`、`assets/engine/battle|game|tv*` 全在。

## 3. rAF 后台节流与看门狗 ✅

自动化环境中浏览器面板后台化时 rAF 节流到≈0（帧计数探针挂起 32s）。对策（`game.js` 末尾）：320ms `setInterval` 看门狗在 `lastTs` 落后时兜底步进 + `window.BookPlayGameDebug.step` 泵帧测试钩子（`ignoreHidden` 配合）。真机 WebView 同类风险一并覆盖。

## 4. 生图管线经验 ✅

- provider（cliprox/gpt-image-2）常无视 1536x1024（返回 1774x887/1402x1122/1254x1254）→ `--allow-any-ratio` + PIL 归一；
- 提示词写 "transparent background" 会画出**假透明棋盘格** → 小角色用 `remove_background.py --mode checkerboard` / 场景图直接写实心；
- 行序与实际画面可能对调 → 拆格后目视按实际语义重命名（manifest 记录映射）；
- 拆格禁用 `--trim`；GIF 用共享调色板 + 固定透明索引（防背景变黑）；
- runner 路径必须显式 `C:/Users/No'mi'l/...`（bash `$HOME` 展开为 POSIX 路径导致空跑）。
详见 `assets/generated/jttw-game-sprites/review.md`。

## 6. 开发期修复的真 bug（模式教训）✅

1. `buildLevel` 组装运行时对象时丢弃新增 `map` 字段 → 透传 + 单测（教训：构造函数式映射要显式透传扩展字段）；
2. 实体监听器闭包捕获**原始数据对象**而非状态对象（`alive/done` 判定失效，点击静默无效）→ 先建状态对象再绑监听器；
3. NPC 答错重试把正确项一并 disable（玩家卡死）→ 只禁点错的项；
4. `throwOrb` 设 `locked=true` 导致主循环 early-return、追踪弹永久冻结（投掷死锁）→ 投掷不锁世界；
5. 撞击击退发生在拾取判定前（`updateOrbs` 排序）→ 拾取提前 + 半径 0.085→0.11；
6. Boss 血条推进引用未定义 `hpWords`（ReferenceError）→ 定义缺失。
