## 问题起因

2026-09-04 当天，P2 六特性方案与自包含提示词刚定稿（`docs/plans/2026-09-04-西游记多形式学习闭环P2/`），用户随即提问"此项目还要如何优化"。本会话用两路探索代理（代码现状调查 / 计划与文档历史梳理）加直接验证（`git log`、`wc -l`、`npm test`、`grep`）做全景分析，目标不是再找新学习特性，而是找出**不在任何计划里**的缺口。

分析产出四缺口框架（工程安全 / 发布验证 / 代码整合债 / 半开产品线）与建议执行顺序，并生成 003 号交接包。全程零代码改动。

## 影响范围

- **工程安全**：git 版本控制、localStorage 存档兼容性、打包脚本、Android 原生插件——影响全部后续开发的数据安全与排错效率。
- **发布验证**：磨耳朵、跟读、趣配音等语音特性只在桌面浏览器验证过，Android/iOS/TV 真机项持续积压。
- **代码整合**：`prj/engine/` 五大文件（合计 8807 行）与 17 个页面的重复实现，影响后续每个特性的实现成本。
- **产品线管理**：6 条开了一半未显式关闭的线，影响"当前哪条是主线"的判断。
