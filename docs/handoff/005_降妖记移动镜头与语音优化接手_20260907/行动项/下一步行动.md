# 下一步行动

> 接手先复述确认，再完成可试玩的运动与输入样板。

## P0第一步：接手确认与T00

前置是用户对接手者复述的确认，不沿用“生成文档”的确认代替“开始实现”。

1. 读README、关键发现与本文件，复述需求/证据/方案/禁区。
2. 用户确认后记录当前git status、核心源码/运行包hash、npm基线。
3. 在相同视口用正常输入对比母本与ep1/ep5，记录四向、轻推/满推和镜头；无法取得设备时明确标待验。
4. 确认浏览器或设备实际消费的引擎/数据版本，避免对错误副本诊断。

P0依据：用户直接反馈移动有问题；源码已证实非零幅度归一与居中硬跟随。先修最小体验链比扩资产/章节更贴近当前问题。

## P0首个实施检查点：T01–T02

修改game-core/game.js/game.css，新增game-input适配器，兼容tv-remote。先加失败行为测试，再做统一坐标、死区保幅度、边缘跟随、pointer归属和弹层输入分权。

验收至少包含：横竖及斜向速度差≤5%、中央区镜头偏移≤1px、轻推慢走、松手100ms内停止、边缘平滑、双指移动投掷和后台清理。阈值为设计目标，记录实测值，不提前勾选。

产出：ep1和ep5正常输入录屏、相关行为测试、改动文件清单、未覆盖设备项；全仓测试不低于357且无失败/人为跳过。
