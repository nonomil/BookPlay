# 待做实验

> 以下均未在改造版执行，用于验证方案而非宣称结果。

## 最小实验清单

| ID | 假设/动作 | 通过标准 | 反证或失败后动作 |
|---|---|---|---|
| E01 | 同函数输入0.1与1；真实摇杆记录raw意图 | 改造后死区之外幅度影响速度 | 同速则查归一或实际加载版本 |
| E02 | 固定有效时间四向/斜向移动 | screen/world一致；速度差≤5% | 分查rect、scale、dt与碰撞 |
| E03 | 中央、四边、停止、反向、世界边界 | 中央≤1px；停后250ms内稳；不露底 | 查目标camera、clamp及平滑收尾，不无限调速度 |
| E04 | 双指移动投掷、失焦、取消、后台 | 无指针劫持/卡键；恢复需重新输入 | 查pointerId、capture及blur/hidden清理 |
| E05 | 首波→NPC→次波→Boss→返回 | 不跳门控；不重刷；奖励只一次 | 查run快照、prev合并和结果消费 |
| E06 | 非原hpWords地图错词+Boss连点 | 错词进入复习；一回合判一次 | 查词库组池/roundId，而非仅锁按钮 |
| E07 | 断网先直接播放已知静态MP3，再触发同词游戏事件 | 关键声音无需系统语言包也能播 | 直接播放失败查设备；事件失败查索引/接线 |
| E08 | NPC连翻、暂停/切页、BGM同播 | 旧音取消、字幕相符、人声清楚 | 查generation token/watchMedia/优先级 |
| E09 | 样板原声逐句试听 | 文本、speaker、首尾和时间线一致 | 保留pending；用同文本既有音频，不伪造approved |
| E10 | APK/zip解包、旧数据包升级 | JS/JSON/音频依赖完整且真实路由版本正确 | 查COMMON_FILES、引用闭包及数据覆盖优先级 |

“静态文件直接播放”只是对照实验，不是最后用直链绕开游戏事件验收。所有实验都需要正常交互验证对应消费链。

## 环境与最小反证规则

浏览器使用独立上下文/夹具，不污染用户进度；设备须记录型号、系统/WebView、APK hash、数据版本、网络和输出通道。

若浏览器表现正确而真机失败，先核对实际资源hash和输入事件，再判断是性能/平台差异。若冻结镜头也出现人物抖动，不把所有问题归因于摄像机。

调校参数如25%–75%死区、100–160ms时间常量只是候选。若250ms收尾阈值无法达成，要调整收尾算法或提交实测依据讨论目标，不能把未达标标通过。

## 结果保存

实施阶段结果写到docs/reports/降妖记优化验收/，包括environment.json、results.json、版本hash、完整录屏和故障日志。结果至少含caseId/status/episode/device/appVersion/contentVersion/expected/actual/evidence/timestamp。

对应产品验收沿用[V01–V28矩阵](../../../plans/2026-09-07-降妖记移动镜头与语音优化/08-验收矩阵与后续集清单.md)，不把本表10个诊断实验与28个验收项相加计算“通过率”。
