# 风险阻塞

> 当前没有阻止文档交接的技术阻塞，游戏实施仍有明确风险和待验条件。

## 风险与应对

| 风险 | 影响 | 处理 |
|---|---|---|
| 工作区大量既有修改 | 覆盖入口/打包/用户修改 | 先记录定向diff，仅改任务文件；不可reset/checkout清理 |
| 源码、生成副本、APK不同步 | 修了代码用户仍看旧效果 | 核对public/engine实际路由和源码hash |
| 新JSON或MP3遗漏 | 静默缺关卡/缺声 | 三通道+引用闭包，缺资源构建失败 |
| 导入旧c01覆盖内置 | 升级后仍旧数据或缺字段 | 记录来源，兼容旧字段并验证保留数据升级 |
| 两条游戏键混写/覆盖prev | NPC奖励丢失或重复 | 可选run字段、merge、结果幂等；学习键不迁移 |
| 原声时间线不一致 | 错句/截断/错speaker | 锁源hash和时间基准，逐句审核 |
| Node通过被当真机完成 | 用户问题继续存在 | 按V矩阵记录实测与待验，不汇总伪通过率 |

## 待补条件

- 🔲 目标手机/电视、ADB serial、WebView和已装APK版本未确认。先定位SDK/platform-tools；没有实物的TV项保持待验。
- 🔲 FFmpeg位置、原声时间窗和音质审核待做；可以先复用现有静态词句，不能自动把候选片段标approved。
- 🔲 浏览器E2E脚本和依赖待创建/核实；package.json当前不声明Playwright，不假装已有可用E2E。
- 🔲 ZCode调用接口未连接。本包提供手动接手提示词；若要自动派发，需要明确可用入口和权限，不以Codex/GLM代理替代冒称ZCode。

## 权限与安全边界

新装验收使用专用测试设备或另行确认的数据清理权限，不能为了“干净安装”卸载用户现有应用。构建会自增版本且生成多个副本，留到实施计划对应阶段。

没有做视频切片、APK构建/安装或源码修复，不需要回滚本轮运行变更。不得删除content目录、原视频、junction或手写content/game源数据。

## 口径冲突

004的“全落地”和357测试通过都不能替代用户体验验收。当前仅按源码事实、用户确认和显式实测作结论；遇到交接包/新增凝蜕/transcript真实冲突，先停下问用户。
