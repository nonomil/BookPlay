# 根因分析：解锁链两处崩溃（已修）

结论先给：`map.js` 里两个辅助函数漏传 `prev` 参数，靠 `||` / `&&` 短路侥幸没炸；第 2 切片接线巩固节点后条件路径变了，`forEach` 在第 3 页抛异常中断，**13 页只渲染出 2 页**。已修并验证。

---

## 现象

造出「1–13 集已学完 + c01/c02 已豁免」的状态后打开 `map.html`：

```
pagesInDom : 2          ← 应该是 13
visible    : [c01, c02] ← c03 已解锁，应该可见
lockMsg    : []         ← 应该在 c04 上
ep14       : false      ← 第 14 集已解锁，应该可点
toast      : "地图数据加载失败: Cannot read properties of undefined (reading 'from')"
```

## 定位手段

不猜，直接在页面上重跑渲染并抓栈：

```js
try { buildPages(); } catch (e) { return { error: e.message, stack: e.stack }; }
```

## 缺陷 1：`drillUnlocked` 漏传 `prev`

```js
// 错
const drillUnlocked = (c) => colUnlocked(c) && colDone(c);
//                            ^^^^^^^^^^^^^ prev === undefined
const colUnlocked = (c, prev) => c.index === 1 || (colDone(prev) && drillDone(prev));
const colDone = (c) => epNums(c).every(epDone);
const epNums  = (c) => { const a = []; for (let n = c.from; ... } // ← c.from 炸
```

调用链：`nodesHTML` → `drillUnlocked(c)` → `colUnlocked(c, undefined)` → `colDone(undefined)` → `epNums(undefined).from` → **TypeError**。

**为什么第 1 切片没炸**：当时 `nodesHTML` 把巩固节点硬编码成 `<span class="node drill locked">`，`drillUnlocked` 从未被调用。第 2 切片改成 done/current/locked 三态才第一次真正调用它。

**为什么 c01、c02 没炸**：
- c01：`c.index === 1` 让 `||` 短路，`colDone(prev)` 根本不执行
- c02：`drillDone(c02)` 为真（已豁免），`nodesHTML` 走了前一个 `if` 分支，没走到 `drillUnlocked`
- c03：`drillDone` 为假 + `index !== 1` → 两道短路都失效 → 炸

## 缺陷 2：`epUnlocked` 同类缺陷

修掉缺陷 1 后仍崩，栈变成：

```
at epNums    (map.js:65)
at colDone   (map.js:67)
at colUnlocked (map.js:69)
at epUnlocked  (map.js:70)   ← 新的源头
at nodesHTML   (map.js:102)
```

```js
// 错
const epUnlocked = (n, c) => colUnlocked(c) && (n === c.from || epDone(n - 1));
//                            ^^^^^^^^^^^^^ 同样漏 prev
```

调用点是 `} else if (isUnlocked && epUnlocked(n, c)) {`。

**为什么第 1 切片没炸**：空进度时 c01 靠 `index === 1` 短路；c02 的 `isUnlocked` 为 false，`&&` 短路让 `epUnlocked` 根本不求值。要同时满足「合辑已解锁」+「集未学完」+「index ≠ 1」才触发 —— 正好是 c03 在豁免生效后的状态。

## 修法

```js
// map.js:69-72
const colUnlocked = (c, prev) => c.index === 1 || (colDone(prev) && drillDone(prev));
// 调用方 nodesHTML 已用 isUnlocked(= colUnlocked(c, prev)) 把过闸，这里只判集内条件
const epUnlocked  = (n, c) => n === c.from || epDone(n - 1);
const drillUnlocked = (c, prev) => colUnlocked(c, prev) && colDone(c);
```

```js
// map.js:112，巩固节点分支
} else if (isUnlocked && colDone(c)) {   // 原：drillUnlocked(c)
```

思路：`isUnlocked` 就是 `buildPages` 已经算好的 `colUnlocked(c, cols[i-1] || null)`，直接复用，别在内层函数里重算一遍。语义完全不变。

改完全仓审计了一遍调用点，现在 `colUnlocked` 的三处调用都传了两个参数：

```
124: cols.findIndex((c, i) => !colUnlocked(c, cols[i - 1] || null))
127: const isUnlocked = colUnlocked(c, cols[i - 1] || null)
173: cols.findIndex((c, i) => !colUnlocked(c, cols[i - 1] || null))   // initialIndex()
```

## 缺陷 3：`map.html` 引资源没带版本号

修完代码刷新页面仍崩。核对发现服务器发的**是**新文件（`fetch('map.js?bust=...')` 里能看到修改），但页面跑的是缓存的旧 JS —— `map.html` 写的是 `<script src="map.js">`，无版本参数。

项目里 `wala.html` 一直用 `wala.css?v=43` 这种方式规避，map 这套漏了。已补：

```html
<link rel="stylesheet" href="map.css?v=3">
<script src="map.js?v=3"></script>
```

**给接手者**：以后每次改 `map.js` / `map.css` / `drill.js` / `drill.css` 都要递增 `?v=`，否则你会以为自己的修改没生效而白白 debug。`drill.html` 目前也没带版本号，**建议一并补上**。

## 同类风险

这类「辅助函数少传参 + 短路掩盖」的写法在 `map.js` 里已清理完，但 `drill.js`（17KB，本次未逐行审）可能有同类问题。`drill.js` 的分支比 `map.js` 多（三种题型 × 对错 × 提示），建议接手后用同样手法验证：**在页面上跑真实交互，出错就抓栈，不要只读代码**。
