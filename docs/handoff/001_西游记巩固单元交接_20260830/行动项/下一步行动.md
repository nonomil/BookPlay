## P0 · 端到端验证巩固通关链路 ✅

该 APK 前硬门槛已解除。

**实测结果**：在 `localhost:8810` 隔离 origin 中完成 c01 全流程：单词 12/12、句型 6/6、测验 21/21；出现“本辑巩固通过！下一辑已解锁”，写入 `bookplay_drill.c01.done=true`。返回地图后 EP8 可点，EP9 仍锁。隔离夹具为 `prj/tests/fixtures/drill_c01_harness.html`，未覆盖 `127.0.0.1` 的真实用户进度。

**为什么是 P0**：`drill.html` 的三种题型「能出题」已验证，但「答完 → 判定 → 写 `bookplay_drill` → 回地图看下一辑解锁」这条链**一次都没走通过**。之前被 `map.js` 的崩溃阻断，现在崩溃修了，但通关链路仍是未知。

**怎么做**：

```js
// 1. 浏览器控制台造「c01 七集已学完、巩固未做」的状态
const p={}; for(let n=1;n<=7;n++) p[n]={node:9,total:9,done:true};
localStorage.setItem('bookplay_adv_progress', JSON.stringify(p));
localStorage.removeItem('bookplay_drill');
localStorage.setItem('bookplay_drill_migrated','1');   // 关键：跳过豁免，逼自己真做巩固
```

```
2. 打开 map.html → 确认 c01 的 ★巩固 是可点的（current 态），c02 仍锁
3. 点进 drill.html?c=c01
4. 单词补全 12 题、句型排序 6 题、剧情测验 21 题都做完
5. 期望：出现「本辑巩固通过！下一辑已解锁」卡片
6. 检查 localStorage.bookplay_drill.c01.done === true
7. 回 map.html → 期望 c02 解锁、第 8 集可点
```

**验收标准**：第 6、7 步都成立。

**已知风险点（重点看这几处）**：
- 三个标签是否都必须做完才判定？只做完两个会不会提前判过或永不判过
- 句型排序的标点/大小写宽松匹配是否真的宽松（`puzzles[].words` 不带标点，`sentence` 带）
- 剧情测验 21 题（std 档）一次做完对孩子是否太长 —— 是否需要中途可退出并保留进度
- 未达标时「再做一次」是否真的不重复已答对的题
- **`drill.js` 17KB、分支比 `map.js` 多，可能有同类的"漏传参 + 短路掩盖"缺陷**。出错就在页面上抓栈（`try{...}catch(e){e.stack}`），不要只读代码

**如果发现 bug**：先补 `drill.html` 的 `?v=` 版本号再调，否则改了不生效（见 `技术分析/环境信息.md`）。

## P1 · 补「知识回顾」和「错题回顾」两个标签 ✅

`drill.js` 目前只有 单词 / 句型 / 测验 三个标签，原方案是五个。

- **知识回顾**：本辑生词卡网格（`term` + `pos` + `zh`），一屏 6–8 张，底部「继续 4S」倒计时按钮。取词优先 `bookplay_adv_vocab_stat[term].wrong > 0`，不足用本辑 `official_words` 随机补
- **错题回顾**：本辑范围内 `wrong > 0` 的词重问词义，答对清错次；没有错题显示「还没有错题，太棒了」

数据都在 `drill/cNN.json` 里，不用改包格式。

⚠️ 加标签后要重新确认通过判定：这两个标签**不应该**成为通过的必要条件（知识回顾是浏览、错题回顾可能为空），别把 `pass` 条件改坏。

**实测结果**：知识回顾显示 8 张词卡，英文可触发发音，继续按钮在 4 秒后启用；故意把 `last` 选错后错题数为 1，答对中文后归零并显示空状态。两标签未加入三项通关门禁。
