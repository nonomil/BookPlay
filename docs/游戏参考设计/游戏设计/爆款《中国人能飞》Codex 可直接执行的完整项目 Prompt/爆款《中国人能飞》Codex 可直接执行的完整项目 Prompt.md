## 《中国人能飞》Codex 可直接执行的完整项目 Prompt

你现在要直接产出一个可运行的纵向像素风 Web 小游戏，游戏名为《中国人能飞》。请不要只写方案，请直接生成完整项目代码、可运行资源、占位素材、配置文件、README 与启动方式，让我拿到后即可本地运行、继续迭代。

## 一、项目目标

制作一款2D 纵向无限上升跳跃/飞升类像素小游戏，核心体验是：

- 玩家控制一个带翅膀的小人，从中国城市地表一路向上飞
- 经历 地面 → 高楼 → 高空 → 云层 → 平流层 / 地球边缘 → 外太空
- 通过平台跳跃 / 自动上升 / 左右控制，持续向上突破高度
- 有 爱心生命值、障碍物、奖励道具、护盾、加速器
- 视觉重点是：背景不是静态图，而是连续超长、层级连贯、相对下移的滚动背景
- 玩家向上飞时，背景应相对向下运动，从而形成“玩家在持续上升”的视觉效果
- 玩家拾取 加速奖励 时，背景的下降速度必须同步明显加快，产生强烈冲刺感
- 最终目标是：飞到外太空

- 纵向无限上升
- 平台跳跃 / 飞升躲避
- 轻街机
- 快节奏
- 一局可反复重开
- 适合手机竖屏和桌面浏览器竖屏预览

### 核心卖点

1. “中国人能飞”这个梗本身有记忆点
2. 从中国城市一路飞到外太空
3. 背景连续滚动特别重要，且层级衔接不能突兀
4. 加速器触发时，背景也要明显加速下移
5. 视觉要有像素街机爽感，而不是静态海报感

## 四、角色设定

请生成一个原创角色，但视觉方向参考我之前确认过的形象特征，不要做成之前那种过于可爱或鬼畜失控的风格，也不要照搬现成 IP。

### 角色视觉方向

- 像素风小人
- 男性 / 中性搞笑英雄感
- 黑色短发
- 黑色墨镜
- 黑色上衣，中间有红绿横条纹元素
- 白色裤子 / 短裤
- 背后有一对白色翅膀
- 表情可夸张，但整体要顺眼、耐看、易识别
- 需要有以下状态 / 动画帧：
- 待机
- 上升 / 飞行
- 下落
- 受伤
- 吃到加速器
- 护盾状态
- Game Over

### 角色风格要求

- 纯 2D pixel art
- 清晰像素边缘
- 适合游戏内小尺寸显示
- 需要有辨识度
- 不要做成海报插画风人物
- 必须适合实机游戏使用

## 五、核心玩法

### 核心循环

- 小人会持续向上进行平台跳跃 / 飞升
- 玩家通过 左右移动 控制落点
- 角色离开平台后会继续向上 / 下落运动
- 摄像机会持续跟随角色向上
- 背景则持续相对下移
- 玩家需要：
- 踩中平台
- 躲避障碍
- 收集道具
- 保持生命
- 不断刷新高度
- 最终飞向外太空

### 失败条件

- 爱心全部耗尽：失败
- 角色掉出屏幕底部：失败

### 成功 / 阶段目标

- 不设传统“通关结束”
- 但设计明确的阶段推进感
- 首次飞到外太空时，给予强反馈与成就感
- 外太空之后仍可继续刷高度纪录

- D / →：向右移动

### 操作原则

- 简单直接
- 不要复杂按键
- 不需要攻击键
- 重点是“移动找落点 + 收集道具 + 躲障碍”

## 七、生命系统

### 爱心生命

- 生命值使用 爱心 显示
- 最大 5 颗
- UI 样式类似：
- 满血：❤️❤️❤️❤️❤️
- 掉血后：❤️❤️❤️🤍🤍

### 规则

- 开局建议：4 颗心
- 最大上限：5 颗心
- 玩家可拾取爱心奖励恢复生命
- 若当前已满 5 颗，再拾取爱心：
- 不增加生命
- 可转化为少量加分或提示 “生命已满”

### 扣血规则

- 普通障碍：掉 1 颗心
- 强力障碍：掉 2 颗心
- 受击后需有短暂无敌时间（如 0.8 秒），避免连续瞬间掉光

## 八、道具系统

至少实现以下核心道具：

### 1）爱心

- 图标：像素爱心
- 效果：+1 颗心
- 上限：最多 5 颗

### 2）护盾

- 图标：像素蓝色护盾
- 效果：
- 持续 5 秒
- 持续期间碰到障碍不掉血

必须有明显视觉反馈：

- 角色周围出现护盾光圈
- UI 有护盾剩余时间

护盾只防障碍伤害，不防掉出屏幕死亡

### 3）加速器

- 图标：像素小火箭 / 推进器
- 效果：
- 持续 3 秒
- 角色高速向上冲刺
- 背景必须同步明显加速下移
- 摄像机与速度反馈要很强

要有强烈爽感：

- 拖尾
- 速度线
- 角色状态变化
- 背景滚动加速

加速器是非常重要的核心爽点

### 可选扩展道具（如果不影响主流程，可以顺带实现）

- 磁铁：自动吸取附近奖励
- 弹簧鞋：下一次跳跃更高

## 十一、阶段与背景体系（最重要部分）

这是本项目的重中之重。

### 绝对关键要求

你必须实现一个连续的纵向背景系统，而不是单张静态图。

玩家向上飞时：

- 背景要相对下移
- 形成“玩家持续上升”的视觉错觉
- 不同高度要看到不同景观层级
- 每个层级之间必须过渡自然、可拼接、不卡断、不突兀

### 必须实现的 6 个层级

1. 地面城区
2. 高楼天际线
3. 高空
4. 云层
5. 平流层 / 地球边缘
6. 外太空

## 十二、背景设计硬性要求

### 1）每个层级都必须是“超长可滚动背景”

不是普通竖图，也不是宣传海报，而是游戏背景资产。

### 2）每个层级都要有“纵向延展感”

要让玩家感觉这个阶段非常长，不是一眼就过去。

### 3）每个层级之间必须连贯衔接

例如：

- 地面城区顶部 → 自然过渡到高楼区底部
- 高楼区顶部 → 自然过渡到高空区底部
- 高空区顶部 → 自然过渡到云层区底部
- 云层顶部 → 自然过渡到平流层底部
- 平流层顶部 → 自然过渡到外太空底部

不能突然换一张完全不同的背景导致割裂。

### 4）每个层级边缘必须可拼接

请把每个阶段设计成：

- 本阶段内部可连续滚动
- 本阶段底部与上一个阶段顶部可衔接
- 本阶段顶部与下一个阶段底部可衔接

### 5）要有“相对运动感”

背景不是一层死图，而要支持多层滚动：

- 远景层
- 中景层
- 近景层
- 特效层

例如：

- 地面城区：远景楼群、中景高楼、近景招牌 / 天台 / 水塔
- 云层：远景云海、中景云团、近景漂浮云与热气球
- 太空：远景星空、中景星云 / 地球边缘、近景卫星 / 小碎片

### 6）背景滚动速度要可控

- 普通上升时：稳定速度下移
- 玩家速度变快时：背景下移速度变快
- 拾取加速器时：背景明显加速下移
- 不同层级可有不同视差速度

## 十四、背景衔接实现要求（非常重要）

请在代码和资源设计上显式实现以下逻辑：

### 背景不是一张图，而是一个“高度驱动的连续背景系统”

建议实现方式之一：

- 将背景拆分为多个阶段段落
- 每个段落使用可循环滚动的超长背景
- 在高度接近阶段边界时，开始做渐进式过渡
- 通过以下手段实现平滑衔接：
- 透明度混合
- 双背景叠加过渡
- 颜色 / 雾效过渡
- 远景先切换、近景后切换
- 环境元素逐步增加或减少

### 具体要求

- 低矮建筑逐步减少
- 高楼逐步变密
- 天空面积逐步变大
- 建筑逐步远离
- 城市轮廓变成远景
- 空中交通元素增加
- 薄云逐步变厚
- 云量逐步增加
- 地面痕迹淡出
- 云层逐步下沉为下方云海
- 天空颜色逐渐变深
- 开始出现地球边缘感
- 天空蓝色转为深蓝 / 黑蓝
- 星点逐步增加
- 卫星 / 轨道元素逐步增加
- 大气发光边缘过渡到太空感

### 拼接要求

每个层级底部与相邻层级顶部必须视觉上接得上，不能跳变。要让玩家在持续飞升时，感觉背景是在自然地向下滑过，而不是突然换皮。

## 十五、背景运动要求（必须实现）

### 普通状态

- 玩家持续上升
- 摄像机跟随玩家
- 背景以设定速度向下滚动
- 各视差层速度不同

### 高度提升时

- 背景滚动不应卡顿
- 越到高处，背景元素可适度稀疏变化，但仍保持连续运动感

### 玩家拾取加速器时

这是硬性要求，必须做到：

- 角色进入高速上冲状态
- 背景整体明显加速向下滚动
- 远景、中景、近景全部加速，但速度比例不同
- 要让玩家有“真的冲上去了”的强烈视觉反馈
- 可叠加：
- 拖尾
- 速度线
- 轻微镜头拉伸 / 震动
- 背景模糊感（可选，轻量即可）

### 加速结束时

- 背景速度要平滑恢复正常
