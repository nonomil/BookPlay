## 1. 当前产品

BookPlay 当前是“离线优先的《西游记》英语学习播放器”，不是传统游戏引擎。核心体验是 108 集逐句视频学习，绘本阅读和石猴视觉小说为旁支入口。

旗舰播放器入口位于 `prj/engine/wala.html`、`wala.js`、`wala.css`，核心职责已拆成 `storage.js`、`media.js`、`study-plan.js`、`quiz.js`，包含：

- 剧情遍与精学遍；
- 逐句原片播放、字幕高亮和语速切换；
- 单词卡、复现测验、官方剧情题和 SP 积分；
- 英文、中文预生成音频；
- 进度、词汇掌握和偏好本地存储。

每集看完进入 `lesson.html?ep=N` 做一次知识巩固；每辑完成后在 `drill.html?c=cNN` 做整辑巩固，达标后解锁下一辑。

## 2. 仓库地图

| 路径 | 类型 | 职责 | Git 策略 |
| --- | --- | --- | --- |
| `prj/engine/` | 源码 | 静态 Web 播放器 | 跟踪，媒体文件除外 |
| `prj/tools/` | 源码 | 内容流水线、本地服务、校验与发布工具 | 跟踪 |
| `prj/tests/` | 测试 | Python 单元与数据合同测试 | 跟踪 |
| `scripts/` | 源码 | Capacitor Web 资源准备 | 跟踪 |
| `android/` | 源码/生成物 | Android 外壳、本机 Range 服务、数据包插件 | 跟踪源码，忽略构建产物 |
| `docs/` | 文档 | 当前说明、历史需求和实施计划 | 跟踪 Markdown，忽略嵌入媒体与 Office 文件 |
| `content/` | 生成数据 | 108 集运行时 JSON、音视频、封面、语音 | 不跟踪 |
| `data/` | 原始素材 | PDF、MP3、MP4、字幕、课件与题库 | 不跟踪 |
| `release/` | 发布产物 | APK、外置数据包、覆盖率收据 | 不跟踪 |

`prj/assets` 和 `prj/data` 是指向 `content/` 的目录联接，不是独立数据副本。

## 3. 核心链路

### 3.1 内容生产

```text
data/ 原始素材
  → prj/tools/ Python 流水线
  → content/storybooks/ 与 content/dialogue_stories/
  → content/assets/ 视频、语音、封面和角色素材
```

流水线输出必须通过 `validate_data.py` 和 `validate_storybooks.py`，但输出文件本身不进入 Git。

### 3.2 桌面运行

`启动服务.bat` 调用 `prj/tools/start_server.py`，后者选择可用端口并启动 `serve.py`。服务把：

- `/engine/` 映射到 `prj/engine/`；
- `/data/` 映射到 `content/`；
- `/assets/` 映射到 `content/assets/`；
- `/api/tts` 映射到桌面 Edge TTS 缓存。

服务必须支持 HTTP Range，否则逐句视频 seek 不可靠。

### 3.3 Android 运行

Capacitor APK 只携带播放器代码。用户选择外置数据包 ZIP 或解压目录后，`DataPackPlugin` 保存持久读取权限，`LocalRangeServer` 在 `127.0.0.1:18787` 提供与桌面近似的 URL 合同。

手机端 `/api/tts` 只读取已打包音频，不进行在线合成。因此发布前的音频覆盖校验属于发布门禁。

### 3.4 学习状态

浏览器 `localStorage` 保存以下核心状态：

- `bookplay_adv_progress`：逐集进度；
- `bookplay_adv_vocab_stat`：词汇见过、答对、答错统计；
- `bookplay_sp`：积分；
- `bookplay_read_mode`、`bookplay_pass_mode`、`bookplay_learn_level`：学习偏好；
- `bookplay_play_rate`、`bookplay_annot`：播放与标注偏好。
- `bookplay_lesson_settings_v1`：年级段与巩固强度；
- `bookplay_lesson_progress_v1`：每集知识巩固完成状态；
- `bookplay_drill`、`bookplay_drill_migrated`：每辑巩固与升级豁免状态。

当前没有账号或跨设备同步。

## 4. 当前验证基线

从仓库根目录执行：

```powershell
python -X utf8 -m pytest prj/tests -q
$nodeTests = Get-ChildItem prj/engine -Filter "*.test.mjs" -File | ForEach-Object FullName
node --test $nodeTests
python -X utf8 prj/tools/validate_data.py
python -X utf8 prj/tools/validate_storybooks.py
```

2026-08-31 基线结果：Python 143 项通过，Node 39 项通过，数据校验 0 错误/0 警告，108 集绘本通过。浏览器额外验证 EP1 与 EP108 能加载、播放器首句和设置面板正常，控制台无警告或错误。

这些检查覆盖数据和静态合同，不代表浏览器与 Android 端到端体验已经验证。

## 5. 优化路线

### P0：先让工程状态可控

1. 建立仅跟踪源码、测试、配置和文档的 Git 仓库。
2. 统一文档入口和当前路径；把早期 `demo/` 文档标记为历史记录。
3. 建立一条固定验证命令，至少覆盖现有四项检查。
4. 在修改 `wala.js` 前补最小浏览器冒烟测试：打开书架、进入一集、加载 JSON、播放/暂停、前后句、保存进度。

验收：一次提交中不存在媒体和构建产物；新环境能明确知道代码如何验证、素材如何恢复。

### P1：拆解高耦合播放器 ✅ 第一阶段完成

按行为边界逐步拆分 `wala.js`，不做一次性重写：

1. `storage.js`：存档键、读取、迁移和容错；
2. `media.js`：视频 Range seek、音频序列、TTS 回退；
3. `study-plan.js`：词卡计划、复现题、学习量策略；
4. `quiz.js`：剧情题定位、答题状态和积分；
5. `wala.js`：页面状态协调与渲染入口。

2026-08-31 已完成第一阶段：四模块均可被 Node 独立加载并由 `wala.html` 按序消费；`wala.js` 从 2011 行 / 74.6 KB 降为 1659 行 / 62.1 KB。DOM 渲染仍由 `wala.js` 编排，避免一次性重写。

验收：模块合同测试已覆盖损坏存档、旧键结构、媒体 URL/播放取消状态、三级学习计划和剧情题归位。后续只在有具体功能改动时继续细拆 DOM 渲染器。

### P1：补运行时端到端验证

增加浏览器测试，至少覆盖：

- HTTP Range 返回 206 和正确 `Content-Range`；
- 第 1、54、108 集可加载；
- 视频能 seek 到非零时间；
- 剧情遍/精学遍切换；
- 刷新后恢复节点与设置；
- 缺失可选音频时有明确回退，不阻塞下一句。

Android 增加数据包清单校验：版本、集数、必需目录、文件大小或摘要，而不是只检查 `ep1.json`。

### P2：发布与性能

1. 统一桌面和 Android 的服务行为及错误格式。
2. 为大 ZIP 的首次打开、随机 seek 和低端手机内存建立性能基线。
3. 把 APK、数据包、覆盖率清单和校验摘要做成可重复发布流程。
4. 增加存档 schema 版本与迁移，避免播放器升级破坏已有学习进度。

## 6. 暂不优化

- 不在播放器重构前更换前端框架；
- 不把 6 GiB 媒体迁入 Git 或 Git LFS；
- 不先做账号、云同步和公开发行；
- 不批量重写已经通过校验的 108 集内容；
- 不把历史计划全部改写成当前时态。

## 7. 决策规则

新改动按以下顺序判断：

1. 是否改善用户能看到或听到的真实路径；
2. 是否有自动验证能证明没有破坏播放和学习合同；
3. 是否保持媒体与源码边界；
4. 是否能小步提交和回滚；
5. 若只是增加新方案文档但不缩小真实缺口，则暂缓。
