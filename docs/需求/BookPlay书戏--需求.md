## 1. 背景与问题

### 1.1 背景

书戏Bookplay（深圳书戏科技，bookplay.com.cn）是一家以"英文原著 + 卡牌桌游"为载体的少儿英语教育品牌，约 50 家代理门店，配套「单词争霸」自学 App。其教学素材的核心形态是**角色扮演对话剧本**——学生扮演角色、读台词、推进剧情。

本项目要把这类"英文原著剧本演绎"的体验数字化：用 AI 把（公版）英文原著改编成**可交互的对话故事产品**，让学习者从"读绘本"升级为"玩故事"。

### 1.2 要解决的三个核心问题

1. **AI 生成故事失控**：直接让 LLM 自由生成故事，长度注水、剧情跑偏、人设崩坏。→ 对策：确定性 JSON 剧情骨架 + AI 只填台词（详见技术方案）。
2. **静态绘本交互性弱**：DS 交互记录指出，图文+朗读的形态接近"有声绘本"，参与感不足。→ 对策：加入分支选择、检定、收集等交互层（见 §4）。
3. **素材从哪来**：本项目按**个人使用**推进。`data/` 里已有的西游记 PDF / MP3 / 视频可以直接进工作流，不另做公版重绘。书戏门店剧本仍不复制原文（见 §3）。

## 2. 产品定位

### 2.1 一句话定位

> 用 AI 把公版英文原著变成"可玩的故事"：玩家通过对话选择推动剧情，在分支与收集中学英语。

### 2.2 产品形态：交互式对话故事（视觉小说谱系）

调研确认的技术连续谱（详见 `DS--调研资料.md` §7）：

```
有声绘本 → 交互绘本 → 视觉小说(VN) → 带数值/物品的VN → 探索解谜 → 地图移动RPG → 动作RPG
```

**本产品落在"带数值与收集的视觉小说"档位。** 理由：书戏素材本质是对话剧本（顺势）；目标用户是英语学习者（要的是参与和输入，不是操作）；AI 与现有开源生态全部集中在此区间（技术与成本可行）。

### 2.3 目标用户与场景

- **主要用户**【默认】：英语学习者（书戏学员画像：少儿—青少年）及其家长；demo 阶段先服务开发者本人自测与门店演示。
- **核心场景**：课后自学 20-40 分钟一"章"；章节末知识问答作为学习闭环；家长可回看检查点摘要了解进度。

### 2.4 差异化

Gemini Storybook 等平台能力已把"AI 图文+朗读绘本"变成标配（见 `DS--调研资料.md` §5.3）。本产品的差异化必须落在两点：

1. **分支交互**——玩家选择真正改变剧情走向（结构化对话树，非自由生成）；
2. **英语学习闭环**——点击发声、生词收集、章节问答，可与"单词争霸"理念衔接。

## 3. 内容与版权前提（约束级需求，优先于一切功能）

| # | 红线 | 说明 |
|---|---|---|
| C1 | **个人使用优先** | 本仓库按个人学习/自用推进；`data/` 现有西游记成套素材（PDF 绘本、MP3、中英字幕视频）**可以直接用于制作有声翻页绘本和学习页** |
| C2 | **不复制书戏门店剧本原文** | 书戏剧本只作玩法参考；不把门店讲义贴进产品 |
| C3 | **`data/` 西游记资产可用** | 2026-08-29 项目方确认：个人使用，版权不影响本仓库使用这些文件。流水线默认读这三套目录 |
| C4 | **分集颗粒度沿用现成 108 集** | 一集 ≈ 5 分钟、一个完整事件；第 1 集 `The Monkey` 是黄金样本 |
| C5 | **公开分发另议** | 个人使用不受限。若以后要公开或给门店用，再单独拍板，不挡当前 M0 |

**首批内容**【默认】：`data/` 第 1 集 *The Monkey*（PDF + MP3）。`demo/data/` 里那份公版石猴对话树仍可作 M1 分支实验，不再是唯一合法正文。

## 4. 功能需求

### 4.1 P0 —— 核心闭环（单场景 Demo 必须全部达成）

**核心循环**：读台词（可点击发声）→ 做选择 → 推进/分支 → 章节结束出检查点摘要。

| # | 功能 | 需求描述 | 验收标准 |
|---|---|---|---|
| F1 | 剧情数据加载 | 运行时加载 world / scene / dialogue 三层 JSON（schema 见技术方案 §3）；加载前做 schema 与引用完整性校验 | 缺字段、断链的 `next` 节点能被拒绝并报出定位；合法数据 1 秒内完成加载 |
| F2 | 对话推进与分支 | 按对话树顺序推进；每节点 0-4 个玩家选项；选项可带跳转条件；无条件出口按默认链推进 | 任一完整分支从开场走到章节末，无死路、无断链 |
| F3 | AI 台词生成 | 每节点携带 `intent`（要传达什么）+ `npc_persona_ref`（人设），GLM-5.3-Flash 只负责把 intent 转成符合人设的台词；生成结果按节点缓存 | 同一节点两次生成意图一致（人工评判）；断网/超时时回退节点内置 `fallback_text`，**骨架永远可玩** |
| F4 | 检查点摘要 | 每章结束自动生成 ≤80 字摘要（关键事件+玩家关键选择），注入下一章上下文 | 第 N 章上下文 = 世界设定 + 角色卡 + 前情摘要 + 当前场景（不含全历史对话），prompt 长度不随章节数线性增长 |
| F5 | 点击发声（TTS） | 每条台词可点击播放对应角色配音；音频按节点**预生成**并挂到 dialogue JSON | 点击当前句有高亮反馈；中英文均可发声；音频路径写入 JSON |
| F6 | 立绘与场景图 | 每角色 1 张基准立绘 + ≥2 表情变体，每场景 1 张背景图；统一 `art_style_anchor` 风格锚点 + 基准图参考法生成 | 同一角色跨场景形象一致性人工验收通过 |
| F7 | 自动存档 | 记录当前节点、已触发选择、属性值、检查点摘要；进入游戏可恢复 | 关闭页面后重开，从断点继续 |

### 4.2 P1 —— 完整章节（验证长剧情不跑偏）

| # | 功能 | 需求描述 |
|---|---|---|
| F8 | 属性检定 | 选项可带 `attribute_check`（沿用 world.json 的 观察力/胆量/社交）；检定结果决定分支走向，数值变化有即时反馈 |
| F9 | 物品收集 | 关键道具可拾取入背包；场景切换边可带 `requires_item` 门槛（对应 map.json） |
| F10 | 章节末知识问答 | 每章末 3-5 道与剧情/生词相关的选择题，答对解锁下一章；台词中的生词可点击加入生词本（衔接"单词争霸"学习闭环） |
| F11 | 表情联动 | 台词携带 `emotion` 标签，立绘自动切换对应表情变体 |

### 4.3 P2 —— 扩展交互（验证成功后再做）

| # | 功能 | 需求描述 |
|---|---|---|
| F12 | 场景热点探索 | 背景图上可点击物品/角色，触发旁白或隐藏对话 |
| F13 | 语音输入 | 用语音读出选项完成选择（STT），强化口语练习 |
| F14 | 地图可视化 | map.json 渲染成节点图，玩家点节点跳转场景，锁定的关卡可见未解锁原因 |
| F15 | 跟读与字幕 | 中英字幕开关；逐句跟读（选做评分） |

### 4.4 明确不做（Out of Scope）

- 实时移动、碰撞、动作战斗系统（与素材形态不匹配，投入产出比最低）；
- 多人联机、UGC 平台化、账号体系与商业化（M1-M3 阶段）；
- 3D 渲染、动画骨骼系统（立绘+表情变体已满足演出需求）。

## 5. 非功能需求

| # | 类别 | 需求 |
|---|---|---|
| N1 | 延迟 | 台词与音频**预生成**为主；确需运行时实时生成的，单次响应 ≤5s，超时走 fallback |
| N2 | 成本 | 单章（3-5 场景 × 约 30 对话节点）的 GLM 生成 + 生图 + TTS 总成本给出实测口径；GLM-5.3-Flash 单价约为 GLM-5.3 的 1/10，预期单章生成成本可忽略【待实测校准】 |
| N3 | 内容安全 | 目标用户含未成年人：生成 prompt 携带内容边界（无暴力恐怖、无不良用语）；每章台词人工抽检后入库 |
| N4 | 可维护性 | 全部 JSON 携带 schema 版本号；提供自动校验脚本（ZCode 生成）；素材文件路径统一写入 JSON，不硬编码 |
| N5 | 平台 | Web 浏览器优先（demo 阶段桌面 Chrome）；桌面打包（NarraLeaf 路线）留作 P2 |
| N6 | 可回溯 | 每章生成物（台词、音频、图）落盘归档，可重新生成/回滚 |

## 6. 里程碑（与技术方案路线图对齐）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M0 有声翻页** | 第 1 集 PDF 抽页 + MP3：浏览器能翻页、能听、能停在某一页 | 见 `西游记--工作流与需求对齐.md` §8 |
| **M1 单场景 Demo**（1-2 周） | 在绘本页上叠选择/生词；或继续玩 `demo/data` 石猴对话树 | F1-F7 视模式裁剪验收；绘本模式以翻页+点词+页末题为主 |
| **M2 完整章节**（2-4 周） | 扩到 3-5 个场景，加检查点摘要、属性检定、物品门槛、章节问答 | F4 在跨场景下验证"不跑偏不失忆"；F8-F11 通过；prompt 长度不随场景数膨胀 |
| **M3 完整故事 + 地图**（视规模） | 整本分场景图谱，地图可视化，批量生图建素材库 | F12-F15 按需裁剪；全流程一键重跑（素材→成品） |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| R1 公开分发越界 | 当前按个人使用；若改为公开/门店，再回头看 C5 |
| R2 AI 生成跑偏/注水 | 三重护栏：intent 确定性骨架 + fallback_text 兜底 + JSON schema 校验 |
| R3 角色形象不一致 | 基准图参考法 + art_style_anchor 风格锚点（`DS--调研资料.md` §6.1） |
| R4 范围蔓延成"真RPG" | §4.4 明确不做清单；新增玩法先对照 §2.2 谱系定位 |
| R5 TTS 英文效果不达标 | demo 期用零成本方案起步，验收不过再切 IndexTTS-2.5（多角色+情感） |

## 8. 术语表

| 术语 | 含义 |
|---|---|
| intent | 对话节点上预写的"这句话要传达什么"，AI 生成的唯一依据 |
| persona | 角色 JSON，约束台词的用词、语气、背景 |
| 检查点摘要 | 章末自动生成的 ≤80 字前情提要，替代全历史对话注入上下文 |
| 对话树 / dialogue tree | 以节点+选项构成的有向图，剧情骨架的载体 |
| 场景图 / map.json | 场景为节点、切换条件为边的有向图 |
| 公版（public domain） | 著作权已过期、可自由改编的作品 |
| VN（视觉小说） | 立绘+背景+文本框+选项推进的呈现形态 |
