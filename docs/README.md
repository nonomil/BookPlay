## 历史与规划文档

- `需求/`：早期 PRD、调研和需求对齐记录。它们解释项目为何形成，但不一定描述当前代码。
- `plans/2026-08-29-混合演出/`：混合演出与逐集拆镜方案。部分设计已被当前瓦拉播放器吸收，部分仍是未来方向。
- `plans/2026-08-29-混合演出/episodes/`：108 集的策划拆镜资料，不是播放器直接读取的数据。
- `调研/`：外部产品与技术调研。

历史文档中的 `demo/` 路径均应理解为旧结构。当前源码根为 `prj/`，生成内容根为 `content/`，原始素材根为 `data/`。

## 文档维护规则

- 当前行为以运行代码、验证脚本和本索引列出的权威文档为准。
- 新的架构决策先更新 `项目架构与优化路线.md`，再修改实现。
- 历史文档保留原始决策语境，不做大规模追溯改写；发现失效内容时在索引或文首标注。
- 命令默认从仓库根目录执行，路径统一写成 `prj/...`、`content/...`、`data/...`。
- 生成数据、音视频和图片不写入 Git 历史。
